9.3 核心模块精讲(Buffer / Stream / fs / http) ​

卷:卷九 · Node.js 与运行时 难度:⭐⭐ 进阶 | 阅读时间:30min

引言:四个绕不开的内置模块 ​

Node 后端日常就是"读文件、收请求、搬字节、回响应"。这一章把 Buffer、Stream、fs、http 四个核心模块讲到能直接用。

一、Buffer:处理二进制 ​

JS 原没有二进制类型,Buffer 补上(本质是定长数组 + 底层内存):

js
const buf = Buffer.from("你好", "utf8");
console.log(buf.length);          // 6(UTF-8 每个汉字 3 字节)
const str = buf.toString("utf8"); // 还原

3

场景:读文件、网络传输、处理图片/音视频字节。注意 buf.length 是字节数,不是字符数。

二、Stream:流式处理(性能关键) ​

为什么用流? 大文件若一次性 readFile 读进内存,可能直接爆内存。流是边读边处理,内存占用恒定。

四种流 ​

类型说明
Readable可读(读文件、收请求)
Writable可写(写文件、回响应)
Duplex双向(如 socket)
Transform边读边转换(压缩、加密)

背压(backpressure) ​

js
// 管道自动处理背压:读得快写不快时,pause 读端
readable.pipe(writable);

// 手写写流时要处理
const ok = writable.write(chunk);
if (!ok) readable.pause();          // 写不进去了,暂停读
writable.on("drain", () => readable.resume());  // 排空再继续

背压:消费慢于生产时,让生产端停下来,防止内存被数据"淹没"。pipe 帮你自动处理了它。

js
import { promises as fs } from "fs";

await fs.writeFile("b.txt", "hello");              // 写
await fs.mkdir("dir", { recursive: true });        // 建目录

四、http:创建服务器 ​

js
import http from "http";
const server = http.createServer((req, res) => {
  res.setHeader("Content-Type", "application/json");
  res.end(JSON.stringify({ ok: true, url: req.url, method: req.method }));

server.listen(3000, () => console.log("listening 3000"));

小结 ​

Buffer:二进制(字节数≠字符数)
Stream:边读边处理,内存恒定;背压=消费慢则暂停生产(pipe 自动处理)
fs:promises 异步;请求里禁用 Sync 版;大文件 createReadStream
http:createServer(req, res),底层;工程用 Express/Koa/Fastify

面试题 ​

Q1:什么是"背压"?Node 里如何应对?

背压 = 消费速度 < 生产速度时,数据在内存里堆积。应对:用 pipe(自动 pause/resume)、或手写 write() 返回 false 时 pause() + drain 时 resume()。核心是"读端听写端的,别猛灌"。

Q2:为什么大文件不推荐 readFile?

readFile 会把整个文件一次性读进内存,大文件(几 GB)直接 OOM。应改用流 createReadStream 边读边处理,内存占用恒定。

Q3:Buffer 为什么需要?它和 JS 的字符串有什么区别?

JS 字符串是 UTF-16,无法直接、高效地处理原始二进制(文件/网络字节流)。Buffer 提供定长、按字节的二进制容器,用于 I/O、编码转换、二进制协议解析。长度单位是字节,不是字符。
