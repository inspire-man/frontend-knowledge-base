7.2 Hooks 深度(useState / useEffect / 规则 / 闭包陷阱) ​

卷:卷七 · 框架核心 · React 阅读时间:30min

引言:Hooks 让函数组件"有状态" ​

Hooks 让函数组件拥有状态与副作用。深挖要懂为什么"顺序"决定生死(链表存储),以及闭包陷阱的底层。

一、为什么有 Hooks ​

类组件的 this 绑定、componentDidMount/Update/Unmount 重复逻辑都难受。Hooks 让函数组件有状态、有副作用,且能按逻辑拆分复用。

二、核心 Hooks 速览 ​

Hook用途
useState状态
useEffect副作用(请求/订阅)
useMemo / useCallback缓存计算/函数
useRef可变引用/DOM
useReducer / useContext复杂状态 / 跨层传值
jsx
const [count, setCount] = useState(0);
useEffect(() => { document.title = `${count}`; return () => {/* 清理 */}; }, [count]);
1
2

三、两条铁律 + 底层(链表存储) ​

  1. 只在顶层调用(不能在条件/循环)
  2. 只在函数组件/自定义 Hook 里调用

为什么顺序决定生死? React 用调用顺序在一条 Hook 链表 里对应每个 hook 的状态:

某次渲染跳过了某个 hook(条件里),后续 hook 的状态全部"串位"。所以必须每次渲染顺序一致。

四、闭包陷阱(底层) ​

jsx
useEffect(() => {
  const t = setInterval(() => console.log(count), 1000);
  return () => clearInterval(t);
}, []);            // count 被闭包锁死在"那次渲染的快照"
1
2
3
4

为什么? 函数组件每次渲染都是一次新的函数调用,useEffect 的闭包捕获的是当次渲染的 count 值。依赖数组 [] 表示"只在挂载时执行一次",于是永远锁在初始值。

解法:

jsx
setCount((c) => c + 1);           // ① 函数式更新:基于最新值,绕开闭包
// ② 依赖里加 count → 每次 count 变都重建 effect
// ③ useRef 存最新值
1
2
3

useState 的函数式更新(c => c+1)永远基于最新提交的值,是最稳的写法。

setState 的批处理(Batching,底层):

React 自动批处理多个 setState:同一事件/回调里的多次 setState 会合并成一次渲染。

jsx
const [a, setA] = useState(0);
const [b, setB] = useState(0);
setA(1); setB(2);   // 合并,只重渲染一次
1
2
3

为什么批处理? 避免"每次 setState 都重渲染"的浪费,把同一轮的多次更新合并、只渲染最终结果(与 Vue 的 scheduler 同理)。

  • React 18 起自动批处理扩展到 Promise/setTimeout 里(18 前只在事件内批处理)
  • 要"强制立即同步渲染"用 flushSync(慎用,破坏批处理)

五、useMemo / useCallback 何时用 ​

jsx
const v = useMemo(() => expensive(a), [a]);    // a 不变不重算
const fn = useCallback(() => doX(a), [a]);     // a 不变引用不变
1
2

别滥用:只有"计算昂贵"或"作为 memo 子组件的依赖需引用稳定"时才有意义;无脑包降低可读性,缓存本身也有开销。

六、小结 ​

Hooks:给函数组件加状态与副作用,按逻辑复用
铁律:顶层调用(链表槽按顺序对应);函数式更新防闭包陷阱
闭包陷阱:每次渲染是新的函数调用,闭包捕获当次快照
useMemo/useCallback:仅在昂贵/引用稳定需要时用

七、面试题 ​

Q1:为什么 Hooks 不能在条件语句里调用?

React 靠 hook 调用顺序(链表槽)对应每个 hook 的状态;某次渲染跳过某 hook,顺序错位、后续状态全"串"。必须每次顺序一致。

Q2:useEffect 依赖数组为空/有值/不传分别代表什么?

空 []:挂载跑一次(卸载 cleanup);[a]:a 变时跑;不传:每次渲染都跑。是"何时执行/清理"的开关。

Q3:解释"闭包陷阱",并给出解法?

effect 闭包捕获的是当次渲染的旧值,若依赖数组写空,则永远读旧值。解法:① 函数式更新 setCount(c=>c+1);② 依赖数组加 count;③ useRef 存最新值。

Q4:useState 的函数式更新 (c)=>c+1 有什么好处?

它基于最新提交的值计算,不依赖闭包里的旧值,即使回调被闭包"锁住"也能正确累加。适合依赖旧值更新、且不想在依赖数组里加值的场景。

Q5:useEffect 的 cleanup 什么时候执行?

依赖变化下次执行前、以及组件卸载前。用途:清定时器、移除监听、取消订阅,防止内存泄漏(呼应 2.6)。

Q6:useRef 和 useState 的区别?各自场景?

useRef 返回可变引用对象(.current),修改不触发重渲染;useState 修改触发重渲染。useRef 用于"访问 DOM、存不触发渲染的变量(如定时器 id/最新值快照)"。
