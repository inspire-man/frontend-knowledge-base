## 引言:浏览器能"自己发请求",也能"让 JS 发请求"

浏览器作为**用户代理(user agent)**,有两大能力:**自动发送请求、自动解析响应**。后来它们被开放给 JS,才有了 AJAX。本章把 XHR/Fetch/axios/SSE/WebSocket 一网打尽。

---

## 一、用户代理:自动发请求 & 自动解析

**自动发请求的场景(无需 JS):**

- 地址栏回车(GET)
- `<a>`/`<img>`/`<script>`/`<link>`/`<video>`(GET)
- 表单 `<form>` 提交(但已少用)
- `GET` 约定:**不携带请求体**(参数走 URL/头部)

**自动解析响应(按 `Content-Type` 分流):**

| `Content-Type` | 浏览器动作 |
|----------------|-----------|
| `text/html` | 渲染成页面 |
| `text/css` | 当样式 |
| `text/javascript` | 交给 JS 引擎执行 |
| `image/*` | 显示图片 |
| `application/octet-stream` / `Content-Disposition: attachment` | 触发下载 |

## 二、AJAX 的两种实现:XHR vs Fetch

> 早期浏览器没把通信能力开放给 JS,直到 IE 的 XHR 出现,2005 年正式命名 AJAX。

| | XHR | Fetch |
|---|-----|-------|
| 形态 | 事件回调 | **Promise** |
| 进度监控 | ✅ 支持 `onprogress` | ❌ 原生不支持 |
| 中止 | `abort()` | `AbortController` |
| 状态 | 已基本停更 | 现代主流 |

```js
// XHR
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api");
xhr.onload = () => console.log(xhr.responseText);
xhr.send();

// Fetch
fetch("/api")
  .then((r) => r.json())
  .then((data) => console.log(data));
```

**Fetch 的"promise 完成时机"(关键,易错):**

> `fetch()` 返回的 promise 在**收到响应头**时就 resolve 了,此时 **body 还没完全传输**。要看数据,还得再 `await r.json()` / `r.text()` 读取响应体——它是**流式**的。

```js
const r = await fetch("/api");  // 这里只拿到了响应头
const data = await r.json();    // 这里才真正读完响应体
```

## 三、axios:基于 XHR 的封装

axios 是第三方库,**底层基于 XHR**(Node 环境用 http),在 XHR 之上加了实用能力:

- **拦截器**:请求/响应统一加 token、统一错误处理
- **自动 JSON 转换**、超时、取消(`CancelToken`/`AbortController`)
- **并发**:`Promise.all` 语义封装

> 对比记忆:想用"原生、Promise 化、轻量"选 fetch;想要"拦截器 + 统一配置 + 进度/上传便利"选 axios。基于 fetch 的第三方有 umi-request/ky 等。

## 四、服务器推送:SSE vs WebSocket

| | SSE | WebSocket |
|---|-----|-----------|
| 方向 | 单向(服务器→客户端) | **双向** |
| 协议 | 基于 HTTP(`text/event-stream`) | 独立协议(ws/wss,先 HTTP 升级) |
| 实现 | 简单,原生 `EventSource` | 需额外库/手写 |
| 场景 | 通知、行情、实时榜单 | 聊天、协作、游戏 |

```js
// SSE:服务器持续推送,客户端只读
const es = new EventSource("/events");
es.onmessage = (e) => console.log(e.data);

// WebSocket:双向
const ws = new WebSocket("wss://example.com");
ws.onopen = () => ws.send("hello");
ws.onmessage = (e) => console.log(e.data);
```

## 五、上传二进制文件(两种方式)

```js
// ① multipart/form-data,FormData 自动处理
const fd = new FormData();
fd.append("file", fileInput.files[0]);
fetch("/upload", { method: "POST", body: fd });

// ② 二进制读取
const reader = new FileReader();
reader.readAsArrayBuffer(file);
reader.onload = () => fetch("/upload", { method: "POST", body: reader.result });
```

## 六、小结

```
用户代理:自动发请求(a/img/link/form)、自动解析响应(按 Content-Type)

XHR(事件/可监控进度)vs Fetch(Promise/流式,收到头即 resolve)
axios = 基于 XHR 封装(拦截器/取消/统一配置)
推送:SSE(单向,EventSource)/ WebSocket(双向,ws 协议)
```

## 七、面试题

**Q1:`fetch` 的 promise 什么时候 resolve?body 什么时候能拿到?**

`fetch` 在**收到响应头**时 resolve(此时 `response.body` 还是空流),需再调 `response.json()/text()` 等**读完响应体**才能拿到数据。原因是响应体是**流式传输**,不是一次性到齐。

**Q2:账号 token 放 header 统一注入,用 axios 怎么做?**

用 **axios 拦截器**:

```js
axios.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

**Q3:实时聊天用什么?为什么不用轮询/SSE?**

用 **WebSocket**:聊天是**双向、低延迟、高频**通信,轮询浪费请求且延迟高,SSE 只能服务器→客户端单向(客户端发消息不方便)。WebSocket 全双工、一条长连接双向收发,最贴合。
