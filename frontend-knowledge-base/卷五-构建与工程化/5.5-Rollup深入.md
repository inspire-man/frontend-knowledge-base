# 5.5 Rollup 深入(树摇 / 库打包)

## 引言:为什么"库"都爱用 Rollup

webpack 擅长打**应用**,Rollup 是打 **库(SDK)** 的王牌。差别在一个词:**ESM 静态结构的极致利用(树摇)**。深挖要懂树摇的**作用域分析**、sideEffects 的边界,以及库打包的 **external**。

---

## 一、Rollup 定位

| | Rollup | webpack |
|---|--------|---------|
| 主打 | **库/SDK** | 应用 |
| 产物 | 干净(无 runtime) | 带 webpack runtime |
| 树摇 | **极强** | 强(需配置) |

> Vue、React 这些库本身就由 Rollup 打包。Vite 的生产构建内部就是 Rollup。

---

## 二、完整配置示例

```js
// rollup.config.js
import resolve from "@rollup/plugin-node-resolve";   // 解析 node_modules
import commonjs from "@rollup/plugin-commonjs";       // 让 CJS 依赖可被引入
import { terser } from "rollup-plugin-terser";        // 压缩

export default {
  input: "src/index.js",
  output: [
    { file: "dist/lib.esm.js", format: "es" },                    // ESM(可树摇)
    { file: "dist/lib.cjs.js", format: "cjs" },                   // Node require
    { file: "dist/lib.umd.js", format: "umd", name: "MyLib" },    // script 全局
  ],
  external: ["react", "react-dom"],   // 关键:依赖不打进产物
  plugins: [resolve(), commonjs(), terser()],
};
```

---

## 三、external:库打包的关键

库打包时,**依赖(react/lodash 等)不应打进产物**——否则体积爆炸、且使用方会重复打包一份。用 `external` 把它们排除,只在产物里留 `import react from "react"` 让使用方解析:

```js
external: ["react", "react-dom"],
```

> 对比:**应用**打包(webpack)把依赖打进 bundle(自包含);**库**打包(Rollup)用 `external` 排除依赖(交给使用方)。这是"打库 vs 打应用"的核心差异。

---

## 四、Tree Shaking 的极致

```js
// lib.js
export const add = (a, b) => a + b;
export const sub = (a, b) => a - b;   // 没人用 → 被摇掉
// main.js
import { add } from "./lib";
```

**底层:作用域分析(scope analysis)** —— Rollup 对 ESM 做**静态作用域分析**:

1. 把每个模块解析成 AST,建立**模块依赖图**
2. 追踪每个导出**被谁引用了**
3. 把**没被引用**的导出连同其代码**直接从产物剔除**

这是"树摇"的字面含义:把依赖树上"死掉"的枝桠摇下来。因为是**编译期静态分析**,所以能精确、无损。

---

## 五、sideEffects 边界

```js
// package.json
{ "sideEffects": false }   // 或 ["*.css", "*.scss"]
```

- 标记 `false` → 告诉打包器"可安全摇掉未使用的导出"
- 若模块有**副作用**(`import './polyfill'` 自动执行),必须排除,否则被误删

```js
// 错误:全局注册的副作用被 tree-shake 误删
import "./register-globals";   // 若 sideEffects:false,可能被删!
```

> 这是"为什么设 sideEffects 要谨慎"的根源:标记错了,副作用被删,运行时报错。

---

## 六、产物形态(库的关键)

```js
output: [
  { file: "dist/lib.esm.js", format: "es" },                        // 现代打包器可摇
  { file: "dist/lib.cjs.js", format: "cjs" },                       // Node require
  { file: "dist/lib.umd.js", format: "umd", name: "MyLib" },        // script 全局
];
```

配合 package.json 的 `exports` 条件分发(见 [9.4](/卷九-Node.js与运行时/9.4-包与发布)):

```json
{
  "main": "dist/lib.cjs.js",
  "module": "dist/lib.esm.js",
  "exports": {
    ".": {
      "import": "./dist/lib.esm.js",
      "require": "./dist/lib.cjs.js"
    }
  }
}
```

---

## 七、小结

```
Rollup = 库打包之王;ESM 静态结构 → 作用域分析 → 极致树摇
external:库打包排除依赖(交给使用方);应用打包才内联依赖
sideEffects:false 可安全摇,但副作用模块须排除
产物:es/cjs/umd 多格式 + exports 条件分发;Vite 生产构建 = Rollup
```

## 八、面试题

**Q1:为什么"打包库"选 Rollup 而非 webpack?**

Rollup 基于 ESM 静态结构做**极致树摇**,产物**纯净**(无 runtime)、多格式输出(es/cjs/umd),最贴库"小而净、多环境分发";webpack 强在应用场景,打库带 runtime 冗余。

**Q2:`dist/lib.esm.js` 和 `dist/lib.cjs.js` 分别给谁用?**

`esm` 给现代打包器(Vite/webpack)继续树摇;`cjs` 给 Node(require);`umd` 给浏览器 script 全局。

**Q3:什么是"副作用(side effects)",和 Tree Shaking 什么关系?**

模块"导入即产生效果"(如 `import './polyfill'` 自动执行)叫副作用。树摇会删"看似没用"的代码,若 `sideEffects:false` 标错,副作用模块会被误删。正确声明才能"摇得干净又不误删"。

**Q4:Rollup 的树摇为什么比 webpack 更"极致"?**

Rollup 是**原生面向 ESM**、以静态作用域分析为核心,树摇是其第一设计目标;webpack 早期面向 CJS(动态 require),树摇是后加的、受限于动态性。所以打库 Rollup 更干净。

**Q5:Vite 和 Rollup 是什么关系?**

Vite 的**生产构建内部就是 Rollup**,`vite build` 用 Rollup 打包,`rollupOptions` 可透传定制。所以"Vite 生产产物的质量 = Rollup 的质量"。

**Q6:库要同时支持 ESM 和 CJS,产物怎么配?**

用 Rollup 输出**多格式**:`es`(ESM)+ `cjs`(CJS)+ 可选 `umd`;再在 package.json 用 `exports` 的 `import/require` 条件分发(见 [9.4](/卷九-Node.js与运行时/9.4-包与发布)),让两种消费方各取所需。

**Q7:库打包为什么用 `external`,而不是把依赖打进去?**

依赖(react/lodash)打进产物会**体积爆炸**、且使用方会**重复打包一份**(版本还可能冲突)。`external` 把依赖排除,产物里只留 `import`,交给使用方解析——这是"打库 vs 打应用"的核心差异。

**Q8:Rollup 的树摇底层靠什么实现?**

靠 **ESM 静态结构 + 作用域分析**:把模块解析成 AST、建依赖图、追踪"导出→使用"关系,把**没被引用的导出**连同代码精确剔除。因为是编译期静态分析,所以无损、精确。
