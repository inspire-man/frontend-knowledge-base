---

## 引言:为什么"库"都爱用 Rollup

如果 webpack 擅长打**应用**,Rollup 就是打 **库(SDK)** 的王牌。差别就在一个词:**ESM 静态结构的极致利用(树摇)**。

---

## 一、Rollup 的核心定位

| | Rollup | webpack |
|---|--------|---------|
| 主打 | **库 / SDK 打包** | **应用打包** |
| 产物形态 | ESM / UMD / CJS 干净输出 | 运行时依赖 webpack runtime |
| 树摇 | **极强**(静态优先) | 强(需配置) |
| 非 JS 资源 | 靠插件,相对精简 | 内置丰富 |

> 一句话:**应用上 webpack/Vite,库上 Rollup**。Vue、React 这些库本身就用 Rollup 打包(所以你 `npm i vue` 拿到的是 Rollup 产物)。

---

## 二、Tree Shaking 的极致

Rollup 把 ESM 当一等公民,编译期就能画出精确的模块依赖图,**没用到的导出直接不纳入产物**:

```js
// lib.js
export const add = (a, b) => a + b;
export const sub = (a, b) => a - b;   // 没人用 → 被摇掉

// main.js
import { add } from './lib';
```

产物只保留 `add`,`sub` 从最终代码里消失。这就是"树摇":把依赖树里"死掉"的枝桠摇下来。

---

## 三、产物形态(库打包的关键)

一个库要能被各种环境用,通常同时输出多种格式:

```js
export default {
  input: 'src/index.js',
  output: [
    { file: 'dist/lib.esm.js', format: 'es' },   // 现代打包器可树摇
    { file: 'dist/lib.cjs.js', format: 'cjs' },  // Node require
    { file: 'dist/lib.umd.js', format: 'umd', name: 'MyLib' }, // 浏览器 script 全局
  ],
};
```

> `es` 格式给 Vite/webpack 摇;`cjs` 给 Node;`umd` 给 `<script>` 直接引入。三者齐全,库才好用。

---

## 四、Rollup 与 Vite 的关系(承上启下)

Vite 的生产构建就是 **基于 Rollup**:

- `vite build` 内部用 Rollup 打包
- `rollupOptions` 可直接透传 Rollup 配置做进阶定制(分包、external)

> 所以你写 Vite 项目,本质上在享受"Rollup 的产物质量 + esbuild 的开发速度"。

---

## 五、小结

```
Rollup = 库打包之王
核心:ESM 静态结构 → 极致树摇(死代码直接消掉)
产物:多格式输出(es/cjs/umd)适配各环境
与 Vite:Vite 生产构建 = Rollup(rollupOptions 可定制)
```

## 六、面试题

**Q1:为什么"打包库"普遍选 Rollup 而非 webpack?**

Rollup 基于 ESM 静态结构做**极致树摇**,产物**纯净**(不塞 webpack runtime)、支持多格式输出(es/cjs/umd),最贴合库的"小而净、多环境分发"需求。webpack 强在应用场景(资源处理、HMR、生态),打库会带 runtime 冗余。

**Q2:`dist/lib.esm.js` 和 `dist/lib.cjs.js` 分别给谁用?**

`esm` 给**现代打包器(Vite/webpack)**用,可继续树摇;`cjs` 给 **Node(require)** 用;`umd` 给浏览器 `<script>` 直接引入挂全局。三者覆盖不同消费环境。

**Q3:什么是"副作用(side effects)",和 Tree Shaking 什么关系?**

模块里"导入即产生效果"(如 `import './polyfill.js'` 自动执行某些代码)叫副作用。树摇会删掉"看似没用"的代码,若标记不当可能误删副作用模块。正确声明 `sideEffects: false`(或精确指定),告诉打包器"可安全摇",才能既摇得干净又不误删。
