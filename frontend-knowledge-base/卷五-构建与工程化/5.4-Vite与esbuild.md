## 引言:Vite 为什么"一启动就能开发"

webpack 的思路是"先把所有模块打包,再启动服务器"——项目越大启动越慢。Vite 反其道而行:**开发期不打包**,靠浏览器原生 ESM + 按需编译,快得惊人。

---

## 一、Vite 的双引擎:开发用 esbuild,构建用 Rollup

```mermaid
flowchart TB
    subgraph 开发 dev
    A[请求模块] --> B[native ESM 直接加载]
    B --> C{浏览器请求某个模块}
    C -->|按需| D[esbuild 瞬编译该模块返回]
    end
    subgraph 构建 build
    E[全量依赖分析] --> F[Rollup 打包]
    F --> G[产物 + 树摇 + 分包]
    end
```

| 阶段 | 引擎 | 为什么 |
|------|------|--------|
| **开发** | esbuild(预构建)+ 原生 ESM | 快,不打包,按需 |
| **构建** | **Rollup** | 树摇好、产物干净、适合产线 |

---

## 二、三个关键机制

### 1. 依赖预构建(预打包)

`node_modules` 里的库(CJS 格式、几十上百个文件)如果按原生 ESM 逐个请求会爆炸。Vite 启动时用 **esbuild 预构建**:

- 把 CJS 转 ESM
- 把分散小文件**合并成单个**依赖(如 `lodash-es` 几百个模块 → 一个)

```bash
✓ 预构建依赖:vue, axios, lodash-es  # 启动日志里的那行
```

### 2. 按需编译 + 秒级 HMR

- 浏览器**请求到哪个文件**,esbuild 才现编译哪个(不碰没访问的模块)
- HMR:改哪个文件,只**失效那一条链**,毫秒级替换,**状态不丢**

### 3. 构建时走 Rollup

生产构建追求**最优产物**(树摇、分包、兼容),用 Rollup 更稳——esbuild 虽快但"产物极致优化"不如 Rollup 成熟。

---

## 三、为什么 esbuild 这么快

(呼应 5.2):esbuild 用 **Go** 实现,编译为原生机器码、内部并行、复用 AST、不引导 JS 运行时,所以比 JS 写的打包/转译器快 1~2 个数量级。

---

## 四、Vite vs webpack:一张表选型

| | Vite | webpack |
|---|------|---------|
| 开发启动 | **秒级**(不打包) | 秒到分钟(全量打包) |
| HMR | 极快(按需失效) | 较慢(随项目变大) |
| 构建引擎 | esbuild(dev)+ Rollup(build) | 自研 tapable 体系 |
| 生态/插件 | 快速成长,基于 Rollup 生态 | **最全最成熟** |
| 适用 | 新项目、现代浏览器、SDK/库 | 复杂/老项目、深度定制、兼容性要求高 |

> 趋势:新项目默认 Vite;存量复杂项目继续 webpack;底层 Rust 重写的 Rolldown 正在成为 Vite 未来的构建内核(见 5.6)。

---

## 五、小结

```
Vite 双引擎:dev 用 esbuild(预构建 + 不打包 + 按需编译),build 用 Rollup

三机制:依赖预构建(CJS→ESM,合并小模块)/ 按需编译 + 秒级 HMR / 构建走 Rollup
对比:Vite 开发快、适合新项目;webpack 生态全、适合复杂/存量项目
```

## 六、面试题

**Q1:Vite 为什么开发环境"几乎秒开",webpack 却越来越慢?**

Vite 开发期**不打包**:用浏览器原生 ESM,请求到哪个模块才用 esbuild 现编译哪个(按需);webpack 要先把**所有模块打成一个(或几个)包**再启动,项目越大、模块越多越慢。这是"按需 vs 全量"的差异。

**Q2:Vite 的"依赖预构建"解决什么问题?**

`node_modules` 里的第三方库常是 CJS、且拆成海量小文件。预构建用 esbuild 把它们① **CJS 转 ESM**、② **合并成大模块**,避免浏览器发起成千上万个请求,兼顾"不打包"与"加载效率"。

**Q3:为什么 Vite 开发用 esbuild、构建却用 Rollup?**

esbuild 快,但作为构建器**产物极致优化**(精细的 tree-shaking、分包控制、兼容处理)不如 Rollup 成熟稳定;生产构建要的是"最优产物"而非"最快构建",所以分工:开发求快用 esbuild,构建求优用 Rollup。
