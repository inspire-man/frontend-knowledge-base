# 8.4 工程实践(tsconfig / 声明文件 / satisfies / 收窄)

## 引言:类型写对了,还要"工程接对了"

TS 一半功夫在写类型,另一半在**配置与工程落地**:tsconfig 怎么配、声明文件怎么写、和打包器怎么协同。这一章补上这些"落到项目里"的事。

---

## 一、tsconfig 关键项

```json
{
  "compilerOptions": {
    "target": "ES2020",            // 编译目标 JS 版本
    "module": "ESNext",            // 模块系统(配合打包器常用 ESNext)
    "moduleResolution": "bundler", // 模块解析策略(Vite 场景)
    "strict": true,                // ⭐ 开启全部严格检查
    "skipLibCheck": true,          // 跳过 .d.ts 检查(提速)
    "noUncheckedIndexedAccess": true,  // 索引访问可能 undefined(更严)
    "baseUrl": ".", "paths": { "@/*": ["src/*"] }  // 路径别名
  }
}
```

**`strict` 是一组开关的总开关**,关键子项:

| 子项 | 作用 |
|------|------|
| `strictNullChecks` | `null/undefined` 独立于其他类型(最重要的严格项) |
| `noImplicitAny` | 禁止隐式 any |
| `strictFunctionTypes` | 函数参数逆变检查 |

> 新项目**务必开 `strict`**;老项目渐进开启,先 `strictNullChecks`。

## 二、声明文件(.d.ts)

声明文件用来"给 JS 库补类型"或"暴露公共类型":

```ts
// global.d.ts
declare module "*.css";                     // 声明星号模块
interface Window { myVar: string; }         // 扩展全局

// 给无类型的第三方库声明
declare module "some-lib" {
  export function doThing(x: number): string;
}
```

- `declare`:声明存在但不在此定义
- 类型包 `@types/*`:社区维护的第三方声明

## 三、`satisfies` 与 `as const`

### 1. `as const`(字面量收窄 + 只读)

```ts
const routes = { home: "/home", user: "/user" } as const;
// 类型变成 { readonly home: "/home"; readonly user: "/user" }
```

### 2. `satisfies`(校验但不改变推断)

```ts
const palette = { red: "#f00", green: "#0f0" } satisfies Record<string, string>;
// 既校验了"值都是 string",又保留了字面量推断 red: "#f00"(而非宽化成 string)
```

> `satisfies` vs 类型注解:`as const` 让字面量变只读精确;`satisfies` **边校验边保留精确推断**,双向都不丢。

## 四、tsc 编译 vs esbuild/SWC

| | `tsc` | esbuild / SWC |
|---|-------|---------------|
| 类型检查 | ✅ 完整 | ❌ **只转译,不查类型** |
| 速度 | 慢 | **极快** |
| 用途 | 类型检查 + 构建 | 开发提速 + 构建 |

> **关键认知:esbuild/SWC 只"擦掉类型",不"检查类型"。** 所以现代脚手架(Vite)用 esbuild 转译提速,但**类型检查仍要单独跑 `tsc --noEmit`**(放进 CI/typecheck 脚本)。

```json
// package.json
{ "scripts": { "typecheck": "tsc --noEmit" } }   // 只检查不产出
```

## 五、小结

```
tsconfig:strict 必开(尤其 strictNullChecks);moduleResolution 按工具选 bundler
声明文件 .d.ts:declare 全局 / 模块补类型
as const:字面量只读精确;satisfies:校验但不丢推断
esbuild/SWC 只擦类型不检查 → typecheck 单独 tsc --noEmit
```

## 六、面试题

**Q1:`satisfies` 和类型注解 `: T` 有什么区别?**

类型注解 `: T` 会把变量类型**宽化成 T**(丢失字面量/更窄的推断);`satisfies` 只做**校验**,保留变量的**精确推断类型**。所以想要"既检查又保留精确类型"用 `satisfies`。

**Q2:为什么 Vite(esbuild)构建很快,却没做类型检查?**

esbuild/SWC 只做**语法转译**(把 TS 语法剥掉产出 JS),**不做类型语义检查**——这是它快的主因之一。因此类型安全要靠 `tsc --noEmit` 单独跑(常放 CI 或 `typecheck` 脚本),实现"转译快 + 类型仍严格"分离。

**Q3:`strictNullChecks` 为什么重要?关掉有什么后果?**

开启后 `null`/`undefined` 是**独立类型**,不能随意赋给 string/number,强制你处理"可能为空"的情况,避免大量运行时 `Cannot read xx of undefined`。关掉则所有类型隐式包含 null/undefined,等于埋下一堆空指针隐患。
