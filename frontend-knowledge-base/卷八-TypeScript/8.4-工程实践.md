## 引言:类型写对了,还要"工程接对了"

TS 一半在写类型,一半在**配置与工程落地**。深挖要懂 **esbuild 只转译不查类型** 的分离,以及 `satisfies` 的"校验不丢推断"。

---

## 一、tsconfig 关键项

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,                       // 总开关
    "noUncheckedIndexedAccess": true,     // 索引访问可能 undefined
    "baseUrl": ".", "paths": { "@/*": ["src/*"] }
  }
}
```

**strict 关键子项:**

| 子项 | 作用 |
|------|------|
| `strictNullChecks` | null/undefined 独立(**最重要**) |
| `noImplicitAny` | 禁隐式 any |
| `strictFunctionTypes` | 函数参数逆变检查 |

> 新项目**务必开 strict**;老项目渐进,先 `strictNullChecks`。

## 二、声明文件(.d.ts)

```ts
declare module "*.css";                 // 声明模块
interface Window { myVar: string; }     // 扩展全局
declare module "some-lib" { export function d(x: number): string; }  // 给无类型库补
```

---

## 三、satisfies 与 as const

```ts
const routes = { home: "/home" } as const;   // 字面量只读精确
const p = { red: "#f00" } satisfies Record<string, string>;  // 校验但不丢推断
```

**satisfies vs 类型注解(底层):** 注解 `: T` 会把变量**宽化成 T**(丢字面量推断);`satisfies` 只**校验**,保留**精确推断**。要"既检查又保留精确"用 satisfies。

---

## 四、tsc 编译 vs esbuild/SWC

| | `tsc` | esbuild/SWC |
|---|-------|-------------|
| 类型检查 | ✅ 完整 | ❌ **只转译不查** |
| 速度 | 慢 | **极快** |

```json
{ "scripts": { "typecheck": "tsc --noEmit" } }   // 只查不产出
```

> **关键认知:esbuild/SWC 只"擦掉类型",不"检查类型"。** 现代脚手架用 esbuild 转译提速,类型检查仍要单独 `tsc --noEmit`(放 CI/typecheck)——"转译快 + 类型仍严格"分离。

## 六、面试题

**Q1:satisfies 和类型注解 `: T` 的区别?**

注解把变量**宽化成 T**(丢字面量/窄推断);`satisfies` 只**校验**、保留**精确推断**。要"既检查又保留精确"用 satisfies。

**Q2:为什么 Vite(esbuild)构建很快,却没做类型检查?**

esbuild/SWC 只做**语法转译**(剥类型),**不做类型语义检查**;类型安全靠 `tsc --noEmit` 单独跑(CI/typecheck),实现"转译快 + 类型严格"分离。

**Q3:strictNullChecks 为什么重要?关掉有什么后果?**

开启后 null/undefined 是**独立类型**,强制处理"可能为空",避免大量 `Cannot read xx of undefined`;关掉则所有类型隐式含 null/undefined,埋空指针隐患。

**Q4:`.d.ts` 声明文件的作用?**

给"无类型的 JS 库"补类型、暴露公共类型、扩展全局(Window 等)。让第三方 JS 也能获得类型提示与检查。

**Q5:`as const` 的作用?**

把值收窄成**字面量 + 只读**类型(如 `"/home"` 而非 `string`),用于"枚举常量、路由表"等需精确字面量的场景。

**Q6:`target` 和 `module` 分别控制什么?**

`target`:输出 JS 的**语法版本**(ES5/ES2020);`module`:输出**模块系统**(ESNext/CommonJS)。两者独立,常见 `target:ES2020 + module:ESNext` 交给打包器处理。
