# 8.3 类型体操

> 卷:卷八 · TypeScript
> 难度:⭐⭐⭐ 专家 | 阅读时间:25min

---

## 引言:类型不只是"标注",还能"编程"

类型体操(Type Gymnastics)就是用**递归 + 条件 + 映射 + infer**在类型层面写算法。它实战意义有二:① 内置工具类型其实都是这么写的;② 复杂库(如框架 API)靠它提供丝滑的类型推断。

---

## 一、递归类型

```ts
// DeepPartial:把嵌套对象的所有层级都变可选
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

// 数组转元组(Reverse)
type Reverse<T extends any[]> =
  T extends [infer F, ...infer R] ? [...Reverse<R>, F] : [];
type R = Reverse<[1, 2, 3]>;  // [3, 2, 1]
```

> 递归的边界:`extends` 空数组/never 作为终止条件。

---

## 二、几个经典手写

```ts
// Includes:判断数组是否包含某类型
type Includes<T extends any[], U> = U extends T[number] ? true : false;

// Push / Unshift
type Push<T extends any[], U> = [...T, U];

// 字符串 length
type LengthOfString<S extends string, A extends any[] = []> =
  S extends `${infer F}${infer R}` ? LengthOfString<R, [...A, F]> : A["length"];
```

---

## 三、内置工具类型的"源码"长这样

```ts
type Partial<T> = { [K in keyof T]?: T[K] };
type Required<T> = { [K in keyof T]-?: T[K] };
type Readonly<T> = { readonly [K in keyof T]: T[K] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Exclude<T, U> = T extends U ? never : T;
type Extract<T, U> = T extends U ? T : never;
type NonNullable<T> = T extends null | undefined ? never : T;
type ReturnType<T extends (...a: any) => any> = T extends (...a: any) => infer R ? R : any;
```

> 看懂这 8 个,就掌握了类型编程 90% 的基本功:`映射` + `条件` + `infer` + `keyof`。

---

## 四、工程里什么时候值得写"体操"

| 场景 | 例子 |
|------|------|
| 精确推断 | 路由参数、表单值、请求响应的**联动类型** |
| 约束 | 限制字符串为特定格式(模板字面量) |
| 派生 | 根据一个类型自动推出一组类型(如 `Config` → `ConfigOptions`) |
| 库 API | 让使用者获得自动补全 + 类型安全 |

> **反直觉但重要的铁律:类型体操是"少而精"的。** 能靠推断就别手写;实在复杂的类型,记得**可读性 > 炫技**,必要时拆小、给别名。

---

## 五、小结

```
类型体操 = 递归 + 条件 + 映射 + infer + 模板字面量

手写:DeepPartial / Reverse / Includes / LengthOfString
内置源码:Partial/Required/Pick/Exclude/ReturnType 的 8 行套路
原则:服务于"精确推断与约束",可读性优先,少而精;进阶练 Type Challenges
```

## 六、面试题

**Q1:手写 `DeepReadonly`(多层只读)**

```ts
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
```

**Q2:如何实现"将联合类型转成元组"?并说明难点**

用 `UnionToIntersection`(联合转交叉)+ 函数参数的逆变特性推导;难点在于**联合类型的顺序无法保证**(TS 内部不保证联合成员顺序),这是 TS 类型系统的固有限制。

**Q3:`-[K]` 里的 `-` 是干什么的?**

在映射类型里 `-?` 去掉可选、`-readonly` 去掉只读(即强制必填/可变)。`Required<T>` 就是用它把 `?` 去掉。
