# 8.3 类型体操

> 卷:卷八 · TypeScript
> 阅读时间:25min

---

## 引言:类型不只"标注",还能"编程"

类型体操 = 用**递归 + 条件 + 映射 + infer** 在类型层面写算法。深挖要懂**递归的终止条件**与内置工具类型的实现。

---

## 一、递归类型

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

type Reverse<T extends any[]> =
  T extends [infer F, ...infer R] ? [...Reverse<R>, F] : [];
```

> **递归的边界**:用 `extends` 的空数组/never 作**终止条件**,否则无限递归会触发"类型实例化过深"。

---

## 二、经典手写

```ts
type Includes<T extends any[], U> = U extends T[number] ? true : false;
type Push<T extends any[], U> = [...T, U];
type LengthOfString<S extends string, A extends any[] = []> =
  S extends `${infer F}${infer R}` ? LengthOfString<R, [...A, F]> : A["length"];
```

---

## 三、内置工具类型的"源码"

```ts
type Partial<T> = { [K in keyof T]?: T[K] };
type Required<T> = { [K in keyof T]-?: T[K] };         // -? 去可选
type Readonly<T> = { readonly [K in keyof T]: T[K] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Exclude<T, U> = T extends U ? never : T;
type Extract<T, U> = T extends U ? T : never;
type NonNullable<T> = T extends null | undefined ? never : T;
type ReturnType<T extends (...a: any) => any> = T extends (...a: any) => infer R ? R : any;
```

> 看懂这 8 个 = 掌握 90% 基本功:**映射 + 条件 + infer + keyof**。

**`-?` / `-readonly`(底层):** 映射类型里的 `-` 前缀是"**去掉**"修饰符(去可选/去只读),`+` 是"加上"。`Required` 用 `-?` 把可选变必填。

---

## 四、工程里什么时候该写体操

| 场景 | 例子 |
|------|------|
| 精确推断 | 路由参数/表单/响应联动类型 |
| 约束 | 限制字符串格式(模板字面量) |
| 派生 | 一个类型派出一组(Config→Options) |

> **铁律:少而精 + 可读性优先。** 能推断就别手写;复杂类型拆小、给别名。

---

## 五、小结

```
类型体操 = 递归 + 条件 + 映射 + infer + 模板字面量
手写:DeepPartial/Reverse/Includes/LengthOfString
内置源码:8 行实现;-'?' 去修饰符
原则:服务于精确推断与约束,可读性优先,少而精
```

## 六、面试题

**Q1:手写 DeepReadonly(多层只读)**

```ts
type DeepReadonly<T> = { readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K] };
```

**Q2:如何将"联合类型转元组"?说明难点**

用 `UnionToIntersection`(联合转交叉)+ 函数参数**逆变性**推导;难点:**联合成员顺序无法保证**(TS 不保证联合顺序),是类型系统固有限制。

**Q3:`-[K]` 里的 `-` 是干什么的?**

映射类型里 `-?` 去可选、`-readonly` 去只读(强制必填/可变)。`Required<T>` 就是用它把 `?` 去掉。

**Q4:递归类型为什么要终止条件?没有会怎样?**

无终止条件会**无限递归**,触发 TS 的"类型实例化过深(Type instantiation is excessively deep)"错误。终止条件通常是 `extends 空/never` 分支。

**Q5:`UnionToIntersection` 的原理(简述)?**

利用**函数参数的逆变位置**:`T extends any ? (x: T) => void : never` 把联合拆成函数,再 `infer` 参数位置,利用"参数逆变"把联合收敛成交叉。

**Q6:类型体操写太复杂,工程上怎么平衡?**

**可读性 > 炫技**:复杂类型拆成多个**具名别名**、加注释;能用简单泛型就别上递归体操;只在"精确推断/约束"有真实收益时才写,别为炫技。
