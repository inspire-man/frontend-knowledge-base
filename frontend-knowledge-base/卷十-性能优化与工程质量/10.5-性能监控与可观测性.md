## 一、为什么需要"上线后"的监控

本地跑得快不代表用户体感好。**真实用户监控(RUM)** 收集的是用户设备上的真实数据,才能发现"环境差异导致的问题"。

## 二、Performance API

```js
// 拿到关键时间点
const timing = performance.getEntriesByType("navigation")[0];
console.log(timing.domContentLoadedEventEnd, timing.loadEventEnd);

// 打点自定义耗时
performance.mark("start");
// ...do something...
performance.mark("end");
const d = performance.measure("task", "start", "end").duration;
```

- **PerformanceObserver** 监听 LCP/CLS/INP/长任务等事件

## 三、web-vitals 库(生产打点)

```js
import { onLCP, onINP, onCLS } from "web-vitals";
onLCP((m) => report("LCP", m.value));
onINP((m) => report("INP", m.value));
onCLS((m) => report("CLS", m.value));
// 上报到监控平台
```

## 四、监控体系(可观测性三支柱)

| 支柱 | 工具 | 关注 |
|------|------|------|
| 指标 Metrics | web-vitals + 平台 | LCP/INP/CLS/错误率 |
| 日志 Logs | 结构化日志 | 定位上线问题 |
| 链路 Tracing | Sentry/OpenTelemetry | 从请求到报错的链路 |
| 错误监控 | Sentry | 报错堆栈、影响面 |

> 一句话体系:指标看趋势、日志看现场、链路看归因、错误看影响。

## 小结

```
RUM 真实用户监控 > 本地测试
Performance API / web-vitals 采样打点
可观测性:指标 + 日志 + 链路 + 错误
```

## 面试题

**Q1:为什么不能只看 Lighthouse 跑分?**

Lighthouse 是**本地/实验室环境**的合成测试,不代表真实用户(网络、设备、地域差异)。所以要用 **RUM(真实用户监控)** 采集生产环境数据,两者结合:Lighthouse 定位问题,RUM 验证真实体感。

**Q2:如何监控前端报错?**

① `window.onerror` / `unhandledrejection` 捕获;② 上报到 Sentry 等平台(含堆栈 + sourcemap 还原);③ 结合用户行为回放定位复现路径。
