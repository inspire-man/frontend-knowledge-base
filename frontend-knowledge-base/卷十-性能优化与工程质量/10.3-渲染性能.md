# 10.3 渲染性能(减少重排 / 长任务 / 首屏)

## 引言:渲染性能 = 别让主线程被占死

与卷二(2.4/2.5)强关联,这里做"工程落地"汇总。深挖要懂 **长任务(Long Task)** 的定义与拆分。

---

## 一、减少重排/重绘(原理见 [2.4](/卷二-浏览器工作原理/2.4-重排与重绘))

- 批处理读写(读写分离),避免强制同步布局
- 离线 DOM(`DocumentFragment`)/ 隐藏后改
- 动画用 `transform/opacity`,别改 `left/top/width`

```js
const h = el.offsetHeight;   // 先读
el.style.height = h + "px";  // 后写
```

---

## 二、长任务拆分(INP 的关键)

**长任务(Long Task,底层):** 单次任务 **> 50ms** 就会阻塞交互、影响 INP。拆法:

```js
// 时间切片:分批处理,穿插让出主线程
async function processChunks(items, chunkFn, size = 1000) {
  for (let i = 0; i < items.length; i += size) {
    chunkFn(items.slice(i, i + size));
    await new Promise((r) => setTimeout(r, 0));  // 让出主线程
  }
}
```

- 大数据计算丢 **Web Worker**(2.7)
- 复杂列表用**虚拟滚动**(只渲染可视区)

**为什么让出主线程能"不卡"?** 浏览器渲染/响应交互都要主线程;长任务占满主线程,渲染与点击就排队。切碎后穿插让出,浏览器有机会处理输入与渲染(呼应 [1.8](/卷一-JavaScript语言内核/1.8-深入事件循环) 事件循环)。

---

## 三、首屏渲染优化

- 减少阻塞:JS 用 `defer`/`async`;CSS 关键内联
- LCP 元素尽早、别被 JS 阻塞
- SSR/SSG 提前出内容

---

## 四、小结

```
减少重排:读写分离/离线DOM/transform动画(2.4/2.5)
长任务:>50ms 阻塞交互;时间切片/Web Worker/虚拟滚动(保 INP)
首屏:defer/async、关键内联、SSR
```

## 五、面试题

**Q1:什么场景需要"虚拟滚动"?原理?**

列表**极大**(几万条)时,一次性渲染海量 DOM 代价高。虚拟滚动**只渲染可视区少量项**,滚动时用 `translateY` + 占位高度模拟完整高度,渲染成本从 O(n) 降到 O(可视区)。

**Q2:如何定位"卡顿"是谁造成的?**

DevTools → Performance 录制 → 看**长任务(Long Task)**与火焰图,找到长占主线程的函数 → 拆分/丢 Worker/优化。**先定位再优化**。

**Q3:什么是"长任务"?为什么它影响 INP?**

**>50ms 的任务**叫长任务;它占满主线程,让用户点击/输入无法及时响应 → INP 变差。所以要拆分长任务。

**Q4:时间切片怎么"让出主线程"?为什么 `setTimeout(0)` 就行?**

把大任务切成小块,每块之间 `setTimeout(0)`/`MessageChannel` 让出,浏览器在间隙处理输入与渲染。本质:别让单个宏任务长期霸占主线程(1.8 事件循环)。

**Q5:为什么动画用 transform 而非 left(渲染性能角度)?**

`left` 触发**重排**(样式→布局→绘制→合成),占主线程;`transform` 只走**合成**(2.5),合成线程/GPU 完成,不占主线程、不掉帧。

**Q6:读写分离为什么能减少重排?**

写样式只"标脏"、合并批处理;读布局属性会**强制立即重排**。读写交替 → 每次读都打断批处理、立即重排(读 N 次重排 N 次);读写分离 → 只重排一次。
