# 10.3 渲染性能(减少重排 / 长任务 / 首屏)

## 一、减少重排/重绘(原理见 2.4)

- 批处理读写(读写分离),避免强制同步布局
- 离线 DOM(`DocumentFragment`)/ 隐藏后改
- 动画用 `transform/opacity`,别改 `left/top/width`

```js
// ❌ 读一次写一次,反复强制重排
// ✅ 先读后写
const h = el.offsetHeight;
el.style.height = h + "px";
```

## 二、长任务拆分(INP 的关键)

> 单次 > 50ms 的"长任务"会阻塞交互。拆法:

```js
// 时间切片:分批处理,穿插让出主线程
async function processChunks(items, chunkFn, size = 1000) {
  for (let i = 0; i < items.length; i += size) {
    chunkFn(items.slice(i, i + size));
    await new Promise((r) => setTimeout(r, 0));  // 让出主线程
  }
}
```

- 大数据计算丢 **Web Worker**(2.7)
- 复杂列表用**虚拟滚动**(只渲染可视区)

## 三、首屏渲染优化

- 减少阻塞:JS 用 `defer`/`async`;CSS 关键部分内联
- 首屏即关键:LCP 元素尽早、别被 JS 阻塞
- SSR/SSG 提前出内容

## 小结

```
减少重排:读写分离/离线DOM/transform动画(2.4/2.5)
长任务:时间切片/Web Worker/虚拟滚动(保 INP)
首屏:defer/async、关键内联、SSR
```

## 面试题

**Q1:什么场景需要"虚拟滚动"?原理?**

**列表数据极大**(几万条)时,一次性渲染大量 DOM 代价极高。虚拟滚动**只渲染可视区内的少量项**,滚动时用 `transform: translateY` + 占位高度模拟完整高度,把渲染成本从 O(n) 降到 O(可视区)。

**Q2:如何定位"卡顿"是谁造成的?**

用 DevTools → Performance 录制 → 看**长任务(Long Task)**与火焰图,找到长时间占主线程的函数 → 针对性拆分/丢 Worker/优化。原则:**先定位再优化**。
