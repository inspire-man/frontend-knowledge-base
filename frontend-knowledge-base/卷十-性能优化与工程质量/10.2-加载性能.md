# 10.2 加载性能(代码分割 / 懒加载 / 预加载)

> 卷:卷十 · 性能优化与工程质量
> 难度:⭐⭐ 进阶 | 阅读时间:20min

---

## 一、加载性能的本质:减少"首屏要下多少、等多久"

两个方向:**少传**(体积小)+ **早到**(关键资源优先)。

## 二、代码分割与懒加载(少传核心)

```js
// 路由级懒加载(Vue/React 通用思路)
const User = () => import("./User.vue");      // 独立 chunk,访问才加载
const User = lazy(() => import("./User"));    // React
```

- 首屏只加载当前页,其余**按需加载**
- 配合 5.3 的 `splitChunks`:公共依赖抽离、稳定缓存

## 三、预加载(早到核心)

```html
<link rel="preload" as="script" href="critical.js">  <!-- 关键资源提前拉 -->
<link rel="prefetch" href="next-page.js">            <!-- 下个页面空闲时预取 -->
<link rel="preconnect" href="https://api.example.com"> <!-- 提前建连 -->
```

| 方式 | 时机 | 用途 |
|------|------|------|
| `preload` | 立即 | 本页**必需**资源 |
| `prefetch` | 空闲 | 下页可能用到的资源 |
| `preconnect` | 尽早 | 提前 DNS/TCP/TLS 握手 |
| `dns-prefetch` | 尽早 | 只提前解析 DNS |

## 四、资源优化清单

- **代码**:压缩、tree-shaking、`contenthash` 长缓存(4.3)
- **图片**:WebP/AVIF、响应式 `srcset`、懒加载 `loading="lazy"`、压缩
- **字体**:`font-display: swap`、`preload`、子集化
- **CSS/JS 颗粒**:三方库按需引入(`import {debouir} from 'lodash-es'` 而非整包)
- **HTTP**:缓存 + CDN + 压缩(gzip/brotli)

## 小结

```
少传:代码分割/懒加载/tree-shaking/按需引入
早到:preload(必需)/prefetch(预取)/preconnect(建连)
资源:图片 WebP+lazy / 字体 swap+preload / 长缓存 contenthash
```

## 面试题

**Q1:`preload` 和 `prefetch` 的区别?**

`preload` 是**当前页面必需**的资源,**立即**高优先级拉取(如关键 JS/字体);`prefetch` 是**未来可能用**的资源,浏览器**空闲时**低优先级预取(如下一页)。一个"现在就要",一个"待会儿可能用"。

**Q2:如何做首屏优化?**

① 路由懒加载减小入口体积;② `preload` 关键资源 + CDN;③ 图片懒加载 + 压缩 + 响应式;④ 长缓存 + contenthash;⑤ SSR/SSG 提前出内容(6.6/7.7);⑥ 关键 CSS 内联,非关键延迟。
