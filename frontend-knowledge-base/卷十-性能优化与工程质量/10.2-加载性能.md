# 10.2 加载性能(代码分割 / 懒加载 / 预加载)

> 卷:卷十 · 性能优化与工程质量
> 阅读时间:20min

---

## 引言:加载性能的本质 = "少传 + 早到"

两个方向:**少传**(体积小)+ **早到**(关键资源优先)。深挖要懂 **preload/prefetch/preconnect 的优先级差异**。

---

## 一、代码分割与懒加载(少传核心)

```js
const User = () => import("./User.vue");   // Vue
const User = lazy(() => import("./User")); // React
```

- 首屏只加载当前页,其余按需;配合 5.3 `splitChunks` 抽公共依赖

---

## 二、预加载(早到核心,优先级分层)

```html
<link rel="preload" as="script" href="critical.js">
<link rel="prefetch" href="next-page.js">
<link rel="preconnect" href="https://api.example.com">
<link rel="dns-prefetch" href="//cdn.example.com">
```

| 方式 | 时机 | 优先级 |
|------|------|--------|
| `preload` | 立即 | **高**(本页必需) |
| `prefetch` | 空闲 | 低(下页可能用) |
| `preconnect` | 尽早 | 建连(TCP/TLS) |
| `dns-prefetch` | 尽早 | 只解析 DNS |

**preload vs prefetch(底层):** `preload` 是"**当前页面必需**"的资源,立即**高优先级**拉取;`prefetch` 是"未来可能用"的资源,浏览器**空闲时低优先级**预取。一个"现在就要",一个"待会儿可能用"。

---

## 三、资源优化清单

- **代码**:压缩、tree-shaking、`contenthash` 长缓存(4.3)
- **图片**:WebP/AVIF、`srcset`、`loading="lazy"`、压缩
- **字体**:`font-display: swap`、`preload`、子集化
- **依赖**:三方库按需引入(`import { debounce } from 'lodash-es'`)
- **HTTP**:缓存 + CDN(内容分发网络)+ gzip/brotli

---

## 四、小结

```
少传:代码分割/懒加载/tree-shaking/按需引入
早到:preload(必需高优先)/prefetch(预取低优先)/preconnect(建连)
资源:图片 WebP+lazy / 字体 swap+preload / 长缓存 contenthash
```

## 五、面试题

**Q1:preload 和 prefetch 的区别?**

`preload` 是**当前页必需**的资源,**立即高优先级**拉取(关键 JS/字体);`prefetch` 是**未来可能用**的资源,**空闲时低优先级**预取(下一页)。

**Q2:如何做首屏优化?**

① 路由懒加载减入口;② preload 关键资源 + CDN;③ 图片懒加载 + 压缩 + 响应式;④ 长缓存 + contenthash;⑤ SSR/SSG 提前出内容;⑥ 关键 CSS 内联,非关键延迟。

**Q3:preconnect 和 dns-prefetch 的区别?**

`preconnect` 提前完成 **DNS + TCP + TLS** 全握手;`dns-prefetch` 只提前**解析 DNS**。前者更彻底(适合确定要用的 API/字体源),后者更轻。

**Q4:为什么图片要 `loading="lazy"`?**

让**视口外的图片**不立即加载,滚到附近才加载,减少首屏请求与带宽,提升首屏速度。

**Q5:字体加载为什么推荐 `font-display: swap`?**

`swap` 让**先用系统字体渲染文本、字体加载完再切换**,避免"文字不可见期(FOIT)"——用户先看到内容,字体后替换。

**Q6:为什么说"内容哈希 + 长缓存"是加载性能的关键?**

`contenthash` 让"内容不变则文件名不变"→ 强缓存命中、零请求;内容变则新名 → 自然更新。加载性能上"能缓存就不请求"收益最大(呼应 [4.3](/卷四-网络与通信/4.3-HTTP缓存与协商))。
