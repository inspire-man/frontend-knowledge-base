# 10.4 运行时与内存(防抖节流 / 内存泄漏)

## 引言:运行时的两个敌人——"高频触发"与"内存只涨不落"

运行时性能两个典型问题:① 事件高频触发导致函数狂跑;② 内存被错误持有、只涨不落。前者用**防抖/节流**压,后者要**定位泄漏源**清。

---

## 一、防抖 debounce(停 n 秒才执行)

**场景**:搜索输入、窗口 resize、按钮防重复提交。

```js
// 普通版:连续触发,只在"停 n 秒后"执行最后一次
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);                             // 每次触发都重置计时
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 立即执行版:第一次立刻触发,之后防抖
function debounce(fn, delay, immediate = false) {
  let timer = null;
  return function (...args) {
    const callNow = immediate && !timer;             // 首次立即
    clearTimeout(timer);
    timer = setTimeout(() => { timer = null; if (!immediate) fn.apply(this, args); }, delay);
    if (callNow) fn.apply(this, args);
  };
}
```

```js
// 用法
const onSearch = debounce((kw) => fetch(`/search?q=${kw}`), 300);
input.addEventListener("input", (e) => onSearch(e.target.value));
// 用户连续输入,只在停下 300ms 后才真正发请求
```

## 二、节流 throttle(每 n 秒最多一次)

**场景**:滚动监听、鼠标移动、高频点击上报、`scroll` 吸顶。

```js
// 时间戳版:立即执行第一次,间隔内不执行(尾触发可能丢)
function throttle(fn, interval = 300) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) { last = now; fn.apply(this, args); }
  };
}

// 定时器版:延迟执行,保证最后一次也执行(首触发延迟)
function throttle(fn, interval = 300) {
  let timer = null;
  return function (...args) {
    if (timer) return;
    timer = setTimeout(() => { timer = null; fn.apply(this, args); }, interval);
  };
}

// 首尾都执行版(leading + trailing):立即第一次 + 保证最后一次
function throttle(fn, interval = 300) {
  let last = 0, timer = null;
  return function (...args) {
    const now = Date.now();
    const remaining = interval - (now - last);
    if (remaining <= 0) {
      if (timer) { clearTimeout(timer); timer = null; }
      last = now; fn.apply(this, args);
    } else if (!timer) {
      timer = setTimeout(() => { last = Date.now(); timer = null; fn.apply(this, args); }, remaining);
    }
  };
}
```

| 版本 | 首触发 | 尾触发 | 适用 |
|------|--------|--------|------|
| 时间戳版 | 立即 | 可能丢 | 要"马上有反馈" |
| 定时器版 | 延迟 | 保留 | 要"不错过最后一次" |
| 首尾都执行 | 立即 | 保留 | 两者都要 |

> 防抖"**等你消停**"(压最后一击),节流"**限频**"(压频率上限)。本质都是**闭包 + 定时器**保存状态。

## 三、内存泄漏(原理见 [2.6](/卷二-浏览器工作原理/2.6-V8引擎与内存))

**内存泄漏 = 本该回收的对象,因被错误引用而一直不回收。** 核心来源五种:

### 1. 全局变量

```js
function leak() {
  leakedGlobal = "一个大对象";   // 没加 let/const/var,误挂到 window
}
// 解法:use strict + 始终声明变量
```

### 2. 未清理的定时器 / 监听器

```js
// React:组件卸载时清理
useEffect(() => {
  const t = setInterval(() => {}, 1000);
  window.addEventListener("resize", handler);
  return () => { clearInterval(t); window.removeEventListener("resize", handler); };
}, []);   // 必须 return 清理函数!
```

### 3. 闭包长持大对象

```js
let big = new Array(1e6);
let keep = () => console.log(big.length);   // 闭包持有 big,不释放
// 用完:keep = null;
```

### 4. 游离的 DOM 引用

```js
let el = document.getElementById("x");
document.body.removeChild(el);   // 移除了 DOM,但 el 变量还引用着
// 解法:el = null; 或结束时清引用
```

### 5. 无限增长的缓存(Map)

```js
const cache = new Map();
// 每次请求都塞进 Map,永远不清 → 越攒越大
// 解法:换 WeakMap(键可被 GC)或 LRU 有限容量缓存
```

## 四、内存泄漏排查(完整步骤)

**DevTools → Memory 面板:**

1. **Performance 录制**:看堆曲线,若"**锯齿不回落**"(GC 后仍在涨)则疑似泄漏
2. **Heap Snapshot**:在嫌疑操作**前后各拍一张快照**,对比 **Delta**,看哪些对象数量异常增长
3. 点开增长对象,看它的**引用链(Retainers)**,找到"谁还在持有它"
4. **Allocation instrumentation**:录制分配,定位**持续分配**的调用栈

> 排查顺序:先确认"是不是真泄漏"(曲线只涨不落)→ 再定位"泄漏的是什么"(快照 Delta)→ 最后找"谁持有它"(Retainers 引用链)。

## 五、缓存与引用优化

```js
// WeakMap:键是弱引用,键对象无引用即被 GC,缓存自动失效
const meta = new WeakMap();
meta.set(targetObj, { hit: 1 });
// targetObj 被回收后,meta 里对应的 entry 自动消失 → 不泄漏

// 转移所有权:ArrayBuffer transfer 零拷贝(见 2.7)
const buf = new ArrayBuffer(1024);
```

## 六、小结

```
防抖:停 n 秒执行(搜索);节流:限频(滚动);本质闭包+定时器
内存泄漏:全局/定时器监听器/闭包/游离DOM/Map缓存 → 卸载时清理
排查:Performance 看曲线 → Heap Snapshot 对比 Delta → Retainers 找引用链
缓存:WeakMap 自动失效;ArrayBuffer transfer 零拷贝
```

## 七、面试题

**Q1:手写防抖 + 立即执行版?**

```js
function debounce(fn, delay, immediate = false) {
  let t;
  return (...args) => {
    const call = () => fn.apply(this, args);
    if (immediate && !t) call();
    clearTimeout(t);
    t = setTimeout(() => { t = null; if (!immediate) call(); }, delay);
  };
}
```

**Q2:哪些常见内存泄漏场景?如何避免?**

① 定时器/监听器不清理 → 卸载钩子清理;② 闭包长持大对象 → 用完置 null;③ 全局变量堆积 → 避免误挂 window;④ Map 无限增长 → 换 WeakMap/LRU。

**Q3:防抖和节流的本质区别?各自典型场景?**

防抖"停 n 秒才执行一次"(搜索、resize);节流"每 n 秒最多一次"(滚动、连点)。防抖压"频繁的最后一击",节流压"频率上限"。

**Q4:为什么 WeakMap 适合做缓存?**

键是**弱引用**,键对象无引用即被 GC,缓存自动失效、不堆积;普通 Map 强引用,键对象永不被回收 → 内存泄漏。

**Q5:如何用 DevTools 定位内存泄漏?**

① Performance 看堆曲线只涨不落;② Heap Snapshot 前后各拍一次,对比 Delta;③ 点开增长对象看 **Retainers(引用链)** 找持有者;④ Allocation instrumentation 定位持续分配调用栈。

**Q6:节流用时间戳和定时器实现的区别?**

时间戳版:立即执行第一次、间隔内不执行;定时器版:延迟执行、间隔内也保证最后一次。可结合:首尾都执行(leading + trailing)。

**Q7:什么是"游离的 DOM 引用"?怎么排查?**

JS 变量仍引用一个**已从文档移除**的 DOM 节点,导致节点(及其子树)无法被 GC。排查:Heap Snapshot 里看 **Detached DOM** 节点数量,若持续增长说明有游离引用;修复:移除后把引用变量置 null。

**Q8:闭包一定会内存泄漏吗?为什么?**

不一定。闭包只是**持有**外部变量的引用;只有当"闭包生命周期过长 + 持有大对象 + 忘记释放"时才泄漏。正常使用、用完置 null、及时清理,就没问题。
