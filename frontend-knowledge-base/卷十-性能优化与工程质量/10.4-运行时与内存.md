## 一、防抖 vs 节流

| | 防抖 debounce | 节流 throttle |
|---|---------------|---------------|
| 语义 | **停 n 秒**才执行 | **每 n 秒最多**一次 |
| 场景 | 搜索输入、resize | 滚动、按钮连点 |

```js
function debounce(fn, delay) {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), delay); };
}
function throttle(fn, interval) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= interval) { last = now; fn(...args); }
  };
}
```

> 记忆:防抖"**等你消停**",节流"**限频**"。本质都是**闭包 + 定时器**。

## 二、内存泄漏(原理见 [2.6](/卷二-浏览器工作原理/2.6-V8引擎与内存))

**常见泄漏源:** 全局变量 / 闭包长持大对象 / 未清理定时器监听器 / 游离 DOM 引用。

```js
useEffect(() => {
  const t = setInterval(() => {}, 1000);
  return () => clearInterval(t);   // ✅ 必须清理
}, []);
```

**排查(DevTools Memory):** Heap Snapshot 前后对比,看对象数量异常增长;Performance 看堆曲线"锯齿不回落"。

## 三、缓存与引用优化

- 用 `WeakMap` 做"可自动回收"的缓存(强 Map 会撑爆)
- 大数据避免深拷贝副本,尽量复用/转移

## 四、小结

```
防抖:停 n 秒执行(搜索);节流:限频(滚动);本质闭包+定时器
内存泄漏:定时器/监听器/闭包/全局 → 卸载时清理
排查:Heap Snapshot 对比
```

## 五、面试题

**Q1:手写防抖 + 立即执行版?**

```js
function debounce(fn, delay, immediate = false) {
  let t;
  return (...args) => {
    const call = () => fn.apply(this, args);
    if (immediate && !t) call();
    clearTimeout(t);
    t = setTimeout(() => { t = null; if (!immediate) call(); }, delay);
  };
}
```

**Q2:哪些常见内存泄漏场景?如何避免?**

① `setInterval`/`addEventListener` 不清理 → 卸载钩子清理;② 闭包长持大对象 → 用完置 null;③ 全局变量堆积 → 避免误挂 window;④ Map 无限增长 → 换 WeakMap/LRU。

**Q3:防抖和节流的本质区别?各自典型场景?**

防抖"**停 n 秒才执行一次**"(搜索输入、resize);节流"**每 n 秒最多一次**"(滚动、连点)。防抖压"频繁的最后一击",节流压"频率上限"。

**Q4:为什么 WeakMap 适合做缓存?**

键是**弱引用**,键对象无引用即被 GC,缓存自动失效、不堆积;普通 Map 强引用,键对象永不被回收 → 内存泄漏。

**Q5:如何用 DevTools 定位内存泄漏?**

① Performance 看堆曲线**只涨不落**;② Heap Snapshot 嫌疑操作前后各拍一次,对比 Delta 找异常增长对象与引用链;③ Allocation instrumentation 定位持续分配调用栈。

**Q6:节流用时间戳和定时器实现的区别?**

时间戳版:立即执行第一次、间隔内不执行;定时器版:延迟后执行、间隔内也保证最后一次执行。可结合:首尾都执行(leading + trailing)。
