# 7.2 Hooks 深度(useState / useEffect / 规则 / 闭包陷阱)

> 卷:卷七 · 框架核心 · React
> 难度:⭐⭐⭐ 专家 | 阅读时间:25min

---

## 一、为什么有 Hooks

之前类组件里,复用的 `this` 绑定、`componentDidMount/Update/Unmount` 里重复逻辑都很难受。Hooks 让函数组件拥有**状态与副作用**,且能**按逻辑拆分复用**。

---

## 二、核心 Hooks 速览

| Hook | 用途 |
|------|------|
| `useState` | 状态 |
| `useEffect` | 副作用(请求/订阅/日志) |
| `useMemo` | 缓存计算结果 |
| `useCallback` | 缓存函数引用 |
| `useRef` | 可变引用 / 访问 DOM |
| `useReducer` / `useContext` | 复杂状态 / 跨层传值 |

```jsx
const [count, setCount] = useState(0);
useEffect(() => {           // 依赖变化时执行副作用
  document.title = `${count}`;
  return () => {/* 清理 */};
}, [count]);                // 依赖数组:空 [] 只跑一次
```

---

## 三、Hooks 的两条铁律

1. **只在顶层调用**:不能在条件/循环里调(否则 hook 顺序错乱)
2. **只在函数组件/自定义 Hook 里调用**

> **为什么**:React 用**调用顺序**来匹配每个 hook 对应的状态(链表),顺序变了状态就"串位"。

---

## 四、闭包陷阱(最易错)

```jsx
// ❌ 定时器里读到的 count 永远是"那次渲染的快照"
useEffect(() => {
  const t = setInterval(() => console.log(count), 1000);
  return () => clearInterval(t);
}, []);          // count 被闭包锁死在初始值

// ✅ 方案1:依赖里加 count
// ✅ 方案2:用函数式更新
setCount(c => c + 1);   // 永远基于最新值
```

> `useState` 的函数式更新(`c => c + 1`)能绕开闭包旧值,是最稳的写法。

---

## 五、`useMemo` / `useCallback` 何时用

```jsx
const v = useMemo(() => expensive(a), [a]);        // a 不变则不重算
const fn = useCallback(() => doX(a), [a]);         // a 不变则函数引用不变
```

> **别滥用**:只有"**计算结果昂贵**"或"**函数被作为依赖**传给 `memo` 子组件"时才有意义,无脑包反而降低可读性。缓存本身也有开销。

---

## 六、小结

```
Hooks:给函数组件加状态与副作用,按逻辑复用
useEffect:依赖变化跑副作用,返回函数做清理
铁律:顶层调用(靠顺序匹配);函数式更新防闭包陷阱
useMemo/useCallback:仅在昂贵计算/引用稳定需要时用
```

## 七、面试题

**Q1:为什么 Hooks 不能在条件语句里调用?**

React 靠 **hook 的调用顺序**(链表)来对应每个 hook 保存的状态;一旦某次渲染跳过了某个 hook,顺序就错位,后续所有 hook 的状态都会"串"。所以必须**每次渲染顺序一致**地调用。

**Q2:`useEffect` 的依赖数组为空、有值、不传,分别代表什么?**

空 `[]`:**只在挂载时跑一次**(卸载时跑 cleanup);有值 `[a]`:`a` 变化时跑;不传:每次渲染都跑。这是"副作用何时执行、何时清理"的控制开关。
