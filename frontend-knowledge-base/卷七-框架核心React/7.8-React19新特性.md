# 7.8 React 19 新特性

> 卷:卷七 · 框架核心 · React

## 引言:Action 表单 + 编译期优化,是 React 19 的主线

React 19 两大主线:**Actions(表单/异步状态管理)** 与 **React Compiler(自动 memo 化)**。深挖要懂 Action 相比传统 onSubmit 的进步。

---

## 一、Actions 与 useActionState

```jsx
const [state, formAction, isPending] = useActionState(submit, initialState);

<form action={formAction}>
  <input name="title" />
  <button disabled={isPending}>提交</button>
</form>
```

**为什么 Action 优于传统 onSubmit?** 传统要**手管 loading/错误/重置 + 乐观更新**;Action 把这些**内置**:`action` 表单自动管理 pending(`isPending`)、支持乐观更新、衔接 Server Actions。

---

## 二、use() 与 useOptimistic

```jsx
const data = use(promise);                     // use():读 Promise/Context,不受 Hooks 规则限制
const [opt, add] = useOptimistic(list, (s, item) => [...s, item]);  // 乐观更新
```

- `use()`:能在条件/循环里"读"Promise(与 Hooks 规则不同)
- `useOptimistic`:先乐观显示,失败回滚

---

## 三、其他关键变化

| 特性 | 说明 |
|------|------|
| **ref 可作 props** | `forwardRef` 不再必需 |
| **`<Context>` 即 Provider** | `<Theme value={...}>` 免 `.Provider` |
| **React Compiler** | 自动 memo 化,免手动 useMemo/useCallback |
| **Server Components 稳定** | 见 7.7 |

---

## 四、React Compiler(底层)

> 编译器在**构建期**自动给需要的地方加 memo 化(等价自动 `useMemo`/`useCallback`),开发者**不必手动做性能优化**。从"默认手写优化"转向"**默认优化 + 按需打破**"。

---

## 五、小结

```
React 19:Actions(useActionState/表单)+ use()/useOptimistic
ref 作 props、Context 即 Provider
React Compiler:编译期自动 memo 化,免手写
```

## 六、面试题

**Q1:React 19 的 action 表单相比传统 onSubmit 有什么优势?**

内置**提交状态管理**(isPending)、支持**乐观更新**、写法更声明式,省手写 loading/错误/重置;且与 Server Actions 天然衔接。

**Q2:React Compiler 做了什么,对开发有什么影响?**

编译期**自动 memo 化**(等价自动 useMemo/useCallback),开发者不再手动做性能优化,从"默认手写"转向"默认优化 + 按需打破"。

**Q3:`use()` 相比普通 Hooks 有什么特殊?**

`use()` 用于**读取 Promise/Context**,不受"顶层调用"规则限制,可在条件/循环里用;它是 RSC 里 "await 数据" 在客户端组件里的桥接方式。

**Q4:`useOptimistic` 解决什么场景?**

**乐观更新**:先立即用预期值更新 UI(如发消息立刻上屏),服务器失败再回滚。相比"等服务器返回才更新",体感更快。

**Q5:ref 直接作 props 意味着什么?**

React 19 里 `ref` 成为**普通 prop**,子组件直接接收,不再需要 `forwardRef` 包裹。简化了"转发 ref"的样板。

**Q6:Server Components 在 React 19 的地位?**

从"实验"转为**稳定特性**,是 React 数据获取与架构的新默认方向(配合 Next.js App Router)。核心见 7.7。
