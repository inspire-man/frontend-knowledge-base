# 7.4 并发特性(useTransition / useDeferredValue / Suspense)

> 卷:卷七 · 框架核心 · React
> 阅读时间:25min

---

## 引言:并发渲染 = 渲染可中断、优先级调度

React 18 的核心:渲染可中断,让"紧急更新"优先于"耗时更新"。深挖要懂 **useTransition 的底层**(startTransition)与 Suspense 的边界。

---

## 一、四大并发 API

| API | 作用 |
|-----|------|
| `useTransition` | 标记低优先级更新,可被打断 |
| `useDeferredValue` | 延迟一个值更新,保持输入流畅 |
| `<Suspense>` | 声明式"等待加载"边界 |
| `startTransition` | 非 Hook 版(事件里标记低优先) |

```jsx
const [isPending, startTransition] = useTransition();
startTransition(() => setQuery(input));   // 搜索列为低优先,输入框即时
```

**为什么这样设计?** 同步渲染下"输入更新"和"海量列表渲染"**绑死在一起**,一卡全卡。并发渲染把更新**分级**:先渲染"可交互"部分,大数据延后,借 Fiber 的"可中断"实现。**用可预测的稍慢,换交互的即时。**

---

## 二、useDeferredValue vs useTransition(细微区别)

| | useTransition | useDeferredValue |
|---|---------------|------------------|
| 控制对象 | 标记"**这次状态更新**"为低优先 | 让"**某个值**"延迟更新 |
| 场景 | 触发更新的函数可控时 | 值来自外部(如 props/他人)时 |

```jsx
const deferredQuery = useDeferredValue(query);   // query 由输入框驱动,延迟用它的结果
```

---

## 三、Suspense:声明式等待

```jsx
<Suspense fallback={<Spinner />}>
  <Profile />          {/* 内部抛 promise,未就绪显示 fallback */}
</Suspense>
```

> 之前异步靠"loading 状态 + 条件渲染",Suspense 把它变**声明式**;配合 RSC/流式 SSR 是 React 数据加载主线(7.7)。

---

## 四、小结

```
并发渲染:可中断 + 优先级调度
useTransition:startTransition 标记低优先更新
useDeferredValue:延迟值更新,保持输入流畅
Suspense:声明式等待(fallback)
```

---

## 五、面试题

**Q1:useTransition 解决什么问题?举例?**

把**非紧急更新**(输入触发的大列表重渲)标记低优先级,让**紧急更新**(输入框本身)即时响应不被拖慢。典型:搜索框 + 大数据结果列表。

**Q2:useDeferredValue 和 useMemo 的区别?**

`useDeferredValue` 是"**延迟**某值生效"(旧值先顶,新值延后),降渲染优先级;`useMemo` 是"缓存计算结果"避免重复算。目的不同。

**Q3:并发渲染的"可中断"对用户意味着什么?**

输入/点击等**高优先**更新能插队即时响应,大数据/低优先渲染延后、不阻塞交互——页面在大更新时也不"冻住"。

**Q4:`isPending`(useTransition 返回值)有什么用?**

标记"过渡是否进行中",用于显示 loading、禁用按钮等待 UI。它来自"低优先更新尚未完成"。

**Q5:Suspense 和传统"loading 状态"的区别?**

传统要自己声明 `loading` 变量 + 条件渲染;Suspense 是**声明式边界**,组件"抛 promise"表达未就绪,f边界自动显示 fallback。更简洁、可组合、配合流式 SSR/RSC。

**Q6:什么时候用 useTransition 而不是 useDeferredValue?**

当你**能控制更新时机**(如在事件回调里 setState),用 `useTransition` 包住那次更新;当值**来自外部**(props/父组件),你只能拿到值本身,用 `useDeferredValue` 延迟消费它。
