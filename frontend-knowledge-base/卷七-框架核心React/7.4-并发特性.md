# 7.4 并发特性(useTransition / useDeferredValue / Suspense)

> 卷:卷七 · 框架核心 · React
> 难度:⭐⭐⭐ 专家 | 阅读时间:20min

---

## 一、并发渲染(Concurrent Rendering)

React 18 的核心:**渲染可中断**,让"紧急更新"优先于"耗时更新"。

| API | 作用 |
|-----|------|
| `useTransition` | 把某次更新标记为**低优先级**,可被打断 |
| `useDeferredValue` | 延迟一个值的更新,保持输入流畅 |
| `<Suspense>` | 声明式"等待加载"边界 |

```jsx
const [isPending, startTransition] = useTransition();

// 输入框保持即时响应,搜索结果作为低优先级更新
startTransition(() => setQuery(input));
```

> 场景:输入框输入要**立即**响应,而搜索结果列表渲染慢——用 `useTransition`/`useDeferredValue` 把后者降级,输入不卡。

---

## 二、Suspense:数据加载的声明式等待

```jsx
<Suspense fallback={<Spinner />}>
  <Profile />          {/* 内部抛 promise,未就绪时显示 fallback */}
</Suspense>
```

> 之前异步要靠"loading 状态 + 条件渲染",Suspense 把它变成**声明式**;配合 RSC/流式 SSR 是 React 未来数据加载的主线。

---

## 三、为什么这样设计(并发 vs 同步)

> 同步渲染下"一次更新 = 一次性渲染完",输入框更新和 1 万列表渲染**绑死在一起**,一卡全卡。并发渲染把更新**分级**:先渲染"可交互"的部分,大数据延后,借 Fiber 的"可中断"实现 —— 本质是"**用可预测的稍慢,换交互的即时**"。

---

## 小结

```
并发渲染:渲染可中断,优先级调度
useTransition:标记低优先级更新(startTransition)
useDeferredValue:延迟值更新,保持输入流畅
Suspense:声明式等待加载(fallback)
```

## 面试题

**Q1:`useTransition` 解决什么问题?举例。**

把**非紧急更新**(如输入触发的海量列表重渲染)标记为低优先级,让**紧急更新**(如输入框本身)始终即时响应不被拖慢。典型:搜索框 + 大数据结果列表。

**Q2:`useDeferredValue` 和 `useMemo` 的区别?**

`useDeferredValue` 是"**延迟**某个值生效"(旧值先顶一阵,新值延后提交),用于**降低渲染优先级**;`useMemo` 是"缓存计算结果"避免重复计算,用于**跳过昂贵计算**,两者目的不同。
