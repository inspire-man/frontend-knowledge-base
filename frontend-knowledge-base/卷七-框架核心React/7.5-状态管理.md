# 7.5 状态管理(Redux / Zustand / React Query)

> 卷:卷七 · 框架核心 · React
> 难度:⭐⭐ 进阶 | 阅读时间:20min

---

## 一、状态分三类(先想清楚再用)

| 类型 | 例子 | 工具 |
|------|------|------|
| 组件局部 | 表单、开关 | `useState` |
| 全局共享 | 用户、主题、购物车 | Redux / Zustand |
| **服务端数据** | 接口列表、详情 | **React Query / SWR** |

> 关键认知:**服务端数据不等于全局状态**。接口数据用请求缓存库(React Query)管理,别塞进 Redux——省掉大量"请求/loading/error/缓存"手写样板。

---

## 二、Redux:经典但重

```js
// slice
const counter = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: { inc: (s) => { s.value += 1; } },
});
// 组件
const value = useSelector((s) => s.counter.value);
dispatch(inc());
```

- 单向数据流:`dispatch(action) → reducer → 新 state → 组件重渲`
- 优:可预测、DevTools 强;缺:样板多、心智重

---

## 三、Zustand:极简的现代替代

```js
import { create } from "zustand";
const useStore = create((set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
}));
// 组件里
const count = useStore((s) => s.count);
```

> 无 Provider、无 action 样板,API 极小,是"全局状态"的轻量首选。

---

## 四、React Query:服务端数据专精

```js
const { data, isLoading, error } = useQuery({
  queryKey: ["todos"],       // 缓存键
  queryFn: () => fetch("/todos").then(r => r.json()),
});
```

内置:**缓存、去重、后台刷新、失败重试、分页/无限滚动、乐观更新**。用 key 区分数据。

---

## 小结

```
局部 → useState;全局 → Zustand/Redux;服务端数据 → React Query
Redux:可预测但重;Zustand:极简;React Query:请求缓存/去重/重试
```

## 面试题

**Q1:为什么服务端数据别放 Redux?**

服务端数据本质是"**带缓存的请求结果**",不是"应用全局状态"。放 Redux 要手写 loading/error/缓存/去重/失效,样板爆炸;用 React Query 直接获得缓存、去重、重试、后台刷新等开箱能力,职责更清晰。

**Q2:Zustand 相比 Redux 的差异?**

Zustand **无 Provider 包裹、无 action/reducer 样板**,`create` 一把搞定,API 极小;Redux 单向数据流严格、可预测性/DevTools 最强,但样板重。中小项目或快速迭代偏 Zustand,大型严格治理偏 Redux(或两者按需混用)。
