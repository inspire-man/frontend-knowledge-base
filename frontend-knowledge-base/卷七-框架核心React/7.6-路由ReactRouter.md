# 7.6 路由(React Router)

> 卷:卷七 · 框架核心 · React
> 阅读时间:20min

---

## 引言:SPA(Single Page Application,单页应用)的"多页面",靠路由模拟

React Router 做三件事:**路径匹配 → 渲染组件 → 管理导航**。深挖要懂 **history/hash 底层** 与 **数据路由(loader)** 的价值。

---

## 一、基本用法

```jsx
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/user/:id" element={<User />} />
    <Route path="*" element={<NotFound />} />
  </Routes>
</BrowserRouter>
```

| API | 作用 |
|-----|------|
| `useParams` | 读 `:id` |
| `useNavigate` | 编程式跳转 |
| `Link` / `NavLink` | 声明式跳转 |
| `<Outlet />` | 嵌套路由出口 |

---

## 二、两种模式(底层:同 Vue Router)

| 模式 | 底层 | 部署 |
|------|------|------|
| `BrowserRouter`(history) | History API | 需服务端 fallback |
| `HashRouter`(hash) | `hashchange` | 免配置 |

> 刷新 `/user/123` 时,history 模式下服务器找不到该路径(404),需 fallback 到 index.html;hash 的 `#` 后不发给服务器,免配。

---

## 三、数据路由(6.4+,关键)

```jsx
<Route path="/users" element={<Users />} loader={loadUsers} />
// 组件内 useLoaderData() 读 loader 结果
```

- loader **渲染前取数据**,组件渲染时数据已就绪
- 配合 `errorElement` 错误边界、`defer` 流式

**价值**:把"加载数据 → 渲染"内置,组件不再"先 loading 再取数",是 Remix 思路的前置。

---

## 四、编程式导航与传参

```jsx
const navigate = useNavigate();
navigate("/list");                       // 跳转
navigate("/user/1", { state: { from: "list" } });  // 带 state
const { from } = useLocation().state;    // 读 state
```

---

## 五、小结

```
Routes/Route 声明路由;useParams 读参;useNavigate 跳转
BrowserRouter(history,需 fallback)/ HashRouter(免配)
嵌套 <Outlet>;数据路由 loader 前置取数 + errorElement
```

## 六、面试题

**Q1:React Router 里如何做"路由懒加载"?**

```jsx
const User = lazy(() => import("./User"));
<Route path="/user" element={<Suspense fallback={<>...</>}><User /></Suspense>} />
```

**Q2:useNavigate 和 Link 的区别?**

`<Link>` **声明式**(渲染 `<a>`,适合导航);`useNavigate` **命令式**(事件/副作用里跳转,如提交后跳转)。

**Q3:数据路由的 loader 解决什么问题?**

在**渲染组件前**先取数据,组件用 `useLoaderData()` 拿到已就绪数据,省去"组件内 loading + 取数"样板,配合 errorElement 做错误边界,Remix 思路前置。

**Q4:BrowserRouter 和 HashRouter 的区别?为什么前者要服务端配置?**

BrowserRouter 用 History API,URL 干净,但刷新 `/user/1` 服务器找不到该路径(404),需 fallback 到 index.html;HashRouter 用 `#`,`#` 后不发给服务器,免配置但 URL 丑、SEO 稍差。

**Q5:嵌套路由的 `<Outlet>` 是什么?**

子路由的**渲染出口**:父路由定义 `<Outlet>` 位置,匹配到的子路由组件渲染在这里。实现"布局 + 内容"的分层。

**Q6:路由跳转时怎么"带数据过去"(非 URL 参数)?**

`navigate("/user/1", { state: {...} })` + 目标组件 `useLocation().state` 读取。适合"列表跳详情传临时数据"(刷新会丢,适合轻量状态)。
