# 7.1 核心心智模型(JSX / 状态 / 单向数据流)

## 引言:React 的三个心智 + 一个底层公式

React 的心智可以概括为:**`UI = f(state)`**。深挖要懂"声明式 vs 命令式"的本质差异,以及为什么单向数据流能赢。

---

## 一、三大心智

1. **声明式 UI**:描述"UI 应该长什么样",不是"怎么一步步改 DOM"
2. **组件化**:props 进、JSX 出
3. **状态驱动**:`UI = f(state)` —— 状态变,UI 自动重算

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

---

## 二、声明式 vs 命令式

| | 命令式 | 声明式(React) |
|---|--------|--------------|
| 观念 | 一步步告诉"怎么做"(找它→改它) | 描述"结果是什么" |
| 维护 | 自己管理"现在→目标"的状态差异 | 只关心数据,框架算差异 |

```js
// 命令式:自己管差异
el.textContent = `${count}`;   // 每次手动同步

// 声明式:描述结果
<div>{count}</div>            // count 变,React 自动同步
```

> 声明式的价值:**把"如何把 state 映射到 DOM"这件易错事交给框架**,你只关心"数据长什么样",复杂度随规模增长而不失控。

---

## 三、JSX:JS 里的 HTML 语法糖

JSX 是 `React.createElement` 的语法糖,编译后是 JS 对象:

```jsx
const el = <div id="a">hi</div>;
// ≈ createElement("div", { id: "a" }, "hi")
```

**规则**:多根节点用 `<></>`;表达式 `{}`;`class`→`className`、`for`→`htmlFor`。

---

## 四、单向数据流

```mermaid
flowchart LR
    A[父组件 state] -->|props 下传| B[子组件]
    B -->|回调上抛 onChange| A
```

数据只能**父 → 子**(props),子不能直接改父,只能通过回调上抛。

**为什么单向数据流能赢?** 状态流向**唯一、可预测、可追溯**:谁改了数据、数据往哪传都清晰。双向绑定虽省事,但多来源同时改状态时容易失控——这是 React 与 Vue 双向绑定的显式差异(React 显式、Vue 框架内隐式)。

---

## 五、列表与条件渲染

```jsx
{list.map((item) => <li key={item.id}>{item.name}</li>)}   // key 稳定唯一
{show && <div>条件渲染</div>}
```

> `key` 不能用 index(与 Vue 同理,复用错乱)。

---

## 六、小结

```
UI = f(state):状态驱动、声明式
声明式:描述结果,框架算差异;命令式:自己改 DOM
JSX → createElement 语法糖;className/htmlFor
单向数据流:props 下传 + 回调上抛,可预测可追溯
```

## 七、面试题

**Q1:React 的"声明式"和手动操作 DOM 的本质区别?**

命令式:告诉浏览器"找到它、改它",自己维护"现在→目标"差异;声明式:只描述"结果是什么",数据变 React 算差异更新。声明式把易错的 DOM 同步交给框架。

**Q2:为什么单向数据流?**

状态流向**唯一、可预测、可追溯**,便于调试维护;双向绑定多来源改状态易失控。React 选择显式单向(回调上抛),换取可预测性。

**Q3:JSX 的本质是什么?**

`React.createElement` 的**语法糖**,编译成描述 UI 的 **JS 对象**(虚拟 DOM 节点)。所以 JSX 不是模板语言,而是"用 JS 表达式描述 UI"。

**Q4:为什么 JSX 里 `class` 要写 `className`、`for` 要写 `htmlFor`?**

因为 JSX 本质是 JS,`class`/`for` 是 JS 的**保留字**,为避免冲突,React 映射成 `className`/`htmlFor` 属性名。

**Q5:为什么列表要 key,且不能用 index?**

key 用于 Diff 判断"新旧是否同一节点"、复用/移动;用 index 在列表增删时后续节点被错误复用(状态/输入串位)。需稳定唯一 id。

**Q6:组件为什么必须"纯"(给定 props 返回相同 JSX)?**

纯函数组件让渲染结果**可预测、可缓存、可并发**(Fiber 可随时中断重算)。若渲染有副作用(改外部、随机),React 复用/中断渲染就会出错。副作用要放 `useEffect`,不能放渲染体。
