# 7.1 核心心智模型(JSX / 状态 / 单向数据流)

> 卷:卷七 · 框架核心 · React
> 难度:⭐ 基础 | 阅读时间:15min

---

## 一、React 的三大心智

1. **声明式 UI**:描述"UI 应该长什么样",而不是"怎么一步步改 DOM"
2. **组件化**:一切是组件,props 进、JSX 出
3. **状态驱动渲染**:`UI = f(state)` —— 状态变,UI 自动重算

```jsx
function Counter() {
  const [count, setCount] = useState(0);   // 状态
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

---

## 二、JSX:JS 里的 HTML 语法糖

JSX 是 `React.createElement` 的语法糖,编译后变成 JS 对象:

```jsx
const el = <div id="a">hi</div>;
// 编译后 ≈ createElement("div", { id: "a" }, "hi")
```

**规则**:多根节点要包 `<></>`(Fragment);表达式用 `{}`;`class` 写 `className`、`for` 写 `htmlFor`。

---

## 三、单向数据流

数据只能从**父 → 子**(通过 props),子组件不能直接改父状态,只能通过父传下来的**回调**上抛:

```jsx
<Child value={x} onChange={(v) => setX(v)} />
```

> 单向数据流让状态流向可预测、易追踪,是 React 的根基(也是与 Vue 双向绑定的显式区别)。

---

## 四、列表与条件渲染

```jsx
{list.map((item) => <li key={item.id}>{item.name}</li>)}   // key 稳定唯一
{show && <div>条件渲染</div>}                              // && 或三元
```

> `key` 同样不能用 index(与 Vue 同理,复用错乱)。

---

## 小结

```
UI = f(state):状态驱动,声明式
JSX → createElement 语法糖;className/htmlFor 等改名
单向数据流:props 下传,回调上抛
```

## 面试题

**Q1:React 的"声明式"和你手动操作 DOM 的本质区别?**

手动改 DOM 是**命令式**(告诉浏览器"先找到它、再改它"),要自己维护"现在是什么、要变成什么";React 是**声明式**(描述"结果是什么"),数据变了 React 自己算出差异并更新,你只关心状态与最终 UI。

**Q2:为什么要单向数据流?**

让状态流向**唯一、可预测、可追溯**:谁改了数据、数据往哪传都清晰,便于调试与维护。双向绑定虽省事,但多个来源同时改状态时容易失控。
