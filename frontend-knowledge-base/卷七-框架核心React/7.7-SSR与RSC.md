# 7.7 SSR 与 RSC(Next.js / Server Components)

## 一、CSR / SSR / RSC 三个层次

| 模式 | 谁渲染 | 特点 |
|------|--------|------|
| CSR | 浏览器 | 白屏、SEO 差 |
| SSR | 服务器 | 首屏快、SEO 好(见卷六 6.6) |
| **RSC** | **组件级混合** | 细分"哪些在服务器、哪些在浏览器" |

> SSR 解决"首屏/SEO",RSC 进一步解决"**哪些代码该在服务端、哪些该在客户端**"的粒度问题(可减少发往客户端的 JS 体积)。

---

## 二、Server / Client Component 的区别

```jsx
// 默认是 Server Component(只运行在服务器)
async function Page() {
  const data = await db.query();   // 直接访问数据库/文件
  return <ClientList data={data} />;
}

// Client Component 需声明 'use client'(有交互/状态)
'use client';
function ClientList({ data }) {
  const [x, setX] = useState(0);   // 交互逻辑在浏览器
  return <ul>{data.map(...)}</ul>;
}
```

| | Server Component | Client Component |
|---|------------------|------------------|
| 运行环境 | 服务器 | 浏览器 |
| 能用 | 数据库/文件/秘密 | useState/事件/DOM |
| 体积 | 不进浏览器 | 进浏览器打包 |

---

## 三、RSC 的价值(为什么这样设计)

> 传统 SPA 把所有代码(含数据逻辑、重库)都打到浏览器。RSC 让**"只依赖服务端的部分"留在服务器**(不进 JS bundle),只有**真正需要交互的部分**发给客户端——既**减包**、又能**直连数据库/读秘密**,还天然写异步(async 组件)。

## 四、Next.js App Router 速览

```jsx
// 文件即路由:app/users/[id]/page.jsx
import { use } from "react";
export default async function UserPage({ params }) {
  const { id } = await params;         // 动态参数
  return <div>{id}</div>;
}
```

- Steam/流式 SSR:`<Suspense>` 包裹,边渲染边推送
- 数据获取:Server Component 里直接 `await fetch`

## 小结

```
CSR(浏览器)→ SSR(服务端首屏)→ RSC(组件级分工)
Server Component:服务端跑、可直连 DB、不进 bundle
Client Component:'use client',有交互
RSC 价值:减 bundle + 直连服务端 + 原生 async
```

## 面试题

**Q1:RSC(Server Component)和 SSR 的区别?**

SSR 是"**首屏 HTML 在服务器渲染**"的**渲染模式**(整页);RSC 是"**按组件划分运行环境**"的**组件模型**(哪些跑服务器、哪些跑浏览器)。二者可组合:Server Component 在服务器生成 HTML,流量化给客户端,客户端组件再 Hydration。

**Q2:什么时候一个组件要标记 `'use client'`?**

当它需要**交互或浏览器能力**:`useState`/`useEffect`/事件处理、DOM API、浏览器 Hook 时。纯展示、纯读数据、可服务端完成的组件保持 Server Component(默认)即可。
