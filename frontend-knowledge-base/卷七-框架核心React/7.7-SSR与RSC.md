# 7.7 SSR 与 RSC(Next.js / Server Components)

> 卷:卷七 · 框架核心 · React
> 阅读时间:25min

---

## 引言:CSR(客户端渲染)/ SSR(服务端渲染)/ RSC(React Server Components,服务端组件)三个层次

CSR 白屏、SEO 差;SSR 首屏快;RSC 进一步解决"哪些代码在服务端、哪些在客户端"的粒度。深挖要懂 **RSC 与 SSR 的本质区别**。

---

## 一、三个层次

| 模式 | 谁渲染 | 特点 |
|------|--------|------|
| CSR | 浏览器 | 白屏、SEO 差 |
| SSR | 服务器 | 首屏快、SEO 好 |
| **RSC** | **组件级混合** | 细分服务端/客户端组件 |

---

## 二、Server / Client Component

```jsx
// 默认 Server Component(只在服务器跑)
async function Page() {
  const data = await db.query();   // 直接访问数据库/文件/秘密
  return <ClientList data={data} />;
}

// Client Component(需 'use client')
'use client';
function ClientList({ data }) {
  const [x, setX] = useState(0);   // 交互在浏览器
  return <ul>{data.map(...)}</ul>;
}
```

| | Server | Client |
|---|--------|--------|
| 运行环境 | 服务器 | 浏览器 |
| 能用 | 数据库/文件/秘密 | useState/事件/DOM |
| 体积 | 不进浏览器 | 进 bundle |

---

## 三、RSC vs SSR(底层,易混)

> **SSR 是"渲染模式"(整页 HTML 在服务器生成)**;**RSC 是"组件模型"(按组件划分运行环境)**。二者可组合:Server Component 在服务器生成 HTML → 流式给客户端 → Client Component 再 Hydration。

**RSC 的价值(为什么这样设计):**

> 传统 SPA 把所有代码(含数据逻辑、重库)打到浏览器;RSC 让"只依赖服务端的部分"**留在服务器**(不进 bundle),只有"需交互的部分"发客户端——既**减包**、又能**直连数据库/读秘密**、还天然 async。

## 四、Next.js App Router 速览

```jsx
// 文件即路由:app/users/[id]/page.jsx
export default async function UserPage({ params }) {
  const { id } = await params;
  return <div>{id}</div>;
}
```

- 流式 SSR:`<Suspense>` 包裹,边渲染边推送
- Server Component 里直接 `await fetch`

---

## 五、小结

```
CSR(浏览器)→ SSR(服务端首屏)→ RSC(组件级分工)
Server Component:服务端跑、直连 DB、不进 bundle
Client Component:'use client',有交互
RSC 价值:减 bundle + 直连服务端 + 原生 async
```

## 六、面试题

**Q1:RSC(Server Component)和 SSR 的区别?**

SSR 是"**首屏 HTML 在服务器渲染**"的**渲染模式**(整页);RSC 是"**按组件划分运行环境**"的**组件模型**。二者可组合:Server Component 服务器生成 HTML 流式给客户端,Client Component 再 Hydration。

**Q2:什么时候一个组件要标记 'use client'?**

需要**交互或浏览器能力**(useState/useEffect/事件/DOM API)时;纯展示、读数据、服务端能完成的保持 Server Component(默认)。

**Q3:Server Component 为什么能"减 bundle"?**

只依赖服务端的代码(数据逻辑、重库、秘密)**不进入浏览器 bundle**,只有 Client Component 的代码发给客户端。所以总 JS 体积更小。

**Q4:Server Component 里能用 useState 吗?为什么?**

不能。Server Component 只在**服务器**运行、无交互、无状态;useState 是浏览器交互、需要客户端。有状态的组件要标 `'use client'`。

**Q5:RSC 里数据获取的典型方式?**

Server Component 直接 `await fetch`/`await db.query()` 获取数据,返回的 JSX 随 HTML 流式下发——不需要 useEffect + 状态管理做取数。

**Q6:流式 SSR(Streaming)解决什么?**

传统 SSR 要等**整页数据就绪**才返回;流式 SSR 用 `<Suspense>` 把页面拆块,**就先渲染好的部分先推送**,慢的部分后到,首屏更快、TTFB 更短。
