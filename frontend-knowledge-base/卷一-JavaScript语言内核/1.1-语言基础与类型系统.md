## 为什么类型系统是「地基」

写 React、写 Vue、写 Node 之前,先得说清楚一件事:**变量里到底装着什么**。类型系统决定了变量怎么存、怎么比较、怎么运算、怎么传参。后面讲闭包、原型、异步,全都建立在「这个值是什么类型」之上。

JS 是**动态类型、弱类型**语言——变量类型运行时才确定,且运算时允许隐式转换。这带来了灵活,也埋下了大量 "0.1 + 0.2" 式的坑。本章把这些坑一次性说透。

---

## 一、7 种基本类型 + 1 种引用类型

规范里,JS 的类型分两类:

**基本类型(原始值 Primitive)—— 7 种:**

| 类型 | 说明 | 示例 |
|------|------|------|
| `number` | 整数与浮点,统一 64 位双精度 | `1`, `0.5`, `NaN`, `Infinity` |
| `string` | 字符串,不可变 | `'hi'` |
| `boolean` | `true` / `false` | `true` |
| `null` | 表示「空」,原型链的终点 | `null` |
| `undefined` | 声明未赋值 / 未定义 | `undefined` |
| `symbol` (ES6) | 唯一标识,做对象的 key | `Symbol('x')` |
| `bigint` (ES2020) | 大整数,精确表示超大数 | `9007199254740993n` |

**引用类型 —— 1 种:对象 `object`**

`object` 是唯一的引用类型,常见的数组、函数、日期、正则都是它的「子类型」。

```js
typeof []        // "object"  数组是对象
typeof function(){} // "function"(历史遗留,本质仍是对象)
```

## 二、`typeof` 的两个著名坑

`typeof` 是判断类型最常用的操作符,但它有两个反直觉结果:

```js
typeof null          // "object"  ← 历史 bug,至今未改(提案曾想改,被否决)
typeof undefined     // "undefined"
typeof NaN           // "number"  ← NaN 是数字家族的一员
typeof Symbol()      // "symbol"
typeof 10n           // "bigint"
```

**为什么 `typeof null === "object"`?**
早期 JS 里,值的类型由二进制低位的「类型标签」区分,对象标签是 `000`,`null` 的机器码恰好全为 0,于是被 `typeof` 误判成对象。这是语言层面的历史遗留,只能「将错就错」。

> 判断 `null` 的正确姿势:`x === null`。
> 判断数组:`Array.isArray(x)`。
> 判断「是不是引用类型」:`typeof x === "object" && x !== null`,或 `x instanceof Object`。

## 三、原始值 vs 引用值:栈与堆

这是理解「值传递」「深浅拷贝」「不可变」的关键分水岭。

| | 原始值 | 引用值 |
|---|--------|--------|
| 存储位置 | 栈(stack),变量直接存值 | 堆(heap),变量存**地址** |
| 大小 | 固定 | 不固定 |
| 复制 | 复制**值**本身 | 复制**地址**(指向同一块堆内存) |
| 可变性 | 不可变 | 可变 |

```js
// 原始值:复制值,互不影响
let a = 1;
let b = a;
b = 2;
console.log(a); // 1  ← a 不受影响

// 引用值:复制地址,共享同一对象
let obj1 = { name: 'jo' };
let obj2 = obj1;
obj2.name = 'amy';
console.log(obj1.name); // "amy"  ← 被改变了!
```

> 判断「是否可变」有个土办法:原始值一旦赋值,你没法在不重新赋值的情况下改变它;对象却能通过属性原地修改。这也解释了为什么 Vue3 的 `reactive` 只对对象有效,而 `ref` 能包原始值。

## 四、值传递:函数传参的本质

JS 的传参**统一是「值传递」**——就是把栈里的值复制一份传给函数。差别在于:

- 基本类型:复制的是值 → 函数内改动不影响外部
- 引用类型:复制的是地址 → 函数内改**属性**会影响外部,但重新赋值**不会**

```js
function change(prim, ref) {
  prim = 100;            // 基本类型:改的是副本
  ref.name = 'changed';  // 引用类型:改属性 → 影响外部
  ref = { name: 'new' }; // 重新赋值:只是让局部变量指向新对象,不影响外部
}

let num = 1;
let obj = { name: 'old' };
change(num, obj);
console.log(num);         // 1         ← 没变
console.log(obj.name);    // "changed" ← 变了
```

> 一句话总结:**基本类型按值改动不了外部,对象能改「内容」但不能改「指向」**。这个点常考「函数能不能改变外部变量」。

## 五、隐式类型转换(ToPrimitive)

弱类型的「弱」,主要体现在运算时自动转换。核心机制是 **ToPrimitive**:

**对象 → 原始值,遵循顺序:**
1. 优先调 `valueOf()`,返回原始值就用
2. 否则调 `toString()`,返回原始值就用
3. 否则报错

**`+` 运算的两个规则:**

```js
// 规则 1:只要有字符串,就拼字符串
1 + '2'      // "12"
'1' + 2      // "12"
null + 'x'   // "nullx"

// 规则 2:没有字符串,转数字相加
1 + true     // 2 ← true 转 1
1 + null     // 1 ← null 转 0
1 + undefined // NaN ← undefined 转 NaN
```

**`==` 与 `===` 的核心差别:**

`==` 在比较前会做类型转换,转换规则繁琐易错:

```js
null == undefined   // true  ← 特例,只等于对方和自己
'0' == false        // true  ← '0' 转 0,false 转 0
[] == false         // true  ← 空数组 toString 成 "",转成 0
[] == 0             // true
```

`===` 不做转换,类型不同直接 `false`。

> **工程铁律:永远用 `===`。** 除非你明确需要 `null == undefined` 这种「都是空值」的判断。

## 六、Truthy 与 Falsy

条件判断里的隐式布尔转换,记住 **8 个 falsy 值**即可,其余全是 truthy:

```js
false, 0, -0, 0n, "", null, undefined, NaN
```

两个经典陷阱:

```js
if ("0")      // truthy! 非空字符串,即使内容是 "0"
if ([])       // truthy! 空数组是 truthy
if ({})       // truthy! 空对象是 truthy
```

> 判断「空数组」请用 `arr.length === 0`,判断「空对象」用 `Object.keys(obj).length === 0`。

## 七、`number` 的精度问题

JS 数字统一是 **IEEE 754 双精度浮点数(64 位)**,因此:

```js
0.1 + 0.2 === 0.3   // false!实际是 0.30000000000000004
```

**根因**:十进制小数转二进制时,很多数是无限循环小数(如 0.1),64 位截断后产生误差,累加放大。

**安全整数范围**:`Number.MAX_SAFE_INTEGER === 2^53 - 1 === 9007199254740991`。超出这个范围,整数运算会失真:

```js
9007199254740992 + 1 === 9007199254740992  // true!加了个寂寞
```

**解法:**
- 小数比较用容差:`Math.abs(a - b) < Number.EPSILON`
- 金额运算:放大为整数(分单位)后计算,或用 `bigint` / decimal 库
- 大整数用 `bigint`:`9007199254740992n + 1n`

## 八、`NaN` 与 `Infinity`

```js
typeof NaN       // "number"
NaN === NaN      // false  ← NaN 是唯一「不等于自己」的值
Number.isNaN(NaN) // true   ← 正确判断法,别用全局 isNaN(会先转数字)
1 / 0            // Infinity
-1 / 0           // -Infinity
Infinity - Infinity // NaN
```

## 九、小结

一张图收束本章:

```
类型体系
├─ 基本类型(7):number string boolean null undefined symbol bigint
│    ├─ 存栈、按值复制、不可变
│    └─ 特例:typeof null === "object"、NaN !== NaN、0.1+0.2 !== 0.3
└─ 引用类型(1):object(含数组/函数/正则...)
     ├─ 存堆、按地址复制、可变
     └─ 传参是「值传递」,对象改内容不改指向

运算中的隐式转换(ToPrimitive + Truthy/Falsy)→ 工程上统一用 ===
```

## 十、面试题

**Q1:下列输出是什么?**

```js
console.log(typeof typeof 1);  // ?
console.log([] + []);          // ?
console.log([] + {});          // ?
console.log({} + []);          // ?
console.log(1 + - + + + - + 1);// ?
```

<details>
<summary>展开答案</summary>

```js
typeof typeof 1
// typeof 1 → "number"; typeof "number" → "string"

[] + []   // "" + "" → ""
[] + {}   // "" + "[object Object]" → "[object Object]"
{} + []   // 视作代码块 + 一元运算,→ 0(注意与 [] + {} 不同!)
1 + - + + + - + 1  // 1 + (-(+ (+ (+ (- (+ 1)))))) → 1 + (-1) → 0
```
</details>

**Q2:如何精确判断一个值的类型?**

```js
Object.prototype.toString.call(x)
// "[object Number]" / "[object Array]" / "[object Null]" ...
// 比 typeof / instanceof 更全、更准
```

**Q3:`const` 声明的对象为什么还能改属性?**

因为 `const` 约束的是「变量与地址的绑定」不能变,而对象内部的堆内存仍然可变。这正印证了本章第三节的栈/堆模型。
