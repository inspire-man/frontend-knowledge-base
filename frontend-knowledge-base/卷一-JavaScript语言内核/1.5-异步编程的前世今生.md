## 引言:从回调地狱到 async/await

JS 单线程,阻塞会卡死页面,所以有了异步。异步的写法一路演进:**回调 → Promise → async/await**,每一次都是为了解决上一个的痛点。本章讲透这条线,并手写一个最简 Promise。(事件循环的底层调度机制见 1.8。)

## 一、回调函数与回调地狱

```js
// 回调:把后续逻辑传进去,等异步完成再执行
fs.readFile("a.txt", (err, dataA) => {
  fs.readFile("b.txt", (err, dataB) => {
    fs.readFile("c.txt", (err, dataC) => {
      // 层层嵌套 → "回调地狱",难读、难维护、错误处理割裂
    });
  });
});
```

痛点:① 深层嵌套;② 错误要每个回调单独处理;③ 无法统一做流程控制。

## 二、Promise:状态机 + 链式

### 2.1 三种状态

```
pending(进行中) ──resolve──▶ fulfilled(成功)
     │
     └─────────reject─────▶ rejected(失败)

状态只能变化一次,且不可逆(pending → 终态)。这就是"Promise 只能 resolve 一次"的由来。
```

```js
const p = new Promise((resolve, reject) => {
  resolve(1);   // 先到 fulfilled
  reject(2);    // 无效,状态已定
});
```

### 2.2 链式调用与错误穿透

`then` **总是返回一个新 Promise**,所以能链式;`catch` 能捕获前面任意一环的异常。

```js
fetchApi()
  .then((r) => r.json())      // 返回新 promise
  .then((data) => process(data))
  .catch((err) => handle(err)); // 一处兜底
```

### 2.3 手写最简 Promise(核心三段)

```js
class MyPromise {
  constructor(executor) {
    this.state = "pending";
    this.value = undefined;
    this.callbacks = [];

    const resolve = (v) => {
      if (this.state !== "pending") return;
      this.state = "fulfilled";
      this.value = v;
      this.callbacks.forEach((cb) => cb.onFulfilled(v));
    };
    const reject = (e) => {
      if (this.state !== "pending") return;
      this.state = "rejected";
      this.value = e;
      this.callbacks.forEach((cb) => cb.onRejected(e));
    };

    try { executor(resolve, reject); } catch (e) { reject(e); }
  }

  then(onFulfilled, onRejected) {
    if (this.state === "fulfilled") onFulfilled?.(this.value);
    else if (this.state === "rejected") onRejected?.(this.value);
    else this.callbacks.push({ onFulfilled, onRejected });
    // 注:此处省略返回新 Promise 的链式实现,核心是「状态 + 回调队列」
  }
}
```

## 三、async/await:生成器 + Promise 的语法糖

`async` 函数**总是返回一个 Promise**;`await` 会"暂停"函数执行,等到 Promise 完成再继续,让异步代码写出**同步的观感**:

```js
async function main() {
  try {
    const dataA = await readFile("a.txt");  // 等
    const dataB = await readFile("b.txt");  // 再等(注意:是串行的!
    return dataA + dataB;
  } catch (e) {
    console.log("统一错误处理", e);
  }
}
```

**两个常见坑:**

```js
// 坑①:串行 vs 并行——想并行用 Promise.all
const [a, b] = await Promise.all([readFile("a"), readFile("b")]);

// 坑②:await 会阻塞后续,循环里 await 是串行;要并行用 map + Promise.all
const results = await Promise.all(urls.map((u) => fetch(u)));
```

## 四、三个核心认知(面试高频)

| 问题 | 答案 |
|------|------|
| `then` 返回什么? | **总是**返回新 Promise(即使你没写 return) |
| `async` 返回什么? | **总是**返回 Promise(return 值会被包成 resolved) |
| `Promise` 状态能变几次? | **一次**。resolve 后再 reject 无效 |
| `catch` 和 `then` 的第二参数区别? | `catch` 能捕获**链上前端**的错;`then(onRes, onRej)` 只处理当前一环 |

## 五、小结

```
异步演进
├─ 回调:想后置逻辑 → 回调地狱(嵌套/错误割裂)
├─ Promise:状态机(pending→fulfilled/rejected,一次性)→ 链式 then,错误穿透
└─ async/await:生成器+Promise 语法糖 → 同步观感,用 try/catch 统一捕获

关键:then 返回新 Promise;async 返回 Promise;并行用 Promise.all
```

## 六、面试题

**Q1:下列执行顺序与输出?**

```js
console.log(1);
Promise.resolve().then(() => console.log(2));
setTimeout(() => console.log(3), 0);
console.log(4);
```

<details>
<summary>答案</summary>

```js
// 1 → 4 → 2 → 3
// 同步先跑(1、4);Promise.then 进微任务(2);setTimeout 进宏任务(3)。
// 微任务优于宏任务先执行。完整机制见 1.8 事件循环。
```
</details>

**Q2:实现一个带并发限制的批量请求 `pLimit` 思路?**

把任务放进队列,维护一个 `active` 计数,每完成一个就取下一个,直到队列清空——本质是"**闭包保存状态 + Promise 链**"的组合。(完整代码见「附录A · 手写系列」)
