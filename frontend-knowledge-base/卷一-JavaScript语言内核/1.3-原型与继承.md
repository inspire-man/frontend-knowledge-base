# 1.3 原型与继承

> 卷:卷一 · JavaScript 语言内核
> 阅读时间:30min

---

## 引言:JS 的"继承"靠链,不靠 class

`class` 是 ES6 加的糖,JS 骨子里是**基于原型**。想真正吃透,要懂底层的 `[[Prototype]]` 内部槽、属性查找的 `[[Get]]` 算法,以及"为什么用共享换内存"。

---

## 一、为什么需要原型

让 N 个对象共享同一份方法,而不是各存一份(浪费内存):

```js
function Person(name) { this.name = name; }
Person.prototype.sayHi = function () { console.log("hi " + this.name); };

const p1 = new Person("大王");
const p2 = new Person("阿北");
p1.sayHi();             // hi 大王
p1.sayHi === p2.sayHi;  // true ← 方法是同一份,存在原型上
```

**为什么这样设计?** 每个实例有独立数据(`name`),但方法可共享——把共享部分放"原型"、私有部分放实例,是"**用共享换内存**"的取舍(与 6.1 Vue 响应式同源)。

---

## 二、底层:`[[Prototype]]` 内部槽

每个对象都有一个隐藏内部槽 **`[[Prototype]]`**,指向它的原型对象(`__proto__` 是它的访问器外壳):

```mermaid
flowchart LR
    P[Person.prototype<br/>sayHi 方法] -->|[[Prototype]]| O[Object.prototype<br/>toString 等]
    O -->|[[Prototype]]| N[null 终点]
    I[p1 实例<br/>name: 大王] -->|[[Prototype]]| P
    P -.->|constructor| F[Person 构造函数]
```

**属性查找 `[[Get]]` 算法**:`obj.foo` 先查自身属性 → 没有就沿 `[[Prototype]]` 逐级向上 → 到 `Object.prototype` → 到 `null` → 返回 `undefined`。这条链就是**原型链**。

```js
p1.__proto__ === Person.prototype;               // true
Person.prototype.__proto__ === Object.prototype; // true
Object.prototype.__proto__ === null;             // true
Person.prototype.constructor === Person;         // true
```

## 三、`new` 的四步(规范等效)

```js
function myNew(constructor, ...args) {
  const obj = Object.create(constructor.prototype); // 1. 建对象,绑 [[Prototype]]
  const res = constructor.apply(obj, args);         // 2. 以 obj 为 this 执行
  return res instanceof Object ? res : obj;         // 3. 有返回对象则用,否则 obj
}
```

---

## 四、`prototype` vs `__proto__`

| 属性 | 属于 | 指向 | 作用 |
|------|------|------|------|
| `prototype` | 函数 | 一个对象 | 供 `new` 出的实例共享 |
| `__proto__` | 每个对象 | 它的原型 | 实现原型链查找 |

> `__proto__` 是历史遗留访问器,规范标准 API 是 `Object.getPrototypeOf/setPrototypeOf`。

---

## 五、`instanceof` 的原理

`A instanceof B`:沿 A 的原型链,看能否找到 `B.prototype`。

```js
function myInstanceof(obj, ctor) {
  let proto = Object.getPrototypeOf(obj);
  while (proto) {
    if (proto === ctor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

## 六、继承的五种演进(完整代码)

### 1. 原型链继承

```js
function Parent() { this.name = "parent"; this.colors = ["red"]; }
Parent.prototype.say = function () { console.log(this.name); };

function Child() {}
Child.prototype = new Parent();   // 核心:把父实例当子原型

const c1 = new Child(), c2 = new Child();
c1.colors.push("blue");
console.log(c2.colors);   // ["red", "blue"] ← ❌ 引用类型被共享了!
```

缺点:① 引用类型属性被所有实例共享;② 子类无法向父类构造函数传参。

### 2. 借用构造函数继承

```js
function Parent(name) { this.name = name; this.colors = ["red"]; }
function Child(name) {
  Parent.call(this, name);   // 借父构造函数,this 指向子实例
}
const c1 = new Child("a"), c2 = new Child("b");
c1.colors.push("blue");
console.log(c2.colors);      // ["red"] ✅ 属性独立了
console.log(c1.say);         // undefined ❌ 但拿不到原型上的方法
```

缺点:方法若定义在构造函数里,每次 `new` 都重新创建;且**原型上的方法拿不到**。

### 3. 组合继承(原型链 + 借用)

```js
function Parent(name) { this.name = name; }
Parent.prototype.say = function () { console.log(this.name); };

function Child(name) {
  Parent.call(this, name);       // 借构造:属性独立
}
Child.prototype = new Parent();       // 借原型:方法共享
Child.prototype.constructor = Child;

const c = new Child("a");
c.say();                      // "a" ✅ 属性和方法都有了
```

缺点:父构造函数被调用了**两次**(一次 `Parent.call`,一次 `new Parent()`)。

### 4. 寄生组合继承(ES5 最优)

```js
function Child(name) {
  Parent.call(this, name);                 // 只调一次父构造
}
Child.prototype = Object.create(Parent.prototype); // 不 new,直接以父原型为原型
Child.prototype.constructor = Child;
```

`Object.create(Parent.prototype)` 创建"原型指向父原型"的空对象,**跳过一次多余的父类调用**——这是"组合继承"到"寄生组合"的关键优化。

### 5. class extends(语法糖 = 寄生组合 + 静态链)

```js
class Child extends Parent {
  constructor(name) { super(name); }   // 等价 Parent.call(this, name) + 绑原型链
}
```

**class 的底层编译结果(等价手写):**

```js
function Child(...args) { return Parent.apply(this, args); }
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;
Object.setPrototypeOf(Child, Parent);   // 静态继承:Child.__proto__ = Parent
```

> 关键:`class` 除了"实例原型链",还额外建了"**静态属性链**"(`Child.__proto__ === Parent`),让子类能继承父类的**静态方法**——这是纯 ES5 寄生组合容易漏掉的一环。

## 七、小结

```
[[Prototype]] 内部槽 → 原型链(实例→构造函数.prototype→Object.prototype→null)
[[Get]] 查找:自身→原型链逐级→undefined
new 四步:建对象/绑原型/执行/返回
继承演进:原型链→借用→组合(调两次)→寄生组合(Object.create,最优)→class
```

## 八、面试题

**Q1:属性查找的全过程(`[[Get]]`)?**

读 `obj.foo` 时:先查 obj **自身属性**(含原型链上"遮蔽"),没有就沿 `[[Prototype]]` 逐级向上到 `Object.prototype`、再到 `null`,都没有返回 `undefined`。若属性在链上但设置了 `getter` 则触发。这条查找路径就是原型链。

**Q2:`a.__proto__.foo = 2` 会影响所有实例吗?**

```js
function F() {} F.prototype.foo = 1;
const a = new F(), b = new F();
a.__proto__.foo = 2;   // 改的是 F.prototype
console.log(b.foo);    // 2 ← 影响所有实例(共享同一原型)
```

**Q3:手写 `Object.create`?**

```js
function create(proto) {
  function F() {}
  F.prototype = proto;
  return new F();
}
```

**Q4:`Object.create(null)` 和 `{}` 有何不同?**

前者**没有原型链**(`[[Prototype]]` 为 null),不含 `toString`/`hasOwnProperty` 等,常做纯净字典/map,避免键名与原型方法冲突(如用 `{"toString": 1}` 做 map 时不会污染)。

**Q5:为什么 `class` 的 `constructor` 里必须先调 `super`?**

`class extends` 的实例由父类构造器创建(`super` 内部 = `Parent.call(this)` + 绑定子类 `[[Prototype]]`),不先 `super` 就没有 `this`(未初始化),访问 `this` 会报错。这是 class 与普通构造函数"默认有 this"的关键区别。

**Q6:`for...in` 会遍历到原型上的属性吗?如何只遍历自身?**

会——`for...in` 遍历**自身 + 原型链上所有可枚举属性**。只要自身可枚举的用 `Object.keys()`(或 `hasOwnProperty` 过滤):

```js
for (const k in obj) if (obj.hasOwnProperty(k)) { /* 自身属性 */ }
// 或 Object.keys(obj)
```
