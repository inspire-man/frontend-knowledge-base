## 引言:JS 的"继承"不是靠 class,而是靠链

`class` 是 ES6 才加的糖,JS 骨子里是**基于原型**的语言。理解了原型,才能解释:为什么数组能 `.map`、对象能 `.hasOwnProperty`、以及 Vue/React 源码里那句 `instanceof Component` 是怎么判的。

---

## 一、为什么需要原型

我们希望 N 个对象共享同一份方法,而不是每个对象各存一份(浪费内存)。于是 JS 设计出:**

**每个对象都有一个隐藏的 `[[Prototype]]` 指向它的"原型对象",自己不认识的属性,就顺着原型去找。**

```js
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  console.log("hi " + this.name);
};

const p1 = new Person("大王");
const p2 = new Person("阿北");
p1.sayHi(); // hi 大王
p1.sayHi === p2.sayHi; // true  ← 方法是同一份,存在原型上
```

## 二、`new` 到底干了什么

构造函数首字母大写只是约定,真正的魔法在 `new`。`new Person()` 等价于四步:

```js
function myNew(constructor, ...args) {
  // 1. 创建一个新对象,并把它的原型指向构造函数的 prototype
  const obj = Object.create(constructor.prototype);
  // 2. 以新对象为 this,执行构造函数
  const res = constructor.apply(obj, args);
  // 3. 若构造函数有返回对象,则用返回值;否则用新对象
  return res instanceof Object ? res : obj;
}
```

## 三、`prototype` vs `__proto__`(最容易混)

| 属性 | 属于谁 | 指向 | 作用 |
|------|--------|------|------|
| `prototype` | **函数**(构造函数 | 一个对象 | 供 `new` 出的实例共享方法 |
| `__proto__` | **每个对象** | 它的原型对象 | 实现原型链查找 |

**核心公式(背下来):**

```js
p1.__proto__ === Person.prototype;          // true
Person.prototype.__proto__ === Object.prototype; // true
Object.prototype.__proto__ === null;        // true ← 链的终点

Person.prototype.constructor === Person;    // true(构造函数的 prototype 上有 constructor 指回自己)
```

> 规范里标准 API 是 `Object.getPrototypeOf(x)` / `Object.setPrototypeOf(x, proto)`,`__proto__` 是历史遗留的访问器(能用但别在生产直接改)。

---

## 四、原型链:属性查找规则

访问 `obj.foo` 时:先看自身 → 没有就看 `__proto__` → 再看 `__proto__.__proto__` → … → 一直到 `Object.prototype` → 再到 `null`,找不到返回 `undefined`。

```js
const arr = [1, 2, 3];
arr.toString(); // 方法来自哪里?
// 查找链:arr → Array.prototype → Object.prototype → null
// 沿链找到 Array.prototype 上覆盖(Object 上也有 toString)的近端版本
```

**一张图看懂整条链:**

```
p1 ──__proto__──▶ Person.prototype ──__proto__──▶ Object.prototype ──__proto__──▶ null
(name: 大王)       (sayHi 方法)                    (toString/hasOwnProperty)
```

## 五、`instanceof` 的原理

`A instanceof B`:沿 A 的原型链往上找,看能不能找到 `B.prototype`。

```js
p1 instanceof Person;  // true(p1.__proto__ === Person.prototype)
p1 instanceof Object;  // true(链上还有 Object.prototype)
[] instanceof Array;   // true
[] instanceof Object;  // true(Array.prototype 的 __proto__ 是 Object.prototype)

// 手写 instanceof
function myInstanceof(obj, ctor) {
  let proto = Object.getPrototypeOf(obj);
  while (proto) {
    if (proto === ctor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}
```

## 六、继承的五种演进(面试重点)

### 6.1 原型链继承

```js
function Parent() { this.colors = ["red"]; }
Parent.prototype.say = () => console.log("hello");
function Child() {}
Child.prototype = new Parent(); // 核心:把父实例当子原型
```

**缺点**:① 父类**引用类型属性被所有子实例共享**(一个改 `colors`,全都变);② 子类无法向父类构造函数传参。

### 6.2 借用构造函数继承

```js
function Child() { Parent.call(this); } // 在子类里调用父类构造,解决①传参和②共享
```

**缺点**:方法定义在构造函数里,每次 `new` 都重新创建,**方法无法复用**。

### 6.3 组合继承(原型链 + 借用)[最常用传统方案]

```js
function Child(...args) {
  Parent.call(this, ...args);      // 继承属性(独立)
}
Child.prototype = new Parent();    // 继承方法(共享)
Child.prototype.constructor = Child; // 修正 constructor 指向
```

**缺点**:父类构造函数被调用了**两次**(一次 call、一次 new Parent)。

### 6.4 寄生组合继承(最优传统方案)

```js
function Child(...args) {
  Parent.call(this, ...args);       // 只调用一次父类构造
}
Child.prototype = Object.create(Parent.prototype); // 不 new,直接以父原型为原型
Child.prototype.constructor = Child;
```

`Object.create(Parent.prototype)` 创建一个"原型指向父原型"的空对象,**跳过了一次多余的父类调用**,是 ES5 下的最优解。

### 6.5 class extends(语法糖)

```js
class Child extends Parent {
  constructor(...args) {
    super(...args);   // 等价于 Parent.call(this, ...args),且绑定原型链
  }
  // 方法自动挂到 Child.prototype,且 Child.prototype.__proto__ = Parent.prototype
}
```

**`class` 的本质**:还是构造函数 + 原型,只是语法更清晰。`extends` 内部做的正是**寄生组合继承**,外加静态方法/`super` 转发。

## 七、小结

```
构造函数 new → 四步(建对象/绑原型/执行/返回)
        │
        ▼
prototype(函数)◀──constructor──▶ __proto__(实例)
        │                            │
        ▼                            ▼
  实例共享方法 ◀──查找── 原型链:实例 → 构造函数.prototype → Object.prototype → null

继承演进:
原型链继承(共享问题)→ 借用构造(方法不共享)→ 组合(调两次)→
寄生组合(Object.create,最优)→ class extends(语法糖 = 寄生组合)
```

## 八、面试题

**Q1:判断对错并解释**

```js
function F() {}
F.prototype.foo = 1;
const a = new F();
const b = new F();
a.__proto__.foo = 2;   // 改的是原型上的值
console.log(b.foo);    // ?
```

<details>
<summary>答案</summary>

```js
// 2。a.__proto__ 就是 F.prototype,
// 改原型上的 foo 会影响所有引用它的实例(包括 b)。
// 这也正是"原型链继承下引用类型被共享"的根源。
```
</details>

**Q2:手写 `Object.create`**

```js
function create(proto) {
  function F() {}
  F.prototype = proto;
  return new F();
}
```

**Q3:`Object.create(null)` 和 `{}` 有何不同?**

`Object.create(null)` 创建的对象**没有原型链**(`__proto__` 为 null),因此不含 `toString`/`hasOwnProperty` 等继承方法,常用来做**纯净的字典/map**,避免键名与原型方法冲突。
