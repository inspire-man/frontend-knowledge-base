## 引言:为什么「作用域」是 JS 面试第一道坎

作用域决定了"变量在哪里能访问、谁访问到了谁"。它背后藏着四个高频考点:**变量提升、暂时性死区、作用域链、闭包**。而闭包又是 Vue 的响应式、React 的 Hooks、防抖节流这些日常代码的底层机制——绕不开。

---

## 一、JS 是"编译型"语言(先编译,再执行)

很多人以为 JS 是纯解释执行,其实标准引擎(V8 等)的执行分两步:

```
源代码 → 编译阶段(词法分析 → 生成作用域 → 声明提升) → 执行阶段(逐行运行)
```

**正是这个"先编译"动作,产生了「变量提升」。** 编译时,引擎先扫一遍代码,把所有声明(`var`/`let`/`const`/函数)登记到各自作用域,然后再执行。

```js
console.log(a); // undefined ← 不是报错!因为 var a 已被"提升"但未赋值
var a = 1;
```

---

## 二、三种作用域

| 作用域 | 边界 | 说明 |
|--------|------|------|
| 全局作用域 | 整个脚本 | 任何地方都能访问,变量挂 `window`(浏览器) |
| 函数作用域 | `function` 内 | 由函数体界定,`var` 属于这一层 |
| 块级作用域 | `{ }` 内 | ES6,`let`/`const` 属于这一层 |

```js
var x = 1;       // 全局
function foo() {
  var y = 2;     // 函数作用域
  if (true) {
    let z = 3;   // 块级作用域
    var w = 4;   // var 无视块级!仍是函数作用域
  }
  console.log(w); // 4
  // console.log(z); // ReferenceError,z 出界了
}
```

## 三、变量提升与 TDZ(暂时性死区)

**`var` 的提升:只提声明,不提赋值**

```js
console.log(a); // undefined
var a = 10;
// 等价于:var a;(提升) → console.log(a) → a = 10
```

**函数声明的提升:整体提升(可直接调用)**

```js
say(); // "hi" ← 函数声明整体提升,能提前调用
function say() { console.log("hi"); }
```

**`let`/`const` 也有提升,但带 TDZ**

`let`/`const` 的声明同样会提升到块顶部,但在「声明之前」访问会直接抛 `ReferenceError`——这块"声明前不可访问"的区域就叫**暂时性死区(Temporal Dead Zone)**。

```js
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 1;
```

> 区别记忆:var 提升后是 `undefined`,let/const 提升后是"死区报错"。函数表达式(非声明)也不会整体提升。

## 四、作用域链:变量查找规则

JS 采用**词法作用域(静态作用域)**:作用域由代码**书写位置**决定,而不是调用位置。

当访问一个变量时,引擎沿着「当前作用域 → 外层作用域 → … → 全局」逐级向上找,找到即止,找不到就 `ReferenceError`。这条查找路径就是**作用域链**。

```js
const a = "global";
function outer() {
  const a = "outer";
  function inner() {
    const a = "inner";
    console.log(a); // "inner"  ← 就近原则
  }
  inner();
}
outer();
```

## 五、闭包(Closure)

### 5.1 定义

> **闭包 = 函数 + 它定义时所在的「词法作用域」的引用。** 当一个函数"记住"并持续访问它外部作用域的变量,即使那个外部函数已经执行完,闭包就形成了。

```js
function outer() {
  let count = 0;
  return function inner() {
    count++;          // inner 引用了 outer 的 count
    return count;
  };
}
const fn = outer();   // outer 已执行完,但 count 没被销毁
console.log(fn());    // 1
console.log(fn());    // 2  ← count 被 inner 持续持有
```

为什么 `outer()` 执行完后 `count` 还没消失?因为返回的 `inner` 仍然持有对 `count` 所在作用域的引用,垃圾回收无法回收它。

### 5.2 三个形成条件(缺一不可)

1. 函数**嵌套定义**
2. 内层函数**引用**了外层变量
3. 内层函数被**返回到外部 / 在外层之外被调用**

### 5.3 经典误区:循环里的 `var` 陷阱

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 输出:3 3 3(全是最外层的同一个 i,循环结束时已变 3)
```

**修复三法,层层递进:**

```js
// ① let 形成块级作用域,每次迭代一个独立 i
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0); // 0 1 2

// ② 立即执行函数(IIFE)包一层,把当前 i 固化进参数
for (var i = 0; i < 3; i++) {
  (function (j) { setTimeout(() => console.log(j), 0); })(i); // 0 1 2
}

// ③ 闭包本质:每次迭代都创建一个新的作用域快照
```

## 六、闭包的实际用途

| 场景 | 说明 |
|------|------|
| **数据私有化** | 模拟私有变量,外部只能通过返回的接口访问 |
| **防抖/节流** | 用闭包保存 timer,多次调用共享同一状态 |
| **柯里化/偏函数** | 固定部分参数,返回新函数 |
| **函数缓存(记忆化)** | 用闭包存计算结果,避免重复计算 |
| **模块化** | 早期 IIFE + 闭包实现模块隔离 |

**私有变量示例:**

```js
function createCounter() {
  let count = 0;               // 私有,外部不可直接触碰
  return {
    add: () => ++count,
    get: () => count,
  };
}
const c = createCounter();
c.add(); c.add();
console.log(c.get()); // 2
console.log(c.count); // undefined ← 外部拿不到
```

**手写防抖(闭包核心应用):**

```js
function debounce(fn, delay) {
  let timer = null;            // 闭包保存 timer,跨调用共享
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

## 七、闭包的代价:内存泄漏

闭包会让外层变量**无法被 GC 回收**,如果闭包本身不再需要、却仍被长期持有,就会泄漏内存。

```js
// 坏味道:全局持续持有闭包,而其内部的"大对象"也被连带锁死
let big = { data: new Array(1000000) };
let keepAlive = () => console.log(big.data.length);
// 若 keepAlive 长期无用却未释放,big 将一直占内存

// 解法:用完显式解除引用
keepAlive = null;
```

> 注意:**闭包本身不必然泄漏**,只有"生命周期过长 + 持有大对象 + 忘记释放"才成问题。工程上注意"用完即断"即可。

## 八、小结

```
作用域
├─ 类型:全局 / 函数 / 块级(let/const)
├─ 查找:作用域链(词法作用域,就近原则)
└─ 前置:编译期 → 变量提升(var=undefined;函数=整体;let/const=TDZ报错)

闭包 = 函数 + 外部词法作用域的引用
├─ 条件:嵌套 + 引用外层变量 + 返回/外调
├─ 用途:私有变量 / 防抖节流 / 柯里化 / 缓存 / 模块化
└─ 代价:持有引用不释放 → 可能内存泄漏(用完置 null)
```

## 九、面试题

**Q1:下面输出什么?**

```js
var a = 1;
function fn() {
  console.log(a);
  var a = 2;
}
fn(); // ?
```

<details>
<summary>答案</summary>

```js
// undefined
// 函数内有 var a,编译期提升到 fn 顶部,遮蔽了外层 a,
// 打印时 a 已声明但未赋值 → undefined
```
</details>

**Q2:为什么 React 的 `useState`/`useEffect` 能"记住"上一次的值?**

因为它们底层借助了闭包 + 链表存储 hook 状态,每次渲染都从"上一次的函数作用域"里读取状态。这正是闭包"跨执行持有变量"的能力在框架层的体现。(详见卷七 Hooks 章节)

**Q3:判断哪些是闭包?**

```js
// A
function a(){ var x=1; function b(){ return x; } return b; }  // ✅ 闭包

// B
function c(){ var y=1; return y; }                            // ❌ 未返回函数

// C
[1,2,3].map(n => n * 2);                                     // ❌ 未引用外层变量(箭头函数没形成对外层作用域的依赖)
```
