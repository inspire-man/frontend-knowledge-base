# 1.4 this 绑定与调用

> 卷:卷一 · JavaScript 语言内核
> 阅读时间:25min

---

## 引言:`this` 是运行时决定的——但为什么?

`this` 指向"谁在调用这个函数",由**调用方式**决定(箭头函数除外)。要彻底理解,得往下挖到规范的 `this` 求值机制和三种 `thisMode`。

---

## 一、四大绑定规则(一图)

```mermaid
flowchart TD
    A[函数被调用] --> B{调用方式?}
    B -->|new Foo()| C[new 绑定 → 新对象]
    B -->|call / apply / bind| D[显式绑定 → 指定对象]
    B -->|obj.foo()| E[隐式绑定 → obj]
    B -->|裸调用 foo()| F[默认绑定 → 全局/undefined]
```

### 1. 默认绑定 | 2. 隐式绑定 | 3. 显式绑定 | 4. new 绑定

```js
function foo() { console.log(this); }
foo();                            // 默认:window / undefined(严格)

const obj = { name: "王", say() { console.log(this.name); } };
obj.say();                        // 隐式:"王"

function greet(g) { console.log(g + this.name); }
greet.call({ name: "北" }, "hi "); // 显式:"hi 北"

function P(n) { this.name = n; }
new P("王");                      // new:新对象
```

**经典的 this 丢失:** 方法赋值给变量后再裸调用,变成默认绑定。

```js
const fn = obj.say;
fn(); // undefined
```

---

## 二、优先级

> **new > 显式绑定 > 隐式绑定 > 默认绑定**

---

## 三、底层机制:this 是怎么"算"出来的(规范视角)

### 1. Reference Record

`obj.foo()` 这种调用,会先求值出成员表达式 `obj.foo`,它产出一个 **Reference**(引用记录):

```
{ base: obj, referencedName: "foo" }
```

**函数调用的 `this` 就取这个 Reference 的 `base` 值**。所以:

- `obj.foo()` → base 是 `obj` → this=obj(隐式绑定)
- `foo()` → 没有 base(是环境引用)→ 走默认绑定
- `const f = obj.foo; f();` → `f` 这个标识符的 base 是环境(不是 obj)→ this 丢了

> 这就是"为什么 `const fn = obj.say` 会丢 this"的规范级答案:**this 绑定在"调用那一刻"由 base 决定,赋值过程不携带这个 base。**

### 2. 三种 thisMode

| thisMode | 含义 |
|----------|------|
| `sloppy`(非严格) | `undefined`/`null` 的 this 被改造成 `globalThis` |
| `strict` | this 原样传入(裸调用就是 undefined) |
| `lexical` | 箭头函数:this 从**外层作用域**捕获 |

```js
function sloppy() { return this; }
sloppy(); // window(undefined 被改造)

function strict() { "use strict"; return this; }
strict(); // undefined(原样)
```

## 四、箭头函数:lexical this

箭头函数**没有自己的 this**(thisMode = lexical),捕获**定义时外层作用域**的 this,且**无法被 call/apply/bind 改变**。

```js
const obj = {
  name: "王",
  say() {
    setTimeout(() => console.log(this.name), 0); // "王"
  },
  sayWrong() {
    setTimeout(function () { console.log(this.name); }, 0); // undefined
  },
};
```

**为什么这样设计?** 回调/定时器/事件处理器里,普通函数的 this 会因"裸调用"丢失(变成全局),开发者得天天 `const self = this` 或 `bind(this)`。箭头函数用**词法 this** 从定义处"锁死",正好解决这个高频痛点——这是它被 React/Vue 回调广泛采用的根因。

## 五、bind 的实现原理(柯里化 + 函数式)

```js
Function.prototype.myBind = function (ctx, ...args) {
  const self = this;
  return function (...rest) {
    // 兼容 new:被 new 调用时 this 是新对象(优先级 new > 显式)
    return self.apply(this instanceof self ? this : ctx, args.concat(rest));
  };
};
```

> bind = "**固定 this + 预置参数(柯里化)**"返回新函数,`args.concat(rest)` 就是参数预置的本质。

## 六、小结

```
this 绑定:默认 / 隐式(obj.foo,this=base)/ 显式(call/apply/bind)/ new
底层:Reference.base 决定 this;赋值剥离 base → this 丢失
thisMode:sloppy(undefined→global)/ strict(原样)/ lexical(箭头捕获外层)
箭头函数:无 this,不可被 bind 改;bind = 固定 this + 柯里化
```

## 七、面试题

**Q1:下面输出什么?**

```js
const length = 10;
function fn() { console.log(this.length); }
const obj = { length: 5, method(fn) { fn(); arguments[0](); } };
obj.method(fn, 1);
// 10, 2(fn() 默认→window.length=10;arguments[0]() 隐式→arguments.length=实参2)
```

**Q2:手写 `call` / `bind`?**

```js
Function.prototype.myCall = function (ctx, ...args) {
  ctx = ctx ?? globalThis;
  const fn = Symbol("fn");
  ctx[fn] = this;
  const res = ctx[fn](...args);
  delete ctx[fn];
  return res;
};
// myBind 见第五节
```

**Q3:为什么"箭头函数不能用 new"?**

箭头函数 thisMode = lexical,**没有自己的 `this` 和 `prototype`**,而 `new` 需要"能指向新对象"的 this 与 prototype 来绑定实例。所以 `new` 箭头函数直接报错。

**Q4:为什么 `const fn = obj.say; fn()` 里 this 丢了?规范层面解释?**

赋值后 `fn` 是独立标识符,调用时它产出的 Reference 没有 `base`(base 是环境而非 obj),this 取不到 obj → 走默认绑定。也就是说 **this 在"调用那一刻"由 base 决定,与赋值来源无关**。

**Q5:如何让"对象方法里嵌套的普通函数"拿到外层 this?三种方式**

```js
const obj = {
  name: "王",
  say() {
    setTimeout(function () { console.log(this.name); }.bind(this), 0); // ① bind
  },
  say2() {
    const self = this;                                            // ② 保存引用
    setTimeout(function () { console.log(self.name); }, 0);
  },
  say3() {
    setTimeout(() => console.log(this.name), 0);                 // ③ 箭头函数(推荐)
  },
};
```

**Q6:`bind` 之后的函数还能被 `new` 吗?this 指向谁?**

能。`new` 优先级高于显式绑定,所以 `new (fn.bind(obj))()` 时 `this` 是**新创建的对象**(bind 的 obj 被忽略)——这正是 `myBind` 里 `this instanceof self ? this : ctx` 那行要处理的情况。
