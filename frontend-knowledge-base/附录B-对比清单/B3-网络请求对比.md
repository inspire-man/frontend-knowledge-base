# B3 网络请求对比

> 附录 B · 对比清单

## 总对比表

| | XHR | Fetch | axios | SSE | WebSocket |
|---|-----|-------|-------|-----|-----------|
| 形态 | 事件回调 | Promise(流式) | Promise(封装) | 事件流 | 事件 |
| 方向 | 请求-响应 | 请求-响应 | 请求-响应 | 服务端→客户端 | **双向** |
| 进度监控 | ✅ | ❌ | ✅(上传/下载) | — | — |
| 中止 | `abort()` | AbortController | AbortController/CancelToken | 关闭 | close |
| 拦截器 | ❌ | ❌ | ✅ | ❌ | ❌ |
| 底层 | 原生 | 原生 | 基于 XHR(浏览器) | HTTP 长连接 | ws 协议 |
| 场景 | 老代码/需进度 | 轻量原生 | 统一配置/拦截 | 单向推送 | 实时双向 |

---

## 关键差异(底层)

- **XHR**:事件模型,能监控上传/下载进度,但 API 啰嗦、已停更
- **Fetch**:Promise + **流式**(收到响应头即 resolve,body 需再读),现代标准
- **axios**:在 XHR 之上封装**拦截器、取消、统一配置**,非原生
- **SSE**:基于 HTTP 的**单向**推送(`text/event-stream`),原生 `EventSource`
- **WebSocket**:独立 `ws` 协议,**双向**长连接,先 HTTP 升级

---

## 选型建议

- 简单请求、轻量 → **Fetch**
- 要拦截器/统一 token/超时/进度 → **axios**
- 服务端单向推送(行情/通知) → **SSE**
- 实时双向(聊天/协作/游戏) → **WebSocket**

> 一句话:**Fetch 原生轻量、axios 工程化、SSE 单向推、WebSocket 双向**。
