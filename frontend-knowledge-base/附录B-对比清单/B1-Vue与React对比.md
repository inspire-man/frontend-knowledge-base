# B1 Vue vs React

> 附录 B · 对比清单

---

## 总对比表

| 维度 | Vue 3 | React 18+ |
|------|-------|-----------|
| 响应式 | `Proxy` 依赖收集(自动) | `setState` + 不可变数据(手动触发) |
| 渲染 | 模板编译 + VNode + Diff(编译期优化) | JSX + Fiber(可中断调度) |
| 数据流 | 双向绑定(`v-model`,框架内隐式) | 单向数据流(回调上抛,显式) |
| 更新粒度 | 组件级(依赖收集精准) | 组件级(自上而下重渲,靠 memo 优化) |
| 编译优化 | 静态提升/patchFlag/Block Tree/Vapor | React Compiler(自动 memo) |
| 状态管理 | Pinia | Redux / Zustand |
| SSR | Nuxt | Next.js |
| 类型支持 | 好(TS 内置) | 好 |
| 心智 | 模板 + 指令,上手快 | JSX + Hooks,更"函数式" |
| 生态 | 官方全家桶(路由/Pinia) | 社区生态庞大 |

---

## 各自优劣

**Vue:**
- ✅ 上手快、模板直观、官方全家桶统一、响应式自动追踪(少写优化)
- ⚠️ 双向绑定在复杂状态流时隐式,`v-model` 语法糖多

**React:**
- ✅ 函数式/声明式纯粹、生态最庞大、可中断并发调度(大数据场景更强)、社区方案丰富
- ⚠️ 需要自己管理性能(memo/useMemo/useCallback)、Hooks 规则与闭包陷阱有门槛

---

## 底层差异(一句话)

> **Vue 用「响应式 + 编译期优化」把 Diff 工作前移;React 用「不可变数据 + 运行时调度(Fiber)」把渲染做可中断。** 殊途同归,都为了"渲染不卡交互",只是路径不同。

---

## 选型建议

- **中小项目 / 团队偏模板 / 求上手快** → Vue 3
- **大型应用 / 团队函数式背景 / 求生态广度** → React
- 两者都能胜任绝大多数场景,选**团队更熟的那个**最重要。

---

## 深入思考

1. **设计哲学**:Vue 偏"渐进式 + 模板直观",React 偏"函数式 + 最小 API 内核"。这不是优劣,是取舍——Vue 把更多约定放进框架,React 把选择权交给生态。
2. **性能模型**:Vue 依赖收集到"属性级"精准更新,React 默认"组件级"自上而下重渲。所以:响应式精准更新 Vue 更省心;"先响应交互再渲染大数据"的并发场景,React 的可中断调度更强。
3. **团队/招聘**:React 生态更大、人才池更广;Vue 上手更快、团队内一致性更高。
4. **真正的决策点**:两者都能做几乎所有事,选型应看"团队现有能力 + 长期维护",而非追逐某一方的新特性。
