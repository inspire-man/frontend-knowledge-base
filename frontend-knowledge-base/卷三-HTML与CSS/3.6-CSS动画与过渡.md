## 引言:过渡是"两状态之间",动画是"多状态编排"

CSS 动效的两大支柱:`transition`(过渡)与 `animation`(动画)。前者靠"状态变化"触发,后者靠 `@keyframes` 主动编排。配合卷二的合成层知识,才能既好看又不卡。

---

## 一、Transition:过渡

### 1. 四要素

```css
.box {
  transition: transform .3s ease .1s;
  /*          属性      时长 缓动 延迟 */
}
.box:hover { transform: scale(1.2); }
```

- **属性**:要过渡的 CSS 属性(可 `all`,但别滥用)
- **时长**:`0.3s` / `300ms`
- **缓动 ease**:`ease` / `linear` / `ease-in-out` / `cubic-bezier(...)`
- **延迟**:延迟多久开始

### 2. 触发条件

必须**状态发生改变**(`:hover`、`class` 变化、JS 改样式),过渡才会发生。页面刚加载时若无状态变化,不会自动动画。

### 3. 不是所有属性都能"顺滑过渡"

能过渡:数值型、颜色、`transform`、`opacity`…;不能/不建议:`display`(突然消失)、`height: auto`(无确定值)。

```css
/* ❌ display 无法过渡,元素会"秒消失" */
/* ✅ 用 opacity + visibility 组合替代 */
.item { opacity: 0; visibility: hidden; transition: opacity .3s; }
.item.show { opacity: 1; visibility: visible; }
```

## 二、Animation:动画

### 1. 基本结构

```css
.box {
  animation: bounce 1s ease-in-out 2s infinite alternate;
  /*        名称    时长  缓动       延迟 次数  方向 */
}
@keyframes bounce {
  0%   { transform: translateY(0); }
  50%  { transform: translateY(-20px); }
  100% { transform: translateY(0); }
}
```

| 属性 | 说明 |
|------|------|
| `animation-name/duration` | 名称/时长(必填) |
| `animation-timing-function` | 缓动 |
| `animation-delay` | 延迟 |
| `animation-iteration-count` | 次数(可 `infinite`) |
| `animation-direction` | `normal/reverse/alternate`(往返) |
| `animation-fill-mode` | `forwards`:结束后停在最后一帧 |

### 2. `fill-mode: forwards` 的坑(高频)

动画结束默认**回退到原始样式**(不保留最后一帧);要停住,加 `forwards`:

```css
.box { animation: fadeIn .5s forwards; }
```

### 3. Transition vs Animation 区别(高频)

| | Transition | Animation |
|---|-----------|-----------|
| 触发 | 需状态变化(被动) | 自动/靠 keyframes 编排(主动) |
| 复杂度 | 两状态间 | 多帧多状态 |
| 循环 | 不支持 | 支持 `infinite`/`alternate` |
| 适用 | 简单悬停/显隐 | 复杂循环动画、入场序列 |

## 三、性能:只动 transform / opacity(呼应卷二)

动画里改 `left/top/width` 会**触发重排**,卡;改 `transform/opacity` 只在**合成线程**完成,丝滑:

```css
/* ❌ 帧帧重排 */
@keyframes bad { from { left: 0; } to { left: 100px; } }
/* ✅ 合成层动画 */
@keyframes good { from { transform: translateX(0); } to { transform: translateX(100px); } }
```

配套:`will-change: transform` 预告提升合成层(但用完移除,防层爆炸,见 2.5)。

## 四、FLIP 技巧(进阶)

**First-Last-Invert-Play**:对"布局属性(如位置/尺寸)的变化"也能做出 60fps 动画:

```
F 记录起始(First)
L 让布局先变到位,记录结束(Last)
I 计算差值,用 transform 从"反方向"拉回来(Invert)
P 再播放 transform 到 0(Play)
```

> 精髓:**用 transform 去"演"布局变化**,既保留 layout 语义,又享受合成层性能。适合列表增删、拖拽排序。

## 五、小结

```
Transition:四要素(属性/时长/缓动/延迟),靠状态变化触发,两状态之间
Animation:@keyframes 多帧编排,可循环/往返/停末帧(forwards)

性能铁律:只动画 transform/opacity(合成层),避免 left/top/width(重排)
FLIP:把布局变化转成 transform 动画,兼顾语义与流畅
```

## 六、面试题

**Q1:如何让"点击后元素淡入并停在最终态"?**

```css
.el { opacity: 0; }
.el.show {
  animation: fadeIn .5s forwards;  /* forwards 停在末帧 */
}
@keyframes fadeIn { from { opacity: 0; } to { opacity: 1; } }
```

**Q2:为什么 CSS 动画比 JS 动画(改 style)更流畅?至少说两点**

① CSS 动画可用 `transform/opacity` 走合成线程/GPU,**不触发布局**(JS 直接改 `left` 会重排);② 浏览器能对 CSS 动画做**独立于主线程**的调度与优化,主线程卡了动画仍可能继续(尤其合成属性),而 JS 动画依赖主线程 tick。

**Q3:`display: none` 的元素能过渡吗?替代方案?**

不能——`display` 是离散属性,无法中间态过渡,且 `none` 时元素不渲染。替代:用 `opacity + visibility`(保留过渡,见上文)或 `@starting-style`(现代支持 `display:none` 的过渡)。
