# 3.6 CSS 动画与过渡

> 卷:卷三 · HTML 与 CSS
> 阅读时间:25min

---

## 引言:过渡是"两状态间",动画是"多状态编排"

两大支柱:`transition`(状态变化触发)与 `animation`(`@keyframes` 主动编排)。深挖要懂**触发条件**、**Web Animations API**、以及**运行时性能与无障碍**(prefers-reduced-motion)。

---

## 一、Transition vs Animation

```mermaid
flowchart LR
    A[CSS 动效] --> B[transition<br/>被动:状态变化触发,两状态间]
    A --> C[animation<br/>主动:@keyframes 编排,多帧可循环]
```

| | Transition | Animation |
|---|-----------|-----------|
| 触发 | 被动(状态变化) | 主动(keyframes) |
| 复杂度 | 两状态 | 多帧 |
| 循环 | 不支持 | infinite/alternate |

---

## 二、Transition:四要素 + 触发条件

```css
.box { transition: transform .3s ease .1s; }
.box:hover { transform: scale(1.2); }
```

- 四要素:属性 / 时长 / 缓动(`ease`/`linear`/`cubic-bezier`)/ 延迟

**触发条件(底层):必须同时满足**

1. 属性在**可过渡列表**里(`color`/`transform`/`opacity` 等数值型)
2. 值**真的变了**(从 A 到 B)
3. 元素**可见且非 `display:none`**

> `display:none→block`、`height:auto` 都不可过渡;用 `opacity + visibility` 或现代 `@starting-style` 替代。

---

## 三、Animation:多帧编排

```css
.box { animation: bounce 1s ease-in-out infinite alternate; }
@keyframes bounce {
  0% { transform: translateY(0); }
  50% { transform: translateY(-20px); }
  100% { transform: translateY(0); }
}
```

| 属性 | 说明 |
|------|------|
| `animation-fill-mode: forwards` | 停末帧 |
| `animation-direction: alternate` | 往返 |
| `animation-iteration-count: infinite` | 无限 |

---

## 四、深层:Web Animations API(WAAPI)

除了声明式 CSS,还有 **JS 驱动的 WAAPI**,能动态控制、暂停、读取状态:

```js
const anim = el.animate(
  [{ transform: "translateX(0)" }, { transform: "translateX(100px)" }],
  { duration: 300, easing: "ease", fill: "forwards" }
);
anim.pause();      // 暂停
anim.play();       // 播放
anim.finished.then(() => console.log("done"));  // Promise 化
```

> WAAPI 底层与 CSS 动画**同一套合成引擎**(同样享受合成层优化),但提供 JS 的控制力与 Promise 接口——适合动画序列编排、手势跟随。

## 五、性能与无障碍

### 1. 只动 transform/opacity(合成层,2.5)

```css
@keyframes good { from { transform: translateX(0); } to { transform: translateX(100px); } }
/* 避免 left/top/width(重排) */
```

### 2. `prefers-reduced-motion`(无障碍)

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

> 尊重"减少动态效果"系统偏好(前庭功能障碍用户),是动效的 a11y 底线。

---

**View Transitions API(视图过渡,Chrome 111+):**

`document.startViewTransition()` 让页面/元素切换有原生过渡——**截图旧页 → 执行 DOM 变更 → 截图新页 → 自动 crossfade 补间**,无需 JS 库:

```js
document.startViewTransition(() => updateDOM(url));
```

> SPA 路由切换、列表增删、主题切换都可用;配合 `::view-transition-old/new` 伪元素自定义动画。

**CSS Houdini(底层渲染扩展):**

W3C 把浏览器**渲染流水线(布局/绘制/合成)开放给开发者**,用 JS worklet 扩展 CSS:

- **Paint API**:`registerPaint` 自定义绘制(不规则背景/图案)
- **Typed OM**:类型化的 CSSOM,读写更快
- **Layout API**:自定义布局引擎(数据大屏、低代码)

> 意义:突破 Flex/Grid 固有限制,worklet 不阻塞主线程,做高度定制化渲染。

## 六、小结

```
Transition:四要素,被动触发(可过渡+值变化+可见),两状态
Animation:@keyframes 多帧,循环/往返/停末帧
WAAPI:JS 驱动同一合成引擎,暂停/播放/Promise
性能:只动 transform/opacity;无障碍:prefers-reduced-motion
```

## 七、面试题

**Q1:如何让点击后元素淡入并停在最终态?**

```css
.el { opacity: 0; }
.el.show { animation: fadeIn .5s forwards; }
@keyframes fadeIn { from { opacity: 0; } to { opacity: 1; } }
```

**Q2:为什么 CSS 动画比 JS 手动改 style 更流畅?**

① 可用 `transform/opacity` 走合成线程/GPU,**不触发布局**(JS 改 left 重排);② 浏览器能**独立于主线程**调度 CSS 动画(主线程卡也不一定掉帧);③ 声明式由引擎优化,JS 动画依赖主线程 tick。

**Q3:transition 不生效的常见原因?**

① 属性不可过渡(`display`/`height:auto`);② 值没真变;③ 元素 `display:none`;④ 没有"状态变化"触发源(如页面加载即想动画,transition 不触发,得用 animation);⑤ 拼错属性名。

**Q4:`display:none` 能过渡吗?替代方案?**

不能(`display` 离散、`none` 不渲染)。替代:`opacity + visibility` 组合;或现代 `@starting-style` + `transition-behavior: allow-discrete`。

**Q5:什么是 Web Animations API?相比 CSS 动画有何优势?**

WAAPI 是用 JS 驱动动画、但走**同一合成引擎**的 API。优势:可**动态暂停/播放/取消**、`finished` 的 Promise(序列编排)、能读当前状态;适合手势跟随、复杂编排,而 CSS 声明式更简洁适合静态动效。

**Q6:为什么要处理 `prefers-reduced-motion`?**

部分用户(前庭功能障碍)对运动/眩晕敏感。尊重系统的"减少动态"偏好,在媒体查询里关掉或减弱动画,是动效的可访问性底线。
