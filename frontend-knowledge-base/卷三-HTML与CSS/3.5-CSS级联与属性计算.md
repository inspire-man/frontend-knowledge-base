## 引言:一个元素的最终样式到底怎么定

你原有的《CSS 属性计算过程》问的就是:为什么 h1 不写样式也有样式?为什么 a 标签不继承颜色?本章把那条"声明值 → 层叠 → 继承 → 默认值"的计算链讲成体系,并补上 `@layer` 这个现代层叠工具。

---

## 一、总纲:属性计算的四步

> **确定声明值 → 层叠冲突 → 使用继承 → 使用默认值**

- 每个 HTML 元素最终都拥有**一整套完整的 CSS 属性值**(不写的也有,只是"最终哪来的"不同)
- 计算就是**按顺序**解决每个属性"值从哪来"

---

## 二、第一步:确定声明值(Declared Values)

把**所有来源**里对该属性声明的值先收集齐。来源有三(重要性递减):

| 来源 | 谁写的 | 说明 |
|------|--------|------|
| 页面作者样式 | 开发者 | 最常见 |
| 用户样式 | 浏览器用户 | 用户自定义(较少见) |
| 用户代理样式(UA) | 浏览器 | 内置默认样式 |

> 你原文的例子:`h1` 不写样式也有字号/加粗,正是 UA 样式表给了默认值。

---

## 三、第二步:层叠冲突(Cascade)——三比较

声明有冲突时,依次比较:

### 1. 比较源的重要性

`页面作者 > 用户 > 用户代理`(默认)。**但 `!important` 会反转这一层**:

```css
p { color: red !important; }
```

`!important` 的优先级顺序反成:`用户代理 important > 用户 important > 作者 important > 作者普通 > …`

### 2. 比较优先级(Specificity,选择器权重)

同源、同重要性时比"特异性"。计算记法 `(id 数, class/伪类/属性 数, 元素/伪元素 数)`:

```css
#nav a              /* (1,0,1)  */
.nav a:hover        /* (0,2,1)  */
a                   /* (0,0,1)  */
```

比较规则:**从左往右逐位比,先比 id 数,再比 class 数,再比元素数**。特殊:`*` 无权重;`!important` > 行内样式 > 一切常规。

### 3. 比较次序(Source Order)

同源、同重要性、同权重 → **后写的赢**:

```css
h1 { color: red; }
h1 { color: blue; }  /* 后者覆盖前者 */
```

---

## 四、第三步:使用继承(Inheritance)

没被声明的属性,看是否**可继承**:

- **可继承**:文本相关 —— `color`、`font-*`、`line-height`、`text-align`、`visibility`…
- **不可继承**:布局/盒模型 —— `width`、`height`、`margin`、`padding`、`border`、`position`…

**两个细节(你原文强调):**

1. **"就近继承"**:继承只从**最近的祖先**取值,不比较权重(因为根本没选中该元素)
2. **继承优先级很低**:继承值"打不过"任何**直接声明**(哪怕声明很弱),所以:

```css
div { color: red; }
a { }  /* a 在 UA 表里声明了 color → 用 UA 声明,不继承 div 的 red */
```

> 这就是"a 标签不继承父元素颜色"的底层原因:UA 表已声明,继承让位于声明值。可用 `inherit` 强制继承:`a { color: inherit; }`。

---

## 五、第四步:使用默认值(Initial Values)

声明、层叠、继承都拿不到 → 用属性**初始值**(规范里每个属性都有默认值)。

---

## 六、三个特殊关键字(进阶)

```css
div {
  color: inherit;  /* 强制继承父值 */
  color: initial;  /* 用初始值 */
  color: unset;    /* 可继承属性=inherit,不可继承属性=initial */
  color: revert;   /* 回退到"上一层来源"的值(如 UA 默认) */
}
```

---

## 七、`@layer`:层叠层(现代工具)

当样式来源众多(第三方库 + 自己代码),用 `@layer` **人为分组、控制优先级**:

```css
@layer base, components, utilities;

@layer base { h1 { font-size: 2rem; } }
@layer components { .title { font-size: 1.5rem; } }
@layer utilities { .text-lg { font-size: 1.25rem; } }

/* 后声明的层优先级高:utilities > components > base
   从而"工具类能覆盖组件类",又不必依赖 !important */
```

> Tailwind 等原子化框架正是靠 `@layer` 管优先级,让"工具类可预期地覆盖"。

---

## 八、小结

```
属性计算四步(按顺序):
① 确定声明值(收集作者/用户/UA 三来源)
② 层叠冲突:源重要性(!important 反转)→ 优先级(id/class/element)→ 次序(后写赢)
③ 使用继承(仅可继承属性,就近继承,弱于任何声明)
④ 使用默认值(初始值)

工具:@layer 分组控优先级;inherit/initial/unset/revert 显式指定
```

## 九、面试题

**Q1:计算 `#nav .item a:hover` 的优先级?**

```js
// id:#nav → (1, ...)
// class:.item + :hover → (2, ...)
// element:a → (1)
// = (1, 2, 1),即 "1 个 id,2 个类/伪类,1 个元素"
```

**Q2:下面 `p` 文字最终什么颜色?为什么?**

```html
<div style="color: red"><p>text</p></div>
```

<details>
<summary>答案</summary>

```js
// 红色。p 未声明 color,color 可继承 → 从最近的 div 继承 red。
// 若 p 是 <a>,则因 UA 表给 a 声明了 color,继承让位 → 是浏览器默认的链接蓝。
```
</details>

**Q3:`!important` 和 `@layer` 谁更能"压住"对方?**

`!important` 仍是最高优先级的"王炸",连 `@layer` 也压不住;但 `@layer` 的价值是**让你不再需要** `!important` 就能预测覆盖次序。规范中 `important` 的层叠顺序还会**在层内反转**(不重要声明 vs 重要声明各自倒序),属于进阶细节。
