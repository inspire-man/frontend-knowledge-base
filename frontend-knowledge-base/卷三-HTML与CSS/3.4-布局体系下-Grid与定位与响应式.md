## 引言:二维布局交给 Grid,定位交给 position,适配交给查询

如果说 Flex 是"一维(单行/单列)神器",Grid 就是"二维(行列网格)之神"。本章补齐剩下的三块拼图,并讲清现代响应式的 `clamp` 与容器查询。

## 一、Grid:二维网格布局

### 1. 核心概念

```css
.grid {
  display: grid;
  grid-template-columns: 200px 1fr 1fr;  /* 三列:固定 + 等分 + 等分 */
  grid-template-rows: auto 100px;
  gap: 16px;                             /* 行列间距 */
}
```

- `1fr`:fr 单位 = **剩余空间的一份**,`1fr 1fr` 即均分
- `repeat(3, 1fr)`:重复生成三列
- `minmax(200px, 1fr)`:最小 200px、最大 1fr

### 2. 定位到格子

```css
.item {
  grid-column: 1 / 3;     /* 从第 1 列线到第 3 列线,占两列 */
  grid-row: 2 / 4;
  /* 或用命名区域 */
}
```

### 3. 对齐

```css
justify-items / align-items   /* 项目在格内对齐 */
justify-content / align-content /* 整个网格在容器内对齐 */
```

> 经典布局(圣杯/双飞翼)用 Grid 几行搞定:侧边栏 + 主内容 + 侧边栏,`grid-template-columns: 200px 1fr 240px`。

## 二、Flex vs Grid:怎么选

| 维度 | Flex | Grid |
|------|------|------|
| 布局维度 | **一维**(单行或单列) | **二维**(行列同时) |
| 适合 | 导航栏、工具条、行内对齐、卡片内元素排列 | 整体页面骨架、卡片网格、行列对齐的复杂布局 |
| 口诀 | 内容**推动**尺寸(先内容后排布) | 先定**网格框架**,内容往格里填 |

> 实战经验:页面大骨架用 Grid,局部一行内几个元素用 Flex,两者可嵌套。

## 三、定位体系(position 五值)

| 值 | 参照物(包含块) | 是否脱离文档流 | 典型场景 |
|----|---------------|---------------|---------|
| `static` | 常规流 | 否(默认) | 默认 |
| `relative` | 自身原位置 | 否(占位保留) | 微调偏移,给 absolute 做参照 |
| `absolute` | 最近非 static 祖先 | **是** | 弹层、角标 |
| `fixed` | 视口 | **是** | 悬浮按钮、吸顶 |
| `sticky` | 滚动容器 | 否(占位保留) | 吸顶导航、表格表头 |

**`sticky` 的原理(高频):**

```css
.nav { position: sticky; top: 0; }
```

> sticky 是 "relative + fixed" 的混合:常规流中占位,滚动到**阈值(如 top:0)**时"粘"住视口,但**不脱离文档流**,也不会超出父容器边界。

与 fixed 的区别:fixed 相对**视口**且脱离文档流;sticky 相对**最近的滚动容器**,且保留占位。

## 四、响应式设计

### 1. 媒体查询(Media Query)

```css
/* 移动优先:先写小屏,再往上加 */
.card { width: 100%; }
@media (min-width: 768px) { .card { width: 50%; } }
@media (min-width: 1024px) { .card { width: 33.33%; } }
```

### 2. 流式单位 + clamp

```css
html { font-size: 16px; }
.text {
  font-size: clamp(1rem, 2vw + 0.5rem, 1.5rem); /* 最小/弹性/最大 */
}
.wrap { width: min(90%, 1200px); margin: 0 auto; } /* 居中但不超过 1200 */
```

- `vw/vh`:视口单位;`rem`:根字号倍数(好做整体缩放);`clamp/min/max`:**把媒体查询省掉一半**

### 3. 容器查询(Container Query,现代)

媒体查询看的是**视口**,容器查询看的是**父容器**——组件级响应式:

```css
.card-wrap { container-type: inline-size; }  /* 声明为容器 */

@container (min-width: 400px) {
  .card { grid-template-columns: 1fr 1fr; } /* 父容器够宽才两列 */
}
```

> 意义:同一组件丢进侧边栏(窄)和主区(宽),能自动适配,无需关心"整个屏幕多宽"。

## 五、小结

```
Grid(二维):grid-template-columns/rows + fr + minmax + grid-column/row

定位:static(默认)relative(占位,作参照)absolute(脱离,最近非 static 祖先)
     fixed(脱离,视口)sticky(占位+滚动粘附,相对滚动容器)

响应式:
├─ 媒体查询:看视口
├─ clamp/min/max + vw/rem:省掉一半查询
└─ 容器查询 @container:看父容器,组件级自适应
```

## 六、面试题

**Q1:`position: sticky` 为什么"不生效"?常见原因?**

① 未设置 `top/bottom/left/right` 阈值;② 祖先元素 `overflow: hidden/scroll` 会破坏 sticky(它相对滚动容器);③ 父容器高度不足,没有滚动空间可"粘";④ sticky 不脱离文档流,若父容器就是内容高度,自然无从粘附。

**Q2:媒体查询和容器查询的本质区别?**

媒体查询基于**视口(viewport)**尺寸做整页适配;容器查询基于**某个父容器**的尺寸做组件级适配。容器查询让组件"随容器伸缩",更适合构建可复用的组件库。

**Q3:实现"三行等高"布局除了 Grid 还有什么方案?**

Grid(推荐):`grid-auto-rows: 1fr` 或直接行列对齐;Flex:`align-items: stretch`(默认)让同排项目等高;旧方案还有"负 margin + padding 补偿"或 table 布局(已过时)。
