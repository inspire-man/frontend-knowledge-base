# 3.7 CSS 工程化

> 卷:卷三 · HTML 与 CSS
> 难度:⭐⭐ 进阶 | 阅读时间:20min | 状态:进行中

---

## 引言:当 CSS 写着写着就"失控"了

原生 CSS 三大痛点:**全局污染(命名冲突)、无法复用(没变量/函数)、难以维护(选择器地狱)**。工程化就是围绕这三件事给方案。本章从预处理到原子化,理清每条技术路线解决什么问题。

---

## 一、CSS 的三大原生痛点 → 四条路线

| 痛点 | 解决方案路线 |
|------|-------------|
| 命名冲突(全局污染) | CSS Modules、CSS-in-JS、原子化类名、BEM 规范 |
| 无法复用(变量/函数) | 预处理器(Sass/Less)、原生 CSS 变量 |
| 维护难(嵌套/组织) | 预处理器嵌套、`@layer`、Tailwind 按需生成 |
| 兼容性 | PostCSS(autoprefixer、polyfill) |

---

## 二、预处理器:Sass / Less

**Sass(SCSS 语法)** 补上变量、嵌套、mixin、函数:

```scss
// 变量
$primary: #4f46e5;

// 嵌套
.card {
  &:hover { color: $primary; }
  .title { font-weight: bold; }
}

// mixin(复用样式块)
@mixin ellipsis($lines: 1) {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
.text { @include ellipsis(); }

// 函数/循环
@for $i from 1 through 4 { .col-#{$i} { width: $i * 25%; } }
```

**原生 CSS 变量(自定义属性)已能替代部分变量,且支持运行时 + 继承:**

```css
:root { --primary: #4f46e5; }
.btn { background: var(--primary); }
```

> 经验:预处理器解决"**写**"的复用;原生 CSS 变量解决"**运行时**"复用(主题切换、动态改值),两者常配合使用。

## 三、PostCSS:后处理器(与"预"相对)

PostCSS 本身是**通用 AST 转换引擎**,靠插件干实事:

- `autoprefixer`:自动加 `-webkit-`/`-moz-` 前缀
- `postcss-preset-env`:把未来 CSS 语法转译成当前浏览器支持的(`@container`、`clamp` 降级)
- `tailwindcss`:本质就是一个 PostCSS 插件

```js

```

> 记忆:Sass 是"**预**编译"(新语法 → 标准 CSS);PostCSS 是"**后**处理"(标准/未来 CSS → 兼容 CSS),两者不冲突,常同链路出现。

---

## 四、CSS Modules:局部作用域

把 class 名**编译成"文件哈希 + 类名"**,天然避免全局冲突,配合打包器(webpack/Vite 原生支持):

```css
/* Button.module.css */
.primary { color: blue; }
```

```jsx
import styles from "./Button.module.css";
<button className={styles.primary}>…</button>  // 实际类名如 ".Button_primary_1a2b"
```

> 特点:仍是"写类名 + 一条类名映射",心智接近原生 CSS,适合组件库/React。

---

## 五、原子化:Tailwind CSS

不写语义化 class,直接**组合工具类**:

```html
<button class="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600">
  按钮
</button>
```

**优点**:约束在固定设计令牌内、按需生成(只产出用到的 CSS,体积小)、改样不改 CSS 文件。**代价**:HTML 类名很长,学习曲线。

> 它隐式用到两样东西(呼应前文):`@layer` 管优先级(工具类可预期覆盖)、PostCSS 做编译。

---

## 六、CSS-in-JS:样式写进 JS

```jsx
const Button = styled.button`
  padding: 8px 16px;
  background: ${(p) => p.theme.primary};
`;
```

**代表**:styled-components、Emotion(React 生态)。**优点**:样式与组件同源、能用 JS 变量/props 动态算样式、天然局部作用域。**代价**:运行时开销(生成/注入 style)、SSR 需额外配置。现代趋势:运行时 CSS-in-JS 渐冷,转向"零运行时"方案(如 Tailwind、styleX、vanilla-extract)。

---

## 七、选型建议(务实结论)

| 场景 | 推荐 |
|------|------|
| 传统多页/后台,快速上手 | Sass + BEM/规范 |
| React 组件库,要局部作用域 | CSS Modules(或 Tailwind) |
| 快速出 UI、设计令牌统一 | Tailwind + 原生 CSS 变量(主题) |
| 需要运行时动态样式、强 JS 耦合 | CSS-in-JS(谨慎,或选零运行时方案) |

> 没有银弹,核心是把"**命名冲突、复用、维护**"三件事,选自己能长期维护的那条路。

---

## 八、小结

```
CSS 工程化 = 解三痛(命名冲突/复用/维护)

路线:
├─ 预处理器 Sass/Less:变量/嵌套/mixin/函数(写时复用)
├─ 原生 CSS 变量:运行时主题切换、继承
├─ PostCSS:autoprefixer + 未来语法降级
├─ CSS Modules:类名哈希,局部作用域
├─ Tailwind:原子化工具类 + @layer + 按需生成
└─ CSS-in-JS:样式进 JS,动态但可能运行时开销
```

## 九、面试题

**Q1:CSS Modules 和普通 CSS 的区别?它解决什么?**

普通 CSS 类名**全局共享**,易冲突。CSS Modules 在构建时把类名**哈希化**(`Button_primary_1a2b`),实现**局部作用域**,组件间同名 class 也不冲突;同时保留"写类名"的原生心智。

**Q2:原生 CSS 变量和 Sass 变量的本质区别?**

Sass 变量在**编译期**被替换成固定值,运行时不参与(不能 JS 动态改、不支持运行时主题)。原生 CSS 变量是**运行时**真实存在的值,支持**继承、级联、JS 读写**(`getPropertyValue`/`setProperty`),所以能实现动态换肤。

**Q3:PostCSS 是预处理器吗?**

不是。PostCSS 是**通用 CSS 解析/转换引擎**(把 CSS 转 AST 再处理),预处理(Sass)和后处理(autoprefixer/preset-env)都能基于或配合它。Tailwind 本身就是一个 PostCSS 插件。
