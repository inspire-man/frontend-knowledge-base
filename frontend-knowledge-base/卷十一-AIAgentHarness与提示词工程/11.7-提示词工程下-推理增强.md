## 引言:让模型"想清楚再答"

上一章解决"**说清楚要什么**",这一章解决"**让模型答得更对**"——核心是诱导模型**显式推理**,而不是直接蹦答案。

---

## 一、思维链(CoT,Chain of Thought)

**让模型把推理步骤写出来**,复杂任务正确率显著提升:

```markdown
问题:一个篮子里有 3 个苹果,又放进 2 个,再拿走 1 个,剩几个?
请一步步推理:
1. 初始 3 个
2. 放入 2 个 → 5 个
3. 拿走 1 个 → 4 个
答案:4 个
```

**为什么有效?**

> 自回归模型一次只能预测"下一个 token"。直接要答案,等于让它在**一步之内**算出复杂推理;而 CoT 把推理拆成**一串 token**,每一步都只做一小步——难度被摊薄,中间步骤还能自我纠错。

**触发方式:**

- **Zero-shot CoT**:加一句"让我们一步步思考"(Let's think step by step)
- **Few-shot CoT**:示例里就展示"推理 + 答案"的完整过程

## 二、自我一致性(Self-Consistency)

**同一个问题采样多次,取"多数投票"的结果:**

```python
answers = [model.ask(q, temperature=0.7) for _ in range(5)]  # 采样 5 次
final = majority_vote(answers)
```

> 原理:推理题单次可能"想歪",但**多次独立采样**,正确路径更容易成为多数。适合有唯一正确答案的推理任务(数学、逻辑、选择题)。

---

## 三、思维树(ToT,Tree of Thoughts)

比 CoT 更进一层:**不只走一条推理链,而是同时展开多条、评估、回溯**:

```
        问题
       /  |  \
    思路A 思路B 思路C     ← 同时探索多条
      |    |    |
    评估  评估  评估      ← 各自打分
      |         |
    剪枝      深入(选最优分支继续)
```

> ToT 适合"**解空间大、需要搜索**"的任务(下棋、规划、谜题)。工程上常简化为"多候选 + 打分选优"。

---

## 四、ReAct:把推理接上工具(回到主线)

11.2 的 ReAct 是"推理增强 + 工具调用"的合体:推理(Thought)之后**接一个真实动作(Action)**,而非只在脑子里想。

```markdown
Question: 2024 年诺贝尔物理学奖得主是谁?
Thought: 我不知道最新消息,需要查。→ 调用 search("2024 诺贝尔物理奖")
Observation: 霍普菲尔德、辛顿
Thought: 拿到答案,总结。
Answer: 约翰·霍普菲尔德 和 杰弗里·辛顿
```

> **为什么 ReAct 比纯 CoT 强?** 纯 CoT 只能"靠脑内知识推",知识截止或记错就错;ReAct 让模型**用工具去拿事实**,把"推理"和"查证"结合——这正是 Agent 优于聊天模型的根本(呼应 11.1 的"事实靠工具锚定")。

## 六、小结

```
CoT:显式写推理步骤,摊薄单步难度(零样本/少样本触发)
自我一致:多次采样 + 多数投票(唯一答案题)
ToT:多分支探索 + 评估回溯(解空间大的搜索题)
ReAct:推理接工具,用事实锚定推理(Agent 核心)
```

## 七、思考题

**Q1:CoT 为什么能提升复杂推理的正确率?**

因为它把"一步到位算出答案"拆成**一串小步 token**,每步只做一小步推理、难度摊薄;且中间步骤写进上下文,模型能**看到并纠正**前面的偏差。自回归的"下一步预测"天然适合这种逐步展开。

**Q2:什么时候该用 ReAct 而不是纯 CoT?**

当任务**依赖外部事实或需要真实动作**时(查最新信息、调用工具、执行代码、逐步验证),用 ReAct;纯 CoT 只适合"**不依赖外部、纯靠脑内推理**"的题(数学、逻辑)。一旦需要"碰世界",就必须 ReAct——事实靠工具拿,而不是靠模型记。
