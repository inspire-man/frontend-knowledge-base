# 11.7 提示词工程(下):推理增强(CoT / ToT / ReAct / 自我一致)

## 引言:让模型"想清楚再答"

上半部分解决"说清楚要什么",这一章解决"让模型答得更对"——核心是诱导模型**显式推理**,而非直接蹦答案。

---

## 一、思维链(CoT)

```markdown
问题:3 个苹果放进 2 个,再拿走 1 个,剩几个?
请一步步推理:
1. 初始 3 → 2. 放入 2 → 5 → 3. 拿走 1 → 4
答案:4 个
```

**为什么有效?** 自回归一次只预测"下一个 token"。直接要答案=一步之内算复杂推理;CoT 把推理拆成**一串 token**,每步只做一小步,难度摊薄、中间步骤还能自我纠错。

**触发**:Zero-shot CoT("让我们一步步思考")或 Few-shot CoT(示例里展示推理+答案)。

---

## 二、自我一致性(Self-Consistency)

```python
answers = [model.ask(q, temperature=0.7) for _ in range(5)]
final = majority_vote(answers)
```

> 原理:推理题单次可能想歪,但**多次独立采样**,正确路径更易成为多数。适合有唯一答案的推理题(数学/逻辑)。

---

## 三、思维树(ToT)

不只走一条推理链,而是**同时展开多条、评估、回溯**:

```
问题 → 思路A/B/C(并行)→ 各自评估打分 → 剪枝 → 深入最优分支
```

> 适合"解空间大、需要搜索"的任务(下棋/规划/谜题)。工程上常简化为"多候选 + 打分选优"。

---

## 四、ReAct:推理接工具(回到主线)

```markdown
Question: 2024 诺贝尔物理奖得主?
Thought: 不知道最新消息,需要查 → search("2024 诺贝尔物理奖")
Observation: 霍普菲尔德、辛顿
Answer: 约翰·霍普菲尔德 和 杰弗里·辛顿
```

> **ReAct 比纯 CoT 强**:纯 CoT 靠脑内知识推,知识截止/记错就错;ReAct 用工具拿事实,把"推理"和"查证"结合——Agent 优于聊天模型的根本(呼应 [11.1](/卷十一-AIAgentHarness与提示词工程/11.1-从LLM到Agent底层心智))。

---

## 五、小结

```
CoT:显式写推理,摊薄单步难度;自我一致:多次采样+多数投票;ToT:多分支搜索;ReAct:推理接工具
```

---

## 六、思考题

**Q1:CoT 为什么能提升复杂推理正确率?**

把"一步到位算答案"拆成**一串小步 token**,每步只做一小步、难度摊薄;中间步骤写进上下文,模型能**看到并纠正**前面的偏差。自回归的"下一步预测"天然适合逐步展开。

**Q2:什么时候用 ReAct 而非纯 CoT?**

任务**依赖外部事实或需真实动作**时(查最新信息、调工具、执行代码),用 ReAct;纯 CoT 只适合"不依赖外部、纯靠脑内推理"的题(数学/逻辑)。需"碰世界"就必须 ReAct。

**Q3:什么是"自我一致性(Self-Consistency)"?什么时候用?**

同一问题**采样多次、取多数投票**。适合"有唯一正确答案"的推理题(数学/逻辑),多次采样时正确路径更易成多数。

**Q4:ToT 和 CoT 的区别?什么时候用 ToT?**

CoT 走**一条**推理链;ToT **同时展开多条、评估、回溯**,解空间大时搜索最优。适合下棋/规划/谜题;普通推理题 CoT 就够。

**Q5:zero-shot CoT 怎么触发?**

加一句"让我们一步步思考(Let's think step by step)",诱导模型显式写出推理步骤,无需示例即可提升复杂推理。

**Q6:ReAct 为什么比纯 CoT 强?**

纯 CoT 只靠脑内知识推,知识过时/记错就错;ReAct 在 Thought 后接 **Action 调工具拿事实**,把"推理"与"查证"结合——事实靠工具锚定,而非靠模型记(呼应 [11.1](/卷十一-AIAgentHarness与提示词工程/11.1-从LLM到Agent底层心智))。
