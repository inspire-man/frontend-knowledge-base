# A4 手写深拷贝 / 并发控制 pLimit

> 附录 A · 手写系列
> 思路:深拷贝 = 递归 + 类型判断 + WeakMap 处理循环引用;pLimit = 任务队列 + 并发计数。

---

## 一、深拷贝(处理循环引用 + 常见类型)

```js
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== "object") return obj;   // 原始值直接返回

  if (map.has(obj)) return map.get(obj);                     // 循环引用:返回已克隆的
  const target = Array.isArray(obj) ? [] : {};
  map.set(obj, target);                                       // 先登记,再递归(关键!)

  for (const key of Reflect.ownKeys(obj)) {                   // 含 Symbol 键
    target[key] = deepClone(obj[key], map);
  }
  return target;
}
```

**为什么用 WeakMap 处理循环引用?** 先 `map.set(obj, target)` 再递归——当子对象引用回父对象时,`map.has(obj)` 命中,直接返回已建的 target,避免无限递归;WeakMap 弱引用不阻止 GC。

**JSON 法 vs 手写(对比):**

| | JSON.parse(JSON.stringify) | 手写 deepClone |
|---|---------------------------|---------------|
| 循环引用 | ❌ 报错 | ✅ WeakMap 处理 |
| 函数/undefined | ❌ 丢失 | ✅ 保留 |
| Date/Map/Set | ❌ 变字符串/丢 | ✅ 需额外判断 |
| 性能 | 快(原生) | 慢(递归) |

> 完整版(支持 Date/Map/Set/RegExp)需额外 `Object.prototype.toString` 判断 + 分类型克隆,面试一般考到"循环引用 + 数组"即可。

## 二、并发控制 pLimit(限流)

```js
async function pLimit(tasks, limit) {
  const queue = [...tasks];                     // 任务队列
  const workers = Array.from({ length: limit }, async () => {
    while (queue.length) {
      const task = queue.shift();
      await task();                             // 执行完一个,再取下一个
    }
  });
  await Promise.all(workers);                   // 等所有 worker 跑完
}
```

**原理**:`limit` 个 worker 并发消费同一个队列,每个 worker 完成一个任务才取下一个——并发数被限制在 `limit`。

**返回结果版(保留顺序):**

```js
async function pLimit(tasks, limit) {
  const result = new Array(tasks.length);
  let idx = 0;                                  // 当前取到第几个任务
  const worker = async () => {
    while (idx < tasks.length) {
      const i = idx++;                          // 原子地取下标(先取值再自增)
      result[i] = await tasks[i]();
    }
  };
  await Promise.all(Array.from({ length: Math.min(limit, tasks.length) }, worker));
  return result;
}
```

> 关键:`idx++` 保证每个任务只被一个 worker 领取;`result[i]` 按原下标写,顺序不乱。

---

## 三、易错点

1. **深拷贝忘先登记再递归**:会死循环(循环引用)
2. **只处理对象/数组**:Date/Map/Set 会被 `{}` 克隆成空对象,需分类型
3. **pLimit 的 idx 竞争**:JS 单线程,`idx++` 是同步原子操作,不会并发冲突
4. **limit 大于任务数**:worker 数应 `Math.min(limit, tasks.length)`

## 四、自测

```js
const a = { x: 1, list: [1, 2] };
a.self = a;                       // 循环引用
const b = deepClone(a);
console.log(b.self === b);        // true(正确处理循环引用)

pLimit([() => Promise.resolve(1), () => Promise.resolve(2), () => Promise.resolve(3)], 2)
  .then((r) => console.log(r));   // [1, 2, 3]
```
