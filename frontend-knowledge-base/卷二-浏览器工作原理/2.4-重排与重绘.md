# 2.4 重排(Reflow)与重绘(Repaint)

> 卷:卷二 · 浏览器工作原理
> 难度:⭐⭐ 进阶(性能高频) | 阅读时间:20min | 状态:进行中

---

## 引言:改一行 CSS,浏览器要重跑多远的流水线

"重排/重绘"是前端性能优化的核心概念。核心结论一句话:**重排代价远大于重绘**,优化就是"让改动尽量只停在流水线的最末端"(合成),别往回倒带。

---

## 一、什么是 Reflow(重排)与 Repaint(重绘)

| | 重排 Reflow | 重绘 Repaint |
|---|-------------|--------------|
| 英文 | 也叫 Layout | Repaint |
| 触发 | 改变**几何信息**(位置/尺寸) | 只改变**外观**(颜色/可见性等) |
| 代价 | **高**:重新走「样式→布局→绘制→光栅→合成」 | 相对低:只重走「绘制→光栅→合成」 |

**铁律:`reflow 一定会 repaint`,反之不一定。**(几何变了,像素必然新画;但改颜色只 repaint 不 reflow)

---

## 二、什么会触发重排

**改几何/结构相关:**

```css
width / height / padding / margin / border
top / left / right / bottom / position
font-size / line-height / text-align
display / float / overflow       /* 影响布局 */
```

**JS 操作:**

```js
document.body.appendChild(el);   // 增删节点
el.classList.add('big');          // 改 class 触发样式重算
window.resize();                  // 视口变化
```

**⚠️ 最常见陷阱:读"布局属性"会强制同步重排(强制回流)**

```js
el.style.width = '100px';   // 写,标记布局"脏"
el.style.height = '50px';
const w = el.offsetWidth;   // 读!浏览器必须先立刻重排才能回答你
const h = el.offsetHeight;  // 又一次读 → 又重排一次
```

> 读 `offsetWidth/offsetHeight/offsetTop/client*`、`scroll*`、`getBoundingClientRect()`、`getComputedStyle()` 等,都会**强制浏览器马上完成一次布局**,硬生生把"批处理"拆成多次 → 性能杀手。

---

## 三、什么触发重绘(不重排)

只影响**视觉、不影响布局**的属性:

```css
color / background / visibility
box-shadow / outline / border-color
```

> `transform`、`opacity` 比较特殊:**它们通常既不重排也不重绘**,只在合成线程完成(见 2.5)。

## 四、减少重排/重绘的实战策略

### 1. 批处理读写(读写分离)

```js
// ❌ 坏:写写读读写写读 → 反复强制同步布局
// ✅ 好:先把"读"全读出来,再统一"写"
const h = el.offsetHeight;   // 读一次
el.style.width = '100px';
el.style.height = h + 'px';  // 写批量
```

### 2. 批量改 DOM

```js
// ❌ 循环里逐个 append,每次都重排
// ✅ 离线操作:用 DocumentFragment 或先拼字符串,一次性插入
const frag = document.createDocumentFragment();
list.forEach(item => frag.appendChild(createNode(item)));
container.appendChild(frag);   // 一次性,只重排一次
```

### 3. 隐藏后再操作

```js
el.style.display = 'none';    // 先脱离布局树
// ...大量修改...
el.style.display = 'block';   // 重新进布局树,只重排两次
```

### 4. 用 transform 代替位移

```js
// ❌ 改 top/left → 触发重排
el.style.top = '10px';
// ✅ 用 transform → 合成线程完成,不重排不重绘
el.style.transform = 'translateY(10px)';
```

### 5. 动画属性选对

动画优先用 `transform` / `opacity`(合成),避免动画里改 `left/top/width`(重排)。

### 6. will-change 预告

```css
.will-animate { will-change: transform; }
```

提前告诉浏览器"这元素要动",让它预提升到合成层,动画更顺。(但别滥用,层多了反而耗内存,见 2.5「层爆炸」)

## 五、框架为什么发明 vDOM

Vue/React 用 vDOM + Diff 来**批量更新真实 DOM**,正是为了减少重排次数——先在新旧 vDOM 间算好差异,再**一次性**把最小变更打到真实 DOM,而不是每次状态变化直接怼 DOM。

> 所以 vDOM 的本质价值之一,就是"**把多次重排合并成一次(或尽量少次)**"。

---

## 六、小结

```
改动属性
├─ 改几何(宽高边距定位)→ Reflow(重排)→ 必伴随 Repaint,代价最大
├─ 改外观(颜色阴影可见性)→ Repaint(重绘),代价较小
└─ transform/opacity → 仅合成,不重排不重绘,代价最小

优化核心:批处理读写 / 离线 DOM / transform 代位移 / 动画选合成属性
陷阱:读 offsetWidth 等会强制同步重排
```

## 七、面试题

**Q1:哪些操作会触发强制同步重排?如何避免?**

读 `offsetWidth/offsetHeight/clientWidth/scrollTop/getBoundingClientRect/getComputedStyle` 等会强制浏览器**立即完成布局**。避免:把"读"集中到一起、和"写"分离开(读写分离);或用 `requestAnimationFrame` 把读写错开。

**Q2:为什么动画用 `transform: translateX` 比 `left` 流畅?**

`left` 是布局属性,改了要**重排**(重走样式→布局→绘制→合成全流程),还占用渲染主线程;`translateX` 只影响**合成阶段**,由合成线程/GPU 独立完成,不碰主线程、不重排,因此不掉帧。这正关联 2.5 的合成层机制。
