## 引言:从「一个页面卡死全崩」到「多进程隔离」

早期浏览器是单进程的:一个标签页崩溃,整个浏览器全挂;一个页面卡死,所有页面跟着卡。现代 Chrome 改成**多进程 + 多线程**,正是为稳定性、安全性和性能。理解进程模型,是理解后面渲染、事件循环、崩溃排查的地基。

---

## 一、进程 vs 线程(先厘清概念)

| | 进程(Process) | 线程(Thread) |
|---|---|---|
| 关系 | 操作系统分配资源的**最小单位** | CPU 调度的**最小单位** |
| 资源 | 独立内存空间,进程间隔离 | 共享所属进程的内存 |
| 隔离 | 一个进程崩溃不影响其他 | 一个线程崩溃可能拖垮整个进程 |

> 一句话:进程是"套房",线程是套房里一起干活的"人"。"套房"之间隔音(隔离),"人"之间共享客厅(共享内存)。

---

## 二、Chrome 的多进程模型

现代 Chrome 主要包含这几类进程:

| 进程 | 职责 |
|------|------|
| **浏览器主进程(Browser)** | 界面、地址栏、书签、协调调度其他进程 |
| **渲染进程(Renderer)** | 解析 HTML/CSS/JS,绘制页面(每个标签页一个,沙箱隔离) |
| **GPU 进程** | 负责 GPU 相关任务(合成、光栅化加速) |
| **网络进程(Network)** | 统一处理网络请求(替代早期放进主进程/渲染进程的方案) |
| **插件/扩展进程** | 已随 Flash 退出历史舞台,插件进程基本淘汰 |

**为什么多进程?三个理由:**

1. **稳定性**:一个渲染进程崩溃 → 只有那个标签页挂了,不影响其他页(崩溃隔离)。
2. **安全性**:渲染进程运行在**沙箱(sandbox)**里,即使页面被攻破(如执行恶意 JS),也拿不到系统权限、读不了别的进程内存。
3. **性能**:多核时代,不同进程并行跑,不再互相抢占;单页卡死只拖垮自己的渲染进程。

**代价**:内存占用更高(每个进程都有自己的开销)——所以 Chrome 也会做些许复用与回收策略。

---

## 三、渲染进程内部的线程

渲染进程是前端最关心的,它内部不是一条线,而是多线程协作:

| 线程 | 职责 |
|------|------|
| **主线程(Main Thread)** | 解析 HTML、构建 DOM/CSSOM、执行 JS、计算样式布局、生成绘制指令 —— 也就是"渲染主线程",事件循环就发生在这 |
| **合成线程(Compositor Thread)** | 分层、分块、调度光栅化、合成位图(不碰 JS,可并行) |
| **光栅化线程(Raster Thread)** | 把绘制指令转成位图像素 |
| **Worker 线程** | 跑 Web Worker,不阻塞主线程 |

> 记住这条分工主线:**主线程管"逻辑和布局",合成线程管"像素合成"**。卷二 2.5 的"为什么 transform 快"正是因为它绕过了主线程、只在合成线程完成。

---

## 四、站点隔离(Site Isolation,安全进阶)

即便一个页面开多个 iframe,历史上它们可能共享同一个渲染进程。**站点隔离**让不同"站点(eTLD+1)"分到**不同的渲染进程**:

- 跨站 iframe 被隔离到自己的进程,防 **Spectre/Meltdown** 这类侧信道攻击
- 代价:更多进程 = 更多内存,但这笔"安全税"现代浏览器愿意付

---

## 五、小结

```
浏览器 ──多进程──▶ 主进程 / 网络 / GPU / 各标签页渲染进程(沙箱)
                         │
                         ▼ 渲染进程内部(多线程)
                主线程(解析+JS+布局) ─┬─ 合成线程(分层/合成/光栅化调度)
                                     └─ 光栅化线程(位图) + Worker

多进程意义:稳定(崩溃隔离) + 安全(沙箱/站点隔离) + 性能(并行)
```

## 六、面试题

**Q1:为什么浏览器要采用多进程模型,而不是单进程?**

三个词:**稳定**(崩溃隔离,一页挂不拖垮整浏览器)、**安全**(渲染进程沙箱化,恶意脚本拿不到系统资源、跨站站点隔离防侧信道攻击)、**性能**(多核并行,GPU 进程独立加速合成)。代价是内存开销变大。

**Q2:一个标签页里的 JS 卡死,为什么不会卡死整个浏览器?**

因为该页面的 JS 只在**它自己的渲染进程主线程**里跑,卡死的是这一个渲染进程;其他标签页各自独立进程,照常响应。用户仍可关掉该页,浏览器主进程不受影响——这正是进程隔离的直接体现。
