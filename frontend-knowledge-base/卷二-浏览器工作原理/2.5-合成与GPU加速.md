## 引言:为什么 transform 能「不重排不重绘」还快

前两章反复埋了个钩子:`transform`/`opacity` 只在合成线程完成。本章把它讲透——这是前端做流畅动画、优化滚动性能的**核心武器**,也是"合成层"这把双刃剑的正确用法。

---

## 一、合成线程在干什么(回忆)

渲染主线程把"绘制指令"交给合成线程后:

```
合成线程:分块(tiling)→ 调度光栅化(转位图)→ 计算层级/滚动偏移 → 合成 → 提交 GPU
```

**合成线程不碰 JS、不碰主线程**,能做纯像素层面的操作。反过来想:**如果一个属性变化只影响"合成",它就能完全在合成线程/GPU 里完成,主线程零参与。**

---

## 二、哪些属性「只影响合成」

```css
transform      /* 位移/缩放/旋转 —— 不引发布局 */
opacity        /* 透明度 —— 不引发布局 */
filter         /* 滤镜(部分) */
```

对比:

| 属性 | 触发阶段 | 主线程参与 | 代价 |
|------|---------|-----------|------|
| `left/top` | 布局 → 绘制 → 合成 | ✅ 是 | 高(重排) |
| `color` | 绘制 → 合成 | ✅ 是 | 中(重绘) |
| `transform` / `opacity` | **仅合成** | ❌ 否 | **最低** |

> 这就是你原文《为什么 transform 效率高》的底层答案:**它跳过布局和绘制,直接在合成线程 + GPU 完成,且能和主线程并行。**

---

## 三、合成层(Layer)的判定

2.3 提过"分层",这里明确:一个元素要被**提升为独立合成层**,常见触发条件:

```css
transform: translateZ(0);        /* 3D 变换 */
will-change: transform, opacity; /* 显式预告 */
filter / backdrop-filter;        /* 滤镜 */
video / canvas / iframe;         /* 特殊元素 */
position: fixed / sticky;        /* 固定/粘性定位 */
```

提升为合成层后,**这个元素的重绘/动画可以独立进行**,不影响其他图层,也不用重走主线程布局。

---

## 四、双刃剑:层爆炸(layer explosion)

"合成层性能好" ≠ "无脑给所有元素 `will-change: transform`"。

**滥用合成层的代价:**

- 每个图层都要**独立的位图内存**,图层越多内存越大
- 每个图层都要**独立光栅化**,图层巨多或图层超大时,反而拖慢
- 隐式提升:一个图层被提升,相邻/被重叠的元素可能被**连带提升**,雪球式增多 → "层爆炸"

**合理用法:**

```css
.will-move { will-change: transform; }   /* 只给真正会动的元素 */
/* 动画结束后可以移除 will-change,释放资源 */
```

> 经验:先**测量再优化**。用 DevTools → Layers 面板看图层数量与内存,别凭感觉大批量加 will-change。

---

## 五、小结

```
合成线程 = 像素层面的阵地(不碰 JS/主线程)

属性分级(代价从高到低):
left/top(布局) > color(绘制) > transform/opacity(仅合成)

合成层:transform/will-change/filter/video 等可能触发独立图层
├─ 好处:独立重绘、动画不打扰其他层、跳过主线程
└─ 风险:层爆炸(内存↑、光栅化↑)→ 只给必要元素,测后再优化
```

## 六、面试题

**Q1:`will-change` 是什么?为什么不能滥用?**

`will-change` 提前告诉浏览器"该元素即将发生某种变化(如 transform)",使其**预先提升为合成层**,动画开始时不产生一次性卡顿。不能滥用:它会**长期占用图层内存**,大量使用会导致层爆炸、内存飙升;应只给即将动画的元素,动画结束移除。

**Q2:滚动性能优化,为什么推荐"合成层滚动"而非监听 scroll 手动改 top?**

原生滚动其实已在合成线程直接移动图层位图,不动布局。若用 JS 在 `scroll` 事件里改元素的 `top/left`,反而在主线程触发一连串重排,导致卡顿。正确方向:交给原生滚动 + `position: sticky`/`transform`,把滚动相关变化留在合成侧。
