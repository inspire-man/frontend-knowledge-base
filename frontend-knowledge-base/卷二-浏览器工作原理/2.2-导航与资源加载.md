# 2.2 导航与资源加载(URL → 首帧)

> 卷:卷二 · 浏览器工作原理
> 难度:⭐⭐ 进阶 | 阅读时间:25min | 状态:已深化

---

## 引言:一道必考题,一条完整链路

"从输入 URL 到页面显示"是前端第一高频面试题。它考的是把**网络 + 进程 + 渲染**串起来的能力。

---

## 一、总览(一图贯穿)

```mermaid
flowchart TD
    A[地址栏输入] --> B[URL 处理<br/>主进程:补全协议 + 编码]
    B --> C[DNS 解析<br/>域名 → IP]
    C --> D[TCP 三次握手]
    D --> E[TLS 握手(HTTPS)]
    E --> F[发送 HTTP 请求]
    F --> G[服务器响应]
    G --> H{Content-Type?}
    H -->|text/html| I[提交导航 → 渲染进程]
    H -->|其他| J[按类型处理:样式/脚本/图片/下载]
    I --> K[解析 DOM + CSSOM]
    K --> L[布局 → 分层 → 绘制 → 光栅化 → 合成]
    L --> M[显示]
```

---

## 二、各阶段要点

### 1. URL 处理(主进程)

补全协议、非 ASCII 字符做 **URL 编码**、交给网络进程。

### 2. 网络请求(网络进程)

DNS(有缓存)→ TCP 三次握手 → TLS 协商 → HTTP 请求 → 响应。

### 3. 解析响应(按 Content-Type 分流)

| `Content-Type` | 动作 |
|----------------|------|
| `text/html` | 提交导航,启动渲染进程 |
| `text/css` | 样式表 |
| `application/javascript` | JS 执行 |
| `image/*` | 图片 |
| `application/octet-stream` / `attachment` | 下载 |

---

## 三、解析阻塞(最易错)

- `<link>`(CSS)→ 其他线程下载,**不阻塞解析**,但 CSS 没就绪会**阻塞渲染**
- `<script>`(JS)→ **阻塞解析**(除非 async/defer)

**为什么 CSS 阻渲染但不阻解析?** 渲染要等 CSSOM 就绪才进行,否则会闪"没样式的裸 HTML"(FOUC);但下载 CSS 是异步的,不妨碍继续解析出 DOM。

| 属性 | 下载 | 执行 | 阻塞解析 |
|------|------|------|---------|
| 无 | 阻塞 | 下载完立即 | ⚠️ 阻塞 |
| `defer` | 异步 | DOM 解析完、DOMContentLoaded 前按序 | 否 |
| `async` | 异步 | 下载完就执行(乱序) | 执行瞬间短暂阻塞 |

---

## 四、一句话把面试答出层次

> "输入 URL 后:主进程补全编码 → 网络进程 DNS→TCP→TLS→HTTP → 按 Content-Type 分流,text/html 提交导航 → 渲染主线程解析 DOM/CSSOM(JS 阻塞解析、CSS 阻塞渲染)→ 样式计算、布局、分层、绘制、光栅化、合成,最终显示。"

能讲到"**进程分工 + 解析阻塞 + 合成结束**"三点就碾压 80% 答案。

---

## 五、小结

```
URL → 主进程(补全/编码)→ 网络进程(DNS→TCP→TLS→HTTP→响应)
    → Content-Type 分流(text/html → 提交导航)
    → 渲染主线程(DOM+CSSOM;JS 阻塞解析,CSS 阻塞渲染)
    → 布局→分层→绘制→光栅化→合成→显示
```

## 六、面试题

**Q1:`defer` 和 `async` 的区别?**

`defer`:异步下载,`DOMContentLoaded` 前按文档顺序执行(保证顺序);`async`:下载完立刻执行,顺序不定。两者都不阻塞解析(async 执行瞬间会短暂阻塞)。

**Q2:为什么 `<script>` 放 `</body>` 前能"更快看到页面"?**

同步 script 阻塞 DOM 解析:放 head 要等下载+执行完才开始渲染 body;放底部先解析渲染完结构再执行。现代更优:`defer` + head,兼顾顺序与不阻塞。

**Q3:为什么输入一个中文 URL 能正常访问?**

浏览器对非 ASCII 字符做了**百分号编码**(URL 编码),把中文转成 `%XX` 的 ASCII 形式,再发起请求——"补全 + 编码"就是主进程在地址栏后干的第一件事。
