# 2.7 Web Worker 与并发

## 引言:主线程被算死了,怎么办

JS 单线程,一个长循环就能让页面假死。Web Worker 让"**重计算**"跑到独立线程,把主线程留给交互与渲染。本章讲清三类 worker 的区别、通信方式,以及它的边界。

---

## 一、为什么需要 Worker

```js
// 主线程干这个,页面直接卡死几秒
let sum = 0;
for (let i = 0; i < 1e9; i++) sum += i;
```

把它丢进 Worker:主线程立即释放,用户照常点击、滚动、看动画。

---

## 二、三类 Worker 对比

| 类型 | 生命周期 | 共享范围 | 典型用途 |
|------|---------|---------|---------|
| **Web Worker(专用)** | 跟随创建它的页面,页面关了它也没了 | 单页面 | 大计算、数据处理 |
| **Shared Worker** | 独立,可被同源多页面共享 | 同源多标签页 | 多页共享状态(如聊天同步) |
| **Service Worker** | 独立,可离线常驻 | 拦截网络请求 | PWA、离线缓存、推送(见卷十二) |

> 三分钟记忆:专用 = 单页重计算;Shared = 多页共享;Service = 网络代理/离线。

---

## 三、基本用法(Web Worker)

```js
// main.js
const worker = new Worker("worker.js");
worker.postMessage({ type: "calc", n: 1e8 });          // 发任务
worker.onmessage = (e) => console.log("结果:", e.data); // 收结果
worker.onerror = (e) => console.error(e);
worker.terminate();                                     // 用完关闭

// worker.js
self.onmessage = (e) => {
  const { n } = e.data;
  let sum = 0;
  for (let i = 0; i < n; i++) sum += i;
  self.postMessage(sum);   // 算完发回
};
```

## 四、通信:postMessage + 结构化克隆

Worker 与主线程**不共享内存**,靠消息传递:

1. **默认:结构化克隆(structured clone)** —— 把数据**深拷贝**一份再传:

```js
const data = { list: [1, 2, 3] };   // 大数据拷贝有开销
worker.postMessage(data);
```

**限制**:函数、DOM、`Error` 等无法克隆;跨线程的对象是副本,不是同一个。

2. **转移(Transferable)**:把 "所有权" 移交给对方,**零拷贝**,更快,适合 `ArrayBuffer`:

```js
const buf = new ArrayBuffer(1024);
worker.postMessage(buf, [buf]);   // 转移后,主线程这边 buf 就"空"了
```

---

## 五、Worker 的边界(不能做什么)

- ❌ 不能访问 `document` / `window` / DOM
- ❌ 不能直接用 `localStorage`(可考虑用 `IndexedDB` 或 postMessage 回主线程操作)
- ✅ 能:`fetch`/网络请求、`FileReader`、定时器、`importScripts`/ES Module 引入

> 记忆:Worker 是"**没有界面的 JS 环境**",能算能联网,不能碰页面。

---

## 六、适用场景与工程建议

| 适合 | 不适合 |
|------|--------|
| 大数据计算(排序/统计/加密) | 简单同步逻辑(通信开销反而更慢) |
| 大文件分片处理、图片/视频编解码 | 频繁小任务(每次克隆都花钱) |
| 埋点上报、耗时正则 | 需要 DOM 的操作 |

> 原则:**计算重、交互弱** 才上 Worker;轻任务硬上反而被"克隆 + 通信"拖慢。现代还有 **SharedArrayBuffer + Atomics** 做真正的共享内存并发,但涉及跨域隔离(COOP/COEP)配置,进阶再谈。

---

## 七、小结

```
Worker = 独立线程,专治"主线程重计算卡顿"

三类:专用(单页计算)/ Shared(多页共享)/ Service(网络代理·PWA)

通信:postMessage + 结构化克隆(默认深拷贝)
     ├─ 限制:不能传函数/DOM,不能碰页面
     └─ 优化:Transferable(ArrayBuffer)转移所有权,零拷贝

适用:重计算、大文件、耗时任务;不适用:简单逻辑、需 DOM
```

## 八、面试题

**Q1:Web Worker 和 Service Worker 的区别?**

定位不同:**Web Worker** 为当前页面提供**并行计算能力**(算完发结果,页面关了即结束);**Service Worker** 是**网络层代理**,独立常驻、可离线拦截请求、做缓存(是 PWA 的基石,见卷十二)。两者都是独立线程,但不能访问 DOM。

**Q2:postMessage 传大对象为什么慢?怎么优化?**

默认走**结构化克隆**,会深拷贝整份数据,大数据拷贝成本高。优化:① 尽量只传必要字段;② 用 `Transferable`(如 `ArrayBuffer` 转移所有权)**零拷贝**;③ 小任务频繁通信本身就不划算,优先合并任务。
