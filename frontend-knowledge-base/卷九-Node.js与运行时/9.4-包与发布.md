# 9.4 包与发布(npm publish / npm link / 版本)

> 卷:卷九 · Node.js 与运行时
> 难度:⭐ 基础 | 阅读时间:15min

---

## 引言:把自己的代码"包装、发布、给别人用"

这一章讲的是"如何把一个库/工具发到 npm、如何本地调试",是组件库和 CLI 工具作者的基本功。

---

## 一、package.json 的三核心字段

```json
{
  "name": "my-utils",            // 包名(唯一)
  "version": "1.0.0",
  "main": "dist/index.js",       // CJS 入口
  "module": "dist/index.esm.js", // ESM 入口
  "exports": { ".": { "import": "./dist/esm.js", "require": "./dist/cjs.js" } },
  "files": ["dist"],             // 只发布这些文件
  "scripts": { "build": "rollup -c" }
}
```

> `exports` 字段决定"别人 import/require 你时拿到哪个文件",是**发布质量的关键**(配合 5.5 的多格式产物)。

---

## 二、npm publish 流程

```bash
npm login            # 登录(需 npm 账号 + 2FA)
npm version patch    # 自动 bump 版本(1.0.0 → 1.0.1)+ 打 git tag
npm publish          # 发布
```

**发布前 checklist:**

1. `files` 精简(只发 dist + README + package.json)
2. `private: true` 必须去掉(否则拒发)
3. 版本号符合 semver(补丁/次/主,见 5.7)
4. 加 `.npmignore` 排除源码/sourcemap

---

## 三、npm link:本地调试

开发库的同时在另一个项目里实时用,不用反复 publish:

```bash
# 在库目录
npm link              # 把当前包链接到全局

# 在消费方项目
npm link my-utils     # 把全局的包链接进 node_modules
# 现在改库代码,消费方立刻生效(符号链接)
```

> 原理:软链接指向库的**源码目录**,改库代码即时可见。替代方案:monorepo 的 `workspace:*`(见 5.8)。

---

## 四、小结

```
package.json:main/module/exports 决定入口;files 控制发布内容
npm publish:login → version → publish(检查 private/fiiles/版本)
npm link:符号链接本地联调,免反复发布
```

## 面试题

**Q1:`exports` 字段的 `import`/`require` 条件有什么作用?**

让同一个包能**按加载方式分发不同产物**:`import` 拿到 ESM 版本(可树摇),`require` 拿到 CJS 版本。这是"库同时支持 ESM 和 CJS 消费方"的标准做法(见 5.5 多格式产物)。

**Q2:如何让 IDE 和 TS 正确识别你发布的包?**

在包里加**声明文件** `types` 字段(`"types": "dist/index.d.ts"`),让 TypeScript 能拿到类型提示;否则使用者会得到隐式 any 或需要额外 `@types`。
