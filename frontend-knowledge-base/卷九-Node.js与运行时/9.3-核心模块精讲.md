# 9.3 核心模块精讲(Buffer / Stream / fs / http)

> 卷:卷九 · Node.js 与运行时
> 阅读时间:30min

---

## 引言:四个绕不开的内置模块

Node 后端日常就是"读文件、收请求、搬字节、回响应"。深挖要懂 **背压(backpressure)** 的机制与**流的内存优势**。

---

## 一、Buffer:处理二进制

```js
const buf = Buffer.from("你好", "utf8");
buf.length;            // 6(UTF-8 每个汉字 3 字节)
buf.toString("utf8");  // 还原
```

> 本质:**定长数组 + 底层内存**。注意 `buf.length` 是**字节数**,不是字符数。

---

## 二、Stream:流式处理(性能关键)

| 类型 | 说明 |
|------|------|
| Readable | 可读 |
| Writable | 可写 |
| Duplex | 双向 |
| Transform | 边读边转(压缩/加密) |

**为什么大文件用流?** 一次性 `readFile` 会把整个文件**读进内存**→ 大文件 OOM(Out Of Memory,内存溢出);流是**边读边处理**,内存占用**恒定**。

### 背压(底层)

```js
readable.pipe(writable);   // pipe 自动处理背压

const ok = writable.write(chunk);
if (!ok) readable.pause();              // 写不进 → 暂停读
writable.on("drain", () => readable.resume());  // 排空再续
```

> **背压 = 消费慢于生产时,让生产端停下。** `write()` 返回 `false` 表示"内部缓冲已满",应暂停上游;`drain` 事件表示"缓冲排空",再恢复。`pipe` 帮你自动做了这套 pause/resume。

---

## 三、fs:文件系统

```js
import { promises as fs } from "fs";
await fs.readFile("a.txt", "utf8");
await fs.writeFile("b.txt", "hello");

const rs = fs.createReadStream("big.bin");   // 大文件用流
rs.on("data", (chunk) => { /* 内存恒定 */ });
```

> **铁律:请求处理里绝不用 `*Sync` 版**(阻塞事件循环);大文件用流。

---

## 四、http:创建服务器

```js
import http from "http";
const server = http.createServer((req, res) => {
  res.setHeader("Content-Type", "application/json");
  res.end(JSON.stringify({ ok: true }));
});
server.listen(3000);
```

> 工程普遍用 Express/Koa/Fastify 封装,底层就是这套 `req`/`res`。

---

## 五、小结

```
Buffer:二进制(字节数≠字符数)
Stream:边读边处理,内存恒定;背压=消费慢则暂停生产(write false→pause,drain→resume)
fs:promises 异步;请求里禁用 Sync;大文件 createReadStream
http:createServer(req,res);工程用 Express/Koa/Fastify
```

## 六、面试题

**Q1:什么是"背压"?Node 如何应对?**

背压 = **消费速度 < 生产速度**,数据在内存堆积。应对:`pipe`(自动 pause/resume)、或手写 `write()` 返回 false 时 `pause()` + `drain` 时 `resume()`。核心:**读端听写端的,别猛灌**。

**Q2:为什么大文件不推荐 readFile?**

`readFile` 一次读进内存,大文件 OOM;改**流** `createReadStream` 边读边处理,内存恒定。

**Q3:Buffer 为什么需要?和字符串区别?**

JS 字符串 UTF-16,无法高效处理原始二进制;`Buffer` 提供**定长、按字节**的二进制容器,用于 I/O、编码转换、二进制协议。长度单位是**字节**。

**Q4:Transform 流是什么?举例?**

**边读边转换**的流(既是可读又是可写),如 `zlib.createGzip()`(压缩)、加密流。数据经它"加工后输出"。

**Q5:为什么事件循环引用里要避免 `fs.readFileSync`?**

同步版会**阻塞事件循环**——文件读期间其他请求全等,高并发下直接拖垮。生产一律用异步版或流。

**Q6:Express/Koa 和原生 http 的关系?**

它们都是原生 `http` 模块之上的**封装层**:原生 http 只有 req/res 与路由要手写;Express/Koa 提供路由、中间件、请求解析等,但底层仍是 http。
