# 9.3 核心模块精讲(Buffer / Stream / fs / http)

## 引言:四个绕不开的内置模块

Node 后端日常就是"读文件、收请求、搬字节、回响应"。深挖要懂 **背压(backpressure)** 的底层机制(highWaterMark)、流的**两种读取模式**与**内存优势**。

---

## 一、Buffer:处理二进制

### 1.1 创建 Buffer

```js
Buffer.alloc(10);                    // 分配 10 字节,清零(安全)
Buffer.allocUnsafe(10);              // 不初始化,可能含旧数据(快,但需手动覆盖)
Buffer.from("你好", "utf8");         // 从字符串/数组/ArrayBuffer 创建
```

### 1.2 字节数 ≠ 字符数

```js
const buf = Buffer.from("你好", "utf8");
buf.length;            // 6(UTF-8 每个汉字 3 字节)
buf.toString("utf8");  // "你好" —— 还原
```

### 1.3 常用操作

```js
Buffer.concat([b1, b2]);             // 拼接
buf.slice(0, 3);                     // 切片(共享内存,非拷贝!)
buf.subarray(0, 3);                  // 同 slice(现代推荐)
buf.equals(other);                   // 比较
buf.toString("hex");                 // 转十六进制
```

### 1.4 Buffer 与 TypedArray

`Buffer` 本质是 `Uint8Array` 的子类,共享底层 `ArrayBuffer`,可直接互相转换:

```js
const u8 = new Uint8Array([65, 66, 67]);
const buf = Buffer.from(u8);         // TypedArray → Buffer
buf.toString();                      // "ABC"
```

> 本质:**定长字节数组 + 底层内存**。`buf.length` 是**字节数**,不是字符数;`slice` 是**视图**(共享内存),改动会影响原 Buffer。

## 二、Stream:流式处理(性能关键)

### 2.1 四种类型

| 类型 | 说明 | 例子 |
|------|------|------|
| Readable | 可读 | `fs.createReadStream` |
| Writable | 可写 | `fs.createWriteStream` |
| Duplex | 双向 | `net.Socket` |
| Transform | 边读边转 | `zlib.createGzip` |

> 所有流都是 `EventEmitter` 实例;`req` 是 Readable 流,`res` 是 Writable 流。

### 2.2 两种读取模式(Readable)

1. **flowing(流动)模式**:数据自动流出,通过 `data` 事件消费
2. **paused(暂停)模式**:必须显式调 `read()` 读

```js
// flowing 模式:监听 data 即自动开始流动
rs.on("data", (chunk) => { /* ... */ });

// paused 模式:用 read() 手动拉
const chunk = rs.read();

// 或用 async 迭代器(推荐,自动处理背压)
for await (const chunk of rs) { /* ... */ }
```

**切换**:监听 `data` / `pipe` → 进入 flowing;调 `pause()` → 回 paused;`resume()` → 再流动。

### 2.3 常用事件

| 事件 | 流类型 | 触发 |
|------|--------|------|
| `data` | Readable | 有数据可读 |
| `end` | Readable | 读完了 |
| `error` | 两者 | 出错 |
| `finish` | Writable | 写完(所有数据 flush) |
| `close` | 两者 | 底层资源关闭 |
| `drain` | Writable | 缓冲排空,可继续写 |

### 2.4 背压的底层:highWaterMark

流内部有**缓冲**。`highWaterMark` 是**阈值**(不是硬限制):

- **Readable**:缓冲数据超过阈值 → 暂停读底层资源(`_read` 不再被调)
- **Writable**:缓冲超过阈值 → `write()` 返回 `false`

```js
const ok = writable.write(chunk);
if (!ok) readable.pause();                    // 写不进 → 暂停读
writable.on("drain", () => readable.resume()); // 排空再续
```

> **背压 = 消费慢于生产时,让生产端停下。** `write()` 返回 `false` = 缓冲满了,应暂停上游;`drain` = 缓冲排空,恢复。`pipe` 帮你自动做这套 pause/resume。

### 2.5 pipe / pipeline / finished

```js
// pipe:基础管道(自动背压)
readable.pipe(writable);

// pipeline:管道 + 自动清理 + 错误传播(推荐)
import { pipeline } from "node:stream/promises";
await pipeline(
  fs.createReadStream("a.tar"),
  zlib.createGzip(),
  fs.createWriteStream("a.tar.gz"),
);

// finished:监听流结束/出错
import { finished } from "node:stream/promises";
await finished(rs);
```

> `pipeline` 比 `pipe` 好:它**自动销毁**上游、**正确传播错误**、支持 AbortSignal 取消。

### 2.6 object mode

流默认处理 Buffer/字符串;`objectMode: true` 可让流处理**任意 JS 对象**(如一条条记录):

```js
const r = new Readable({ objectMode: true, read() {} });
r.push({ id: 1 });   // 推对象而非 Buffer
```

### 2.7 手写一个可读流

```js
import { Readable } from "node:stream";

class MyReadable extends Readable {
  constructor(max) { super(); this.max = max; this.cur = 0; }
  _read() {
    if (this.cur >= this.max) return this.push(null);   // 结束
    this.push(String(this.cur++));                      // 推数据
  }
}

for await (const c of new MyReadable(5)) console.log(c);   // 0 1 2 3 4
```

**为什么大文件用流?** 一次性 `readFile` 会把整个文件**读进内存** → 大文件 OOM(Out Of Memory,内存溢出);流是**边读边处理**,内存占用**恒定**(只留 highWaterMark 大小的一小段缓冲)。

## 三、fs:文件系统

### 3.1 核心 API

```js
import { promises as fs } from "node:fs";

await fs.readFile("a.txt", "utf8");            // 读(小文件)
await fs.writeFile("b.txt", "hello");          // 写
await fs.appendFile("b.txt", "\nmore");        // 追加
await fs.stat("a.txt");                        // 文件信息(大小/时间)
await fs.mkdir("dir", { recursive: true });    // 建目录(递归)
await fs.rm("dir", { recursive: true });       // 删(递归)
await fs.rename("a.txt", "c.txt");             // 重命名/移动
await fs.readdir(".");                         // 列目录
```

### 3.2 流式读写(大文件)

```js
import { createReadStream, createWriteStream } from "node:fs";
const rs = createReadStream("big.bin");        // 大文件用流
const ws = createWriteStream("copy.bin");
rs.pipe(ws);
```

> **铁律:请求处理里绝不用 `*Sync` 版**(阻塞事件循环);大文件用流。

## 四、http:创建服务器

### 4.1 基础服务器

```js
import http from "node:http";
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader("Content-Type", "application/json");
  res.end(JSON.stringify({ ok: true }));
});
server.listen(3000);
```

### 4.2 req(可读流)与 res(可写流)

```js
req.method;           // "GET" / "POST"
req.url;              // "/path?query=1"
req.headers;          // 请求头对象(全小写)
// res
res.statusCode = 404;
res.writeHead(200, { "Content-Type": "text/html" });
res.setHeader("X-Custom", "v");
res.write("<p>hi</p>");
res.end();            // 结束响应(必须调)
```

### 4.3 解析 POST body(流式收集)

`req` 是 Readable 流,body 要**边收边拼**:

```js
const server = http.createServer((req, res) => {
  let body = "";
  req.setEncoding("utf8");
  req.on("data", (chunk) => { body += chunk; });   // 边收边拼
  req.on("end", () => {
    try {
      const data = JSON.parse(body);
      res.end(typeof data);
    } catch (e) {
      res.statusCode = 400;
      res.end(`error: ${e.message}`);
    }
  });
});
```

> 工程普遍用 Express/Koa/Fastify 封装,底层就是这套 `req`(Readable)/ `res`(Writable)。

## 五、小结

```
Buffer:二进制,字节数≠字符数;alloc/allocUnsafe/from;slice 是视图(共享内存)
Stream:四类型(Readable/Writable/Duplex/Transform);两种模式(flowing/paused)
背压:highWaterMark 阈值 → write() 返回 false 暂停;drain 恢复;pipe/pipeline 自动处理
fs:promises 异步;请求里禁用 Sync;大文件 createReadStream(内存恒定)
http:createServer;req 是 Readable、res 是 Writable;POST body 流式收集
```

## 六、面试题

**Q1:什么是"背压"?底层靠什么实现?Node 如何应对?**

背压 = 消费速度 < 生产速度,数据在内存堆积。底层靠 **highWaterMark 阈值**:Readable 缓冲超阈值暂停读、Writable 超阈值 `write()` 返回 false。应对:`pipe`/`pipeline`(自动 pause/resume),或手写 `write()` 返回 false 时 `pause()` + `drain` 时 `resume()`。

**Q2:为什么大文件不推荐 readFile?**

`readFile` 一次读进内存,大文件 OOM;改**流** `createReadStream` 边读边处理,内存恒定(只留 highWaterMark 大小缓冲)。

**Q3:Readable 流的两种模式是什么?如何切换?**

**flowing(流动)** 模式:监听 `data` 即自动流出数据;**paused(暂停)** 模式:需手动 `read()` 拉。监听 `data`/`pipe` → flowing;`pause()` → paused;`resume()` → flowing。`for await...of` 用暂停模式自动处理背压。

**Q4:Buffer 的 `slice` 是拷贝吗?为什么?**

**不是拷贝,是视图**——`slice`/`subarray` 返回共享同一底层内存的新 Buffer,改动会互相影响。所以"切割大 Buffer"用 slice 高效;要独立副本需 `Buffer.from(original)` 或 `copy()`。

**Q5:`pipeline` 比 `pipe` 好在哪里?**

`pipeline` **自动销毁**各流、**正确传播错误**(任一流出错都能 catch)、支持 `AbortSignal` 取消;`pipe` 要手动处理错误与清理。生产推荐 `pipeline`。

**Q6:为什么事件循环里要避免 `fs.readFileSync`?**

同步版会**阻塞事件循环**——文件读期间其他请求全等,高并发下直接拖垮。生产一律用异步版或流。

**Q7:`req` 和 `res` 分别是什么类型的流?**

`req`(http.IncomingMessage)是 **Readable** 流(读请求体);`res`(http.ServerResponse)是 **Writable** 流(写响应体)。所以收 POST body 用 `data`/`end` 事件,回响应用 `write`/`end`。

**Q8:`highWaterMark` 是硬性的内存上限吗?**

**不是硬限制,是阈值**。它规定"缓冲到多少就暂停再要数据",但不强制严格限制内存。具体流实现可以选择更严格,但一般情况只是"背压触发点"。

**Q9:Transform 流和 Duplex 流有什么区别?**

两者都是可读可写。区别:**Transform** 的数据流经它会被"**加工转换**"(读出的 ≠ 写入的),如压缩/加密;Duplex 的读和写是**独立**的两条通道,互不转换,如 TCP socket。

**Q10:如何手写一个简单的可读流?核心要实现哪个方法?**

继承 `Readable`,实现 **`_read()`**:内部用 `this.push(chunk)` 推数据,结束时 `this.push(null)`。消费方用 `data` 事件或 `for await...of` 读。
